실행 비교와 회귀 감지

지표 층 이 프로젝트의 하이라이트 ⏱ 2~3시간
🎯 목표

실행 두 개를 나란히 놓고 지표마다 회귀 / 개선 / 유지를 판정하는 compare.py를 만듭니다. 그리고 일부러 나쁜 설정을 넣어 — P1은 mode=baseline, P2는 프롬프트 규칙을 지워서 — 그게 회귀로 잡히는지 확인합니다. 잡히면 이 하네스는 "테스트"가 된 겁니다.

🧠 개념 — 딱 하나만

회귀는 "낮다"가 아니라 "지난번보다 임계값 넘게 떨어졌다"이다

recall 0.70이 좋은 건지 나쁜 건지는 혼자서는 알 수 없습니다. 지난주에 0.84였다면 나쁜 것이고, 0.58이었다면 좋은 것이죠. 그래서 판정은 항상 두 실행 사이에서 합니다 — 믿고 쓰던 baseline과 이번에 바꾼 candidate.

그리고 STEP 3의 더 알아보기에서 봤듯 LLM 점수는 같은 설정에서도 흔들립니다. 0.01 떨어졌다고 회귀라 하면 매번 울리는 경보가 되죠. 지표마다 임계값을 두고, 그보다 크게 떨어졌을 때만 회귀, 크게 올랐을 때만 개선, 그 사이는 유지로 봅니다.

compare.py — 임계값과 판정

— 지표마다 다르고, 방향도 다르다
compare.py
import json
import sys
from pathlib import Path

import pandas as pd

# 지표마다 '얼마나 떨어져야 회귀로 볼 것인가'. 없는 지표는 기본값을 쓴다.
# 값은 절대 차이(비율 지표는 0.05 = 5%p). 지연은 상대 비율(0.5 = 50% 느려지면 회귀).
THRESHOLDS = {"judge_score": 0.3, "latency_ms": 0.5}
DEFAULT_THRESHOLD = 0.05
LOWER_IS_BETTER = {"latency_ms"}              # 이 지표는 '오르면' 나쁜 것


def load_run(path: str | Path) -> tuple[dict, pd.DataFrame]:
    path = Path(path)
    summary = json.loads((path / "summary.json").read_text(encoding="utf-8"))
    results = pd.read_csv(path / "results.csv", index_col="id")
    return summary, results


def verdict(metric: str, base: float, cand: float) -> str:
    """세 갈래 — 회귀 / 개선 / 유지."""
    thr = THRESHOLDS.get(metric, DEFAULT_THRESHOLD)
    if metric in LOWER_IS_BETTER:
        change = (cand - base) / base if base else 0.0      # 상대 변화. +0.6 = 60% 느려짐
        worse, better = change > thr, change < -thr
    else:
        change = cand - base
        worse, better = change < -thr, change > thr
    return "회귀" if worse else "개선" if better else "유지"

judge_score는 1~5 척도라 0.05로는 너무 민감해서 0.3, 지연은 절대값(ms)이 의미 없어서 상대 비율로 둡니다. 임계값은 코드 맨 위에 모아 두세요 — 이 숫자는 앞으로 계속 손보게 되는 값이고, 그때 코드 안을 뒤지면 안 됩니다.

compare.py — 표 하나, 갈린 케이스 하나

— "얼마나"와 "어디서"
def compare(base: dict, cand: dict) -> pd.DataFrame:
    """두 summary의 metrics를 표 하나로. 한쪽에만 있는 지표는 비교하지 않는다."""
    rows = []
    for m, b in base["metrics"].items():
        c = cand["metrics"].get(m)
        if b is None or c is None:
            continue
        rows.append({"metric": m, "baseline": b, "candidate": c,
                     "delta": round(c - b, 3), "verdict": verdict(m, b, c)})
    return pd.DataFrame(rows).set_index("metric")


def case_diffs(base_df: pd.DataFrame, cand_df: pd.DataFrame, metric: str) -> pd.DataFrame:
    """그 지표에서 값이 달라진 케이스만. 요약표는 '얼마나'를, 이 표는 '어디서'를 알려 준다."""
    both = base_df[[metric]].join(cand_df[[metric]], lsuffix="_base", rsuffix="_cand", how="inner")
    changed = both.iloc[:, 0].fillna(-1) != both.iloc[:, 1].fillna(-1)   # '해당 없음'(NaN)끼리는 같은 것으로 본다
    return both[changed]

compare.py — main: 시험지 확인, 출력, 종료 코드

— 회귀가 있으면 exit 1
def main():
    base, base_df = load_run(sys.argv[1])
    cand, cand_df = load_run(sys.argv[2])
    if (base["dataset"], base["version"]) != (cand["dataset"], cand["version"]):
        sys.exit(f"❌ 시험지가 다릅니다: {base['dataset']} {base['version']} vs {cand['dataset']} {cand['version']}")

    print(f"baseline : {base['run_id']}  params={base['params']}")
    print(f"candidate: {cand['run_id']}  params={cand['params']}\n")
    table = compare(base, cand)
    print(table.to_string())

    regressed = table[table["verdict"] == "회귀"].index.tolist()
    for m in regressed:
        print(f"\n[{m} — 값이 달라진 케이스]")
        print(case_diffs(base_df, cand_df, m).to_string())

    print("\n" + ("🚨 회귀 감지: " + ", ".join(regressed) if regressed else "✅ 회귀 없음"))
    sys.exit(1 if regressed else 0)


if __name__ == "__main__":
    main()

sys.exit(1)이 작아 보이지만 STEP 8의 전부입니다. 종료 코드가 1이면 셸 스크립트도, pytest도, CI도 "실패"로 읽어요. 사람이 표를 읽지 않아도 기계가 판정을 이어받을 수 있게 되는 지점입니다.

🎓 한 줄 정리

판정은 항상 두 실행 사이에서, 임계값을 넘겨 떨어졌을 때만 회귀다. 일부러 망가뜨렸을 때 잡히는 하네스만이 실제 회귀도 잡는다.

더 알아보기 — 임계값은 어떻게 정하나 / tags로 잘라 보기 / 개선도 의심하기

임계값 0.05의 정체

케이스가 15개면 하나가 뒤집힐 때 비율 지표는 0.067 움직입니다. 즉 0.05는 "케이스 하나 차이"예요. 케이스가 30개면 하나가 0.033이라 0.05는 두 개 차이가 됩니다. 임계값을 정하는 가장 정직한 방법은 STEP 3의 더 알아보기 — 같은 설정을 두세 번 돌려 흔들림의 폭을 재고, 그 폭보다 살짝 크게 두는 것입니다. 그 폭을 README에 적어 두면 "왜 0.05인가"에 답이 됩니다.

tags로 잘라 보기

STEP 1에서 채운 tags를 쓰면 "card 케이스만 떨어졌다"를 볼 수 있습니다. results.csv에는 tags가 없으니 시험지에서 가져와 붙입니다. 

from schemas import load_dataset
ds = load_dataset("rag_v1")
tag_of = {c.id: (c.tags[0] if c.tags else "-") for c in ds.cases}
cand_df["tag"] = cand_df.index.map(tag_of)
print(cand_df.groupby("tag")[["source_hit", "context_recall"]].mean().round(3))

개선도 의심하세요

latency_ms가 "개선"으로 찍힌 걸 봤죠. baseline 구성은 리랭커를 안 태우니 빠른 게 당연하고, 그 대가가 recall 회귀입니다. 한 지표의 개선이 다른 지표의 회귀와 같이 오는지 보는 습관이 "숫자를 읽을 줄 안다"의 실체예요. 판정표를 한 줄씩이 아니라 한 덩어리로 읽으세요.
