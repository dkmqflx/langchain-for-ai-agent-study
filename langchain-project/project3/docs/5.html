LLM-as-judge + 채점자 신뢰도

지표 층 ⏱ 3~4시간 (라벨링 포함)
🎯 목표

--judge 플래그로 답변 품질 점수(1~5)를 케이스마다 붙입니다 — RAG와 Agent 양쪽에. 그리고 P2 STEP 8에서 미뤄 둔 질문에 답합니다: "이 채점자를 믿어도 되나?" 케이스 10개를 직접 채점해서 judge와 얼마나 맞는지 숫자로 냅니다.

🧠 개념 — 딱 하나만

채점자도 시험을 봐야 한다

judge가 준 4.2점을 보고 "좋네"라고 하려면, 그 4.2가 내가 읽고 매긴 점수와 비슷하다는 근거가 있어야 합니다. 없으면 judge 점수는 그냥 또 하나의 LLM 출력이에요. 방법은 단순합니다. 실행 하나에서 케이스 10개를 뽑아 답변을 읽고 내가 점수를 매깁니다. judge 점수와 나란히 놓고 일치율을 냅니다. ±1 안에서 80% 이상 맞으면 그 judge로 추세를 보는 데 무리가 없고, 그 아래면 rubric이나 채점 템플릿을 손봐야 합니다.

🛠 할 일 — 네 조각
①

judge.py — 채점자

— P2 STEP 8의 채점자를 파일로 독립시키고, RAG도 채점할 수 있게 기준을 꺼내는 함수를 더한다
judge.py
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from pydantic import BaseModel, Field

load_dotenv()


class Judgement(BaseModel):
    score: int = Field(description="1~5점", ge=1, le=5)
    reason: str = Field(description="그 점수를 준 이유 한 문장")


# 채점자는 피평가 모델(P1·P2 모두 gpt-5-mini)과 다른 모델이 낫다 — 같은 모델은 자기 문체에 후하다.
# 아래 신뢰도 점검에서 두 채점자를 바꿔 가며 비교해 보세요.
JUDGE_MODEL = "openai:gpt-5-mini"
judge = init_chat_model(JUDGE_MODEL).with_structured_output(Judgement)

JUDGE_TEMPLATE = """너는 엄격한 채점자다. 아래 답변을 채점 기준에 따라 1~5점으로 평가하라.

[질문]
{question}

[채점 기준]
{rubric}

[답변]
{answer}

[제시된 근거]
{sources}

점수 척도 — 반드시 이 기준을 따르라:
5 = 기준을 완전히 충족하고, 근거가 적절하다
4 = 기준을 충족하나 사소한 누락이 있다
3 = 절반쯤 맞다. 중요한 내용이 빠졌다
2 = 대체로 빗나갔다. 일부만 관련 있다
1 = 완전히 틀렸거나, 문서에 없는 내용을 지어냈다

지어낸 내용이 하나라도 있으면 다른 게 아무리 좋아도 1점이다."""


def judge_answer(question: str, rubric: str, answer: str, sources: list[str]) -> Judgement:
    prompt = JUDGE_TEMPLATE.format(
        question=question, rubric=rubric, answer=answer,
        sources=" / ".join(sources) if sources else "(없음)",
    )
    return judge.invoke(prompt)


def rubric_for(target: str, case) -> str:
    """케이스에서 채점 기준을 꺼낸다. RAG는 정답 문장이, Agent는 rubric 칸이 기준이다."""
    if target == "rag":
        return f"다음 정답의 핵심 내용을 빠짐없이 담고 있어야 한다.\n정답: {case.ground_truth}"
    return case.rubric

rubric_for가 이 STEP의 작은 요령입니다. RAG 케이스에는 rubric 칸이 없지만 ground_truth가 있으니, 그걸 "기준"으로 바꿔 넣으면 같은 채점자가 두 시험 대상을 다 봅니다.

getattr(case, "expect_blocked", False)는 RAG 케이스에 그 칸이 없어서 쓰는 안전한 읽기입니다. 차단 케이스를 건너뛰는 이유는 P2 STEP 8과 같아요 — 막는 게 정답인 답의 '내용'은 채점할 게 없습니다. 그 케이스의 judge_score는 비어(NaN) 평균에서 빠집니다.

check_judge.py — sample: 10개를 뽑아 라벨 파일을 만든다

— 매번 같은 10개가 뽑히게
check_judge.py
import json
import sys
from pathlib import Path

import pandas as pd


def sample(run_dir: Path, n: int = 10) -> None:
    df = pd.read_csv(run_dir / "results.csv")
    df = df[df["judge_score"].notna()]                     # 차단 케이스처럼 채점을 건너뛴 행은 뺀다
    picked = df.sample(n=min(n, len(df)), random_state=0)  # 매번 같은 10개 — 다시 돌려도 같은 케이스를 라벨한다
    rows = [{"id": r.id, "question": r.question, "answer": r.answer,
             "judge_score": int(r.judge_score), "judge_reason": r.judge_reason,
             "human_score": None}                          # ← 여기를 사람이 채운다
            for r in picked.itertuples()]
    out = run_dir / "human_labels.json"
    out.write_text(json.dumps(rows, ensure_ascii=False, indent=2), encoding="utf-8")
    print(f"📝 {out} — {len(rows)}개. human_score를 채운 뒤 'agree'를 실행하세요.")

라벨 파일이 실행 폴더 안에 생기는 게 맞습니다. 사람 점수는 그 실행의 그 답변에 대한 것이지 케이스에 대한 것이 아니에요 — 다음 실행에서 답이 달라지면 점수도 달라져야 하니까요.

④

check_judge.py — agree: 일치율 셋

— 그리고 2점 이상 갈린 케이스
def agree(run_dir: Path) -> None:
    rows = json.loads((run_dir / "human_labels.json").read_text(encoding="utf-8"))
    df = pd.DataFrame(rows).dropna(subset=["human_score"])
    if df.empty:
        sys.exit("human_score가 하나도 없습니다. 파일을 먼저 채우세요.")
    diff = (df["judge_score"] - df["human_score"]).abs()
    print(f"라벨 {len(df)}개 기준")
    print(f"  정확히 일치   : {(diff == 0).mean():.2f}")
    print(f"  ±1 안에 일치  : {(diff <= 1).mean():.2f}")
    print(f"  평균 차이(MAE): {diff.mean():.2f}")
    print(f"  judge 평균 {df['judge_score'].mean():.2f} vs 사람 평균 {df['human_score'].mean():.2f}"
          f"  → {'judge가 후함' if df['judge_score'].mean() > df['human_score'].mean() else 'judge가 박함'}")
    off = df[diff >= 2][["id", "judge_score", "human_score", "judge_reason"]]
    if not off.empty:
        print("\n[2점 이상 갈린 케이스 — 채점 기준(rubric)이나 템플릿을 손볼 단서]")
        print(off.to_string(index=False))


if __name__ == "__main__":
    cmd, run_dir = sys.argv[1], Path(sys.argv[2])
    {"sample": sample, "agree": agree}[cmd](run_dir)

셋을 따로 내는 이유가 있습니다. 정확 일치는 5단계 척도에서 원래 낮게 나오고, ±1 일치가 "추세를 믿어도 되나"의 실질 기준이며, 평균 차이의 방향은 judge가 전반적으로 후한지 박한지를 알려 줘요. 후하다면 A/B 비교에는 문제없지만 절대 점수를 이력서에 쓸 땐 조심해야 합니다.

🎓 한 줄 정리

judge 점수는 사람 점수와의 일치율이 있을 때만 지표다. 10개면 충분하고, 갈린 케이스는 rubric을 고칠 단서다.

더 알아보기 — 채점자를 바꿔 비교하기 / 왜 정확 일치가 낮나 / 더 엄밀하게

채점자 둘을 비교해 보세요

JUDGE_MODEL을 "google_genai:gemini-2.5-flash"로 바꿔 같은 실행을 다시 채점하고(라벨 파일은 그대로) agree를 돌리면 어느 채점자가 나와 더 잘 맞는지 나옵니다. 이게 "채점자 선택의 근거"가 되고, 이력서에 "judge 신뢰도를 사람 라벨 대비 ±1 일치율 0.9로 검증"이라고 쓸 수 있는 문장이 됩니다.

정확 일치가 낮은 건 정상입니다

5단계 척도에서 사람끼리도 정확 일치는 60~70% 언저리입니다. 4점과 5점의 경계는 원래 흐려요. 그래서 실질 기준을 ±1로 둡니다. 정확 일치를 올리고 싶다면 척도를 3단계(맞음 · 부분 · 틀림)로 줄이는 게 프롬프트를 다듬는 것보다 효과적입니다.

더 엄밀하게 — Cohen's κ

일치율은 "우연히 맞을 확률"을 빼지 않습니다. 논문식으로 하려면 Cohen's kappa를 쓰는데, sklearn.metrics.cohen_kappa_score 한 줄이에요. 10개로는 값이 불안정하니 30개 이상 모였을 때 붙이면 됩니다.
