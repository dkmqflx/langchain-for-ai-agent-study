05. 메시지 객체와 .type 속성 이해하기

실습 노트북: 05.ipynb  ·  원문: docs/03.advanced-agent.md  ·  난이도: 🟡 중급  ·  선행: 04. 멤버십 기반 모델 선택

이 노트북은 겉보기엔 "학생이 부정행위를 못 하게 막는 교육용 가드레일"을 만드는 실습입니다. 하지만 진짜 배울 것은 그 코드 속에 숨은 딱 한 줄, if last_message.type != "human"입니다. 메시지를 print했을 땐 분명 type이 안 보였는데, 코드에서는 .type으로 꺼내 쓰고 있죠. 이 .type은 대체 어디서 온 걸까요? 그 정체를 파헤치는 것이 오늘의 목표입니다.

이 장에서 배우는 것 LangChain의 모든 메시지(HumanMessage, AIMessage, SystemMessage …)는 같은 부모 클래스(BaseMessage)에서 태어난 형제들입니다. 그래서 겉모습(내용)은 달라도 공통 속성을 나눠 갖는데, 그중 하나가 "이 말을 누가 했는가"를 알려주는 type입니다. 이 장에서는 ① .type이 왜 필요한지(실전 가드레일), ② 그게 어디서 왔는지(BaseMessage 상속), ③ 왜 화면 출력엔 안 보이는지(__repr__)를 순서대로 봅니다.
🔍 비유 — 모든 메시지가 달고 있는 명찰 회의실에 들어온 모든 사람이 가슴에 명찰을 달고 있다고 상상해보세요. 명찰에는 "발언자: 사회자", "발언자: 참석자", "발언자: 진행봇"처럼 누가 말했는지가 적혀 있습니다. LangChain 메시지의 .type이 바로 이 명찰입니다 — "human"(사람), "ai"(모델), "system"(지시)처럼요. 가드레일(문지기)은 이 명찰만 슬쩍 보고 "아, 이건 사람이 방금 한 말이구나"라고 판단해 개입할지 말지를 결정합니다. 오늘 이야기의 주인공이 바로 이 명찰입니다.

1. 실전 맥락 — .type은 언제 필요한가

우리가 만들 것은 학생용 AI 튜터에 붙이는 안전장치입니다. 학생이 "숙제 대신 써줘" 같은 부정행위성 질문을 하면, 그 질문을 굳이 비싼 LLM에게 보내지 않고 미리 가로채서 "스스로 고민해보라"는 교육적 멘트로 되돌려주는 것이죠. 이렇게 모델 호출 이전에 끼어드는 문지기를 미들웨어(middleware)라고 부릅니다.

🔍 비유 — 고속도로 톨게이트 에이전트의 실행 흐름을 고속도로라고 생각해보세요. 목적지는 LLM(모델 호출)입니다. @before_agent 미들웨어는 그 앞을 지키는 톨게이트예요. 들어오는 차(메시지)를 검문해서 문제없으면 그냥 통과시키고, 수상하면 목적지까지 갈 것도 없이 바로 회차로(Exit)로 내보냅니다. 그런데 톨게이트가 검문을 하려면 먼저 "이 차가 진짜 검문 대상(=사람이 방금 한 말)인가"부터 확인해야 하죠. 그 확인이 바로 .type 검사입니다.

가드레일이 판단하는 순서를 그림으로 보면 이렇습니다.

1메시지 도착

에이전트에 state["messages"]가 들어옴

2빈 리스트?

비었으면 검사할 게 없으니 return None

3사람 말인가?

.type != "human"이면 그냥 통과

4금지어 검사

부정행위·딴짓·유해어 포함 시 차단

5통과 / 차단

깨끗하면 LLM으로, 걸리면 jump_to: end

2. 가드레일 미들웨어 코드

먼저 모델을 준비하고, 어떤 표현을 막을지 금지어 사전을 만듭니다.

📥 코드 — 준비
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain.agents import create_agent


# .env 파일에서 환경 변수 로드
load_dotenv()

# 모델 선언
model = init_chat_model("gpt-4o-mini")
📥 코드 — 금지어 사전
forbidden_topics = {
    "cheating": ["답지", "정답 알려줘", "숙제 대신", "써줘", "베끼기"],
    "distraction": ["롤", "게임", "유튜브", "아이돌", "웹툰"],
    "harmful": ["담배", "술", "폭력", "바보", "멍청이"],
}

이제 핵심 미들웨어입니다. 코드가 길어 보이지만 구조는 단순합니다 — ① 방어(빈 리스트/사람 말 확인) → ② 카테고리별 금지어 검사 → ③ 통과의 3단계예요. 특히 진하게 볼 두 줄은 last_message = state["messages"][-1](마지막 메시지 꺼내기)와 그 바로 아래 if last_message.type != "human"(그게 사람 말인지 확인)입니다.

📥 코드 — @before_agent 가드레일
from langchain.agents.middleware import before_agent

@before_agent(can_jump_to=["end"])
def education_guardrail(state, runtime):
    """
    학생의 질문 의도를 파악하여 교육적이지 않거나 부정행위가 의심될 경우,
    LLM(AI)에게 질문을 넘기지 않고 교육적인 멘트로 즉시 교정합니다.
    """

    # 1. 메시지 유효성 검사
    if not state["messages"]:
        return None

    # 에이전트가 처음 시작될 때나 특수한 상황에서 메시지 리스트가 비어 있을 수 있습니다.
    # 비어 있는 리스트에서 마지막 메시지를 찾으려고 하면([-1]) 파이썬에서 **IndexError**가 발생하여 프로그램이 멈춥니다.
    # 이를 방지하기 위한 첫 번째 방어선입니다.


    last_message = state["messages"][-1]
    # print(last_message)


    if last_message.type != "human":
        return None
    # 우리가 만들려는 미들웨어(예: 질문 요약, 보안 검사 등)는 보통 사용자의 질문에 대해서만 작동해야 합니다.
    # 만약 AI의 답변이나 도구 결과에 대해 미들웨어가 또 작동하면, 무한 루프에 빠지거나 엉뚱한 처리를 할 위험이 있습니다.

    user_text = last_message.content

    # 2. 카테고리별 검사 로직
    # 단순히 막는 것을 넘어, '왜' 안되는지 카테고리별로 다른 피드백 주기

    # Case A: 부정행위 방지 (Cheating Prevention)
    # AI가 숙제를 통째로 해주는 것을 방지
    for keyword in forbidden_topics["cheating"]:
        if keyword in user_text:
            return {
                "messages": [{
                    "role": "assistant",
                    "content": "🚫 스스로 고민해봐야 실력이 늘어요! 정답을 바로 알려드리는 대신, 힌트를 드릴까요? 어떤 부분이 가장 어려운지 말해주세요."
                }],
                "jump_to": "end"
            }

    # Case B: 학습 집중 유도 (Focus Management)
    # 공부 중에 게임이나 딴짓 이야기를 하면 다시 공부로 유도
    for keyword in forbidden_topics["distraction"]:
        if keyword in user_text:
            return {
                "messages": [{
                    "role": "assistant",
                    "content": "⏰ 지금은 공부에 집중할 시간이에요! 딴짓은 쉬는 시간에 하고, 지금 풀고 있는 문제에 집중해볼까요?"
                }],
                "jump_to": "end"
            }

    # Case C: 유해 콘텐츠 차단 (Safety)
    # 교육 서비스의 브랜드 안전성(Brand Safety)을 위한 기능
    for keyword in forbidden_topics["harmful"]:
        if keyword in user_text:
            return {
                "messages": [{
                    "role": "assistant",
                    "content": "⚠️ 부적절한 대화 주제입니다. 바르고 고운 말을 사용해주세요."
                }],
                "jump_to": "end"
            }

    # 3. 통과 (Pass)
    # 위 조건들에 걸리지 않으면 정상적으로 AI 튜터(LLM)가 답변 생성
    return None
⚠️ 왜 .type부터 확인할까? 에이전트가 도는 동안 state["messages"] 리스트에는 사람의 질문뿐 아니라 AI의 답변·도구(tool) 실행 결과까지 섞여 쌓입니다. 만약 .type 확인 없이 아무 메시지에나 검사를 돌리면, AI가 스스로 만든 답변까지 검열하다가 무한 루프에 빠지거나 엉뚱하게 동작할 수 있어요. 그래서 "방금 도착한 게 사람 말일 때만 개입한다"는 이 .type 검사가 안전장치의 핵심입니다.

💡 첫 줄에 주목하세요 — 여기가 오늘의 열쇠 결과의 맨 윗줄은 코드 속 # print(last_message) 자리에서 마지막 메시지를 출력한 모습입니다. content, additional_kwargs, response_metadata, id는 보이는데… 정작 우리가 if last_message.type로 꺼내 쓴 type은 어디에도 안 보입니다. 그런데도 코드는 멀쩡히 동작했죠. 이게 어떻게 가능한 걸까요? 다음 장에서 풀어봅니다.

4. .type은 어디서 왔나 — BaseMessage 상속

print(state)를 했을 때 HumanMessage(...)라고 나오는 객체에서 .type에 접근할 수 있는 이유는 HumanMessage가 LangChain의 BaseMessage라는 클래스를 상속받아 만들어졌기 때문입니다. 즉 type은 우리가 안 넣어줘도 부모에게서 물려받은 기본 장착 속성이에요.

🔍 비유 — 같은 붕어빵 틀에서 나온 형제들 HumanMessage, AIMessage, SystemMessage는 겉에 담긴 팥·슈크림·초코가 다를 뿐, 전부 똑같은 붕어빵 틀(BaseMessage)에서 찍혀 나옵니다. 그 틀에는 내용을 담는 홈(content), 종류를 새기는 홈(type), 고유번호 홈(id)이 파여 있죠. 그래서 어떤 붕어빵이든 이 홈들은 반드시 가지고 있습니다. 우리가 .type을 꺼낼 수 있는 건, 그 홈이 애초에 틀에 새겨져 있기 때문입니다.

LangChain이 정의한 모든 메시지 객체는 공통적으로 다음 속성들을 가집니다.

속성담긴 내용예시 값
content메시지의 실제 텍스트 내용"숙제 대신 써줘"
type메시지의 종류(명찰) 문자열"human" · "ai" · "system"
additional_kwargs추가적인 부가 정보{}
id메시지 고유 식별자"0d9db59d-…"
💡 .type 값과 메시지 클래스는 짝꿍 HumanMessage의 .type은 "human", AIMessage는 "ai", SystemMessage는 "system", 도구 실행 결과인 ToolMessage는 "tool"입니다. 그래서 last_message.type != "human"은 곧 "이게 사람이 방금 한 말이 아니면"이라는 뜻이 됩니다. 클래스 이름으로 isinstance() 검사를 하는 것보다 문자열 하나로 비교하는 이 방식이 더 간결하죠.

5. 그런데 왜 print할 땐 안 보였나 — __repr__

print(state)나 print(last_message)가 화면에 보여주는 글자는 객체의 __repr__(표현식) 메서드가 정해둔 내용일 뿐입니다. 즉 "이 객체를 사람이 읽기 좋게 어떻게 요약해 보여줄까"를 개발자가 미리 정해둔 겉모습이에요. 실제 객체 내부 구조는 개념적으로 다음과 같습니다.

📥 개념 코드 — 클래스 내부에는 type이 이미 있다
class HumanMessage(BaseMessage):
    type: str = "human"  # 클래스 내부에 이미 정의됨
    content: str
    # ... 기타 속성들
🔍 비유 — 택배 상자의 겉면과 속 라벨 택배 상자 겉면에 이미 큼지막하게 "HumanMessage"라고 적혀 있다고 해봐요. 그럼 굳이 상자를 열고 안쪽 라벨에 "종류: human"이라고 또 적을 필요가 없겠죠. 중복이니까요. LangChain 개발자도 똑같이 생각했습니다 — __repr__에서 이미 클래스 이름(HumanMessage) 자체로 종류를 알 수 있으니 출력에서 type은 생략하도록 설계한 겁니다. 하지만 안쪽 라벨(속성)은 엄연히 존재하기 때문에, 코드에서 점(.)으로 언제든 꺼낼 수 있습니다.
🚫 흔한 오해 — "출력에 안 보이면 없는 것이다" print 결과에 type이 없다고 해서 "이 객체엔 type이 없구나"라고 결론 내리면 안 됩니다. 화면에 표시되는 것(__repr__)과 메모리에 실제로 존재하는 것은 별개입니다. 객체가 무엇을 가지고 있는지 확실히 알고 싶다면 print 대신 dir(last_message)나 last_message.type처럼 직접 접근해 확인하세요.

6. 보충 — return None과 jump_to의 의미

가드레일 코드 곳곳에 나오는 return None과 return {"jump_to": "end", ...}도 짚고 넘어갈까요. @before_agent(can_jump_to=["end"])가 붙은 미들웨어에서 이 둘은 정반대의 뜻을 가집니다.

🔍 비유 — 톨게이트의 두 가지 명령 다시 톨게이트로 돌아가 볼게요. return None은 "통과!" — 아무것도 손대지 않고 차를 원래 목적지(LLM)로 그냥 보냅니다. return {"jump_to": "end"}는 "통과 금지, 회차로!" — 목적지까지 갈 것도 없이 차를 즉시 출구(end)로 내보냅니다. 그리고 can_jump_to=["end"]는 이 톨게이트에게 "필요하면 출구로 순간이동시킬 권한을 준다"는 사전 허가증이고요.
📘 보충 — return None은 "검사 무사 통과" 신호

아래 예시를 보면 흐름이 한눈에 들어옵니다.

@before_agent(can_jump_to=["end"])
def my_middleware(state, runtime):
    # 1. 검사 로직 (예: 질문이 너무 짧은가?)
    if len(state["messages"][-1].content) < 2:
        # 너무 짧으면 모델 호출 안 하고 바로 끝냄 (점프!)
        return {"__jump_to__": "end", "messages": [AIMessage(content="질문이 너무 짧아요.")]}

    # 2. 검사를 통과했다면?
    return None # "정상적으로 모델에게 질문을 전달해라"
반환값의미톨게이트 비유
return None아무것도 안 바꾸고 다음 단계(보통 LLM)로 진행그냥 통과
return {"jump_to": "end", …}중간 단계 다 건너뛰고 즉시 종료회차로로 내보냄
한 줄 요약 can_jump_to=["end"] = "출구로 순간이동시킬 권한이 있다" · return None = "그 권한 안 쓰고 순서대로 진행" · return {"jump_to": "end"} = "그 권한 써서 바로 끝내기".

📚 한 장 정리

오늘의 핵심 LangChain의 모든 메시지는 BaseMessage에서 태어난 형제라서 content·type·id 같은 공통 속성을 늘 가진다. type은 "누가 한 말인지"를 알려주는 명찰이며, print에 안 보여도 메모리엔 엄연히 존재한다.
  • .type = 메시지의 명찰 — "human"·"ai"·"system"·"tool". 가드레일은 이걸 보고 사람 말일 때만 개입한다.
  • 왜 .type부터 확인? — messages엔 AI 답변·도구 결과도 섞이므로, 사람 질문에만 반응하도록 걸러 무한 루프를 막는다.
  • 어디서 왔나 — HumanMessage는 BaseMessage를 상속. type은 클래스에 미리 정의된(붕어빵 틀에 새겨진) 기본 속성이다.
  • 왜 print엔 안 보이나 — __repr__이 클래스 이름으로 이미 종류를 알 수 있어 type을 생략할 뿐, 실제 속성은 살아있다(택배 상자 겉면 vs 속 라벨).
  • 미들웨어 반환값 — return None은 "통과"(다음 단계로), jump_to: "end"는 "회차로"(즉시 종료). can_jump_to는 그 권한 허가증.
