6

Langfuse로 관측성 붙이기

서비스화 층 ⏱ 1~2시간
🎯 목표

서버가 처리한 모든 대화를 기록합니다 — 어떤 도구를 몇 번 불렀고, 토큰을 얼마나 썼고, 어디서 오래 걸렸는지. 기록은 Langfuse 대시보드에서 요청 하나 = 트리 하나로 보입니다.

🧠 개념 — 딱 하나만

Agent는 "왜 그렇게 답했는지"가 실행이 끝나는 순간 사라집니다

P1의 RAG는 길이 하나였어요(검색 → 생성). Agent는 질문마다 다른 길로 갑니다. "왜 이 답이 나왔지?"를 알려면 어떤 도구를 어떤 인자로 불렀는지 봐야 하는데, 그건 응답을 돌려주는 순간 메모리에서 지워집니다. 그래서 돌면서 남기는 장치가 필요하고, 그게 트레이싱입니다.

✈️ 비유 — 블랙박스

비행기가 무사히 내리면 아무도 블랙박스를 안 봅니다. 사고가 났을 때 "그 순간 무슨 일이 있었나"를 알 유일한 방법이라서 다는 거예요. 잘 도는 동안엔 쓸데없어 보이다가, "고객이 이상한 답을 받았다"는 제보가 오는 순간 이게 있느냐 없느냐로 갈립니다.

이번 STEP이 끝나면 "카드 연회비 조항 찾아보고 15000원의 5년치를 계산해줘"가 대시보드에 이렇게 남습니다.

▼ agent-chat 12.4s $0.0031 session: u3 ← 트레이스 (상자 하나 = 요청 하나) ├─ ChatOpenAI 1.8s 1,204 → 38 tokens ← "문서 검색이 필요하겠군" ├─ search_internal_docs 6.2s ← P1을 부르느라 제일 오래 걸림 ├─ ChatOpenAI 2.1s 3,890 → 52 tokens ← 검색 결과가 붙어 입력이 3배 ├─ calculate 0.0s ← 우리 함수라 공짜·즉시 └─ ChatOpenAI 2.3s 4,340 → 96 tokens ← 최종 답변

용어는 세 개만 알면 됩니다.

🛠 할 일 — agent.py, 세 조각

P1에서 Langfuse를 붙여 봤다면 ①은 그때와 같습니다. 새로운 건 ②의 "상자로 묶기"예요.

①

참관인 세우기

— 랭체인 실행을 지켜보다 Langfuse로 흘려보내는 객체 둘
from langfuse.langchain import CallbackHandler   # 모델 호출·도구 실행을 보고 기록하는 참관인
from langfuse import get_client                  # 상자에 이름표(세션·태그)를 붙일 때 쓰는 클라이언트

langfuse_handler = CallbackHandler()   # 키는 .env에서 스스로 읽는다 → 반드시 load_dotenv() '뒤'에
langfuse = get_client()
②

ask()를 상자 하나로 묶기

— with 블록이 상자를 열고, 그 안의 기록은 전부 상자의 자식이 된다
def ask(message: str, session_id: str = "default") -> dict:
    with langfuse.start_as_current_observation(name="agent-chat", as_type="span"):   # 상자 열기
        langfuse.update_current_trace(session_id=session_id, input=message)        # 상자에 이름표

        result = agent.invoke(
            {"messages": [{"role": "user", "content": message}]},
            {"configurable": {"thread_id": session_id},
             "callbacks": [langfuse_handler]},      # ← 이 줄이 있어야 참관인이 따라 들어간다
        )
        ...                                         # used_tools 세기·out 만들기는 STEP 4 그대로

        langfuse.update_current_trace(output=out, tags=used_tools or ["no_tool"])   # 결과도 상자에
        return out

바뀐 건 세 줄입니다. with로 상자를 열고, callbacks로 참관인을 들여보내고, 끝에 결과를 붙입니다. with가 없으면 모델 호출 3번이 서로 남남인 상자 3개로 흩어져서 "이 질문에 총 얼마 들었나"를 볼 수 없어요.

차단된 요청은 모델도 도구도 안 썼으니 토큰 0, 지연 0 — 대시보드에서 아무 일도 없었던 것처럼 보입니다. 그런데 운영에서 정말 세고 싶은 숫자가 "하루에 몇 번 막혔나"예요. 그래서 일부러 태그를 답니다.

# ── ask() 교체 ──
def ask(message: str, session_id: str = "default") -> dict:
    """질문 하나를 처리한다. 처리 과정 전체가 Langfuse에 트레이스 하나로 남는다."""
    with langfuse.start_as_current_observation(name="agent-chat", as_type="span"):
        langfuse.update_current_trace(session_id=session_id, input=message)

        result = agent.invoke(
            {"messages": [{"role": "user", "content": message}]},
            {"configurable": {"thread_id": session_id},
             "callbacks": [langfuse_handler]},
        )
        messages = result["messages"]

        last_human = max(i for i, m in enumerate(messages) if m.type == "human")
        used_tools = [
            call["name"]
            for m in messages[last_human:]
            if getattr(m, "tool_calls", None)
            for call in m.tool_calls
        ]

        reply = result.get("structured_response")
        if reply is None:
            out = {"answer": messages[-1].content, "sources": [], "confident": False,
                   "used_tools": [], "blocked": True}
        else:
            out = {"answer": reply.answer, "sources": reply.sources, "confident": reply.confident,
                   "used_tools": used_tools, "blocked": False}

        langfuse.update_current_trace(output=out, tags=used_tools or ["no_tool"])
        return out

  • 비용·시간이 찍힌다 — 트레이스마다 총비용과 총 소요시간. 제일 느린 칸은 어디인가?

🎓 한 줄 정리

요청 하나를 상자 하나로 묶어 남기면, "왜 이렇게 답했나 · 얼마 들었나 · 어디서 느렸나"를 추측이 아니라 기록으로 답할 수 있다.

더 알아보기 — 자주 겪는 두 가지 / 대시보드에서 해 볼 것

"돌렸는데 대시보드가 비어 있어요" → flush()

Langfuse는 기록을 모아 뒀다가 뒤에서 보냅니다. 서버는 계속 떠 있으니 괜찮지만, 짧은 스크립트는 다 보내기 전에 끝나 버려 기록이 통째로 사라져요. STEP 8의 evaluate.py가 딱 이 경우라, 맨 끝에 langfuse.flush()를 넣습니다.

"차단 태그가 안 보여요" → ask()를 거쳤나

update_current_trace는 지금 열려 있는 상자에 씁니다. ask()가 연 with 블록 밖에서(예: agent.invoke()를 직접) 부르면 열린 상자가 없어서 조용히 아무 일도 안 일어납니다. 에러도 안 나요.

입력 토큰이 불어나는 걸 눈으로 보세요

위 트리에서 입력 토큰이 1,204 → 3,890 → 4,340으로 커집니다. 도구 결과가 대화에 쌓여서 같은 질문 안에서도 입력이 불어나는 거예요. 멀티턴까지 겹치면 10번째 질문은 첫 질문의 몇 배가 됩니다. 이 숫자를 보고 나면 요약 미들웨어(SummarizationMiddleware)를 붙일지 말지를 감이 아니라 근거로 정할 수 있습니다.

트레이스를 느린 순으로 정렬해 보세요

십중팔구 맨 위는 search_internal_docs를 쓴 대화입니다 — P1의 리랭커가 무겁거든요. "느린 건 LLM이 아니라 내 도구였다"가 이 대시보드의 첫 수확인 경우가 많습니다.
