4

RAGAS 지표 장착

지표 층 ⏱ 1~2시간
🎯 목표

RAG 실행에 --ragas 플래그를 더해 faithfulness · answer_relevancy · context_precision · context_recall 네 열이 results.csv와 summary.json에 붙게 합니다. P1 STEP 7에서 한 번 해 본 채점을 러너의 부품으로 옮기는 STEP입니다.

🧠 개념 — 딱 하나만

STEP 3의 지표는 "했나"만 본다. "맞나"를 보려면 문맥과 정답을 놓고 심판이 필요하다

source_hit은 근거가 그 문서였는지만 봅니다. 답이 그 문서 내용과 다르게 지어냈는지, 정답의 절반을 빠뜨렸는지는 모르죠. 그걸 보려면 질문 · 검색된 문맥 · 답 · 정답 넷을 나란히 놓고 읽어야 하는데, 사람이 15개를 매번 읽을 수는 없습니다. RAGAS가 심판 LLM에게 그 일을 시킵니다.

지표무엇과 무엇을 비교하나묻는 것
faithfulness답 ↔ 문맥답의 주장들이 검색된 문맥에 실제로 있나 (지어내지 않았나)
answer_relevancy답 ↔ 질문답이 질문에 대답하고 있나 (딴소리가 아닌가)
context_precision문맥 ↔ 정답검색된 문맥 중 쓸모 있는 게 위쪽에 있나
context_recall문맥 ↔ 정답정답에 필요한 내용이 문맥에 빠짐없이 있나

넷 중 셋이 문맥을 읽습니다. STEP 2에서 P1에 include_contexts를 단 이유가 여기서 드러나요. 지표를 읽는 법은 P1 STEP 7에 자세히 있으니 여기서는 러너에 붙이는 일에 집중합니다.

STEP 3의 지표는 감독관이 시험장에서 바로 매기는 "출석 · 답안지 제출 · 이름 기재" 같은 것이고, RAGAS는 답안지를 모아 채점실로 보내는 일입니다. 한 장씩 보내면 왕복이 낭비되니 15장을 모아 한 번에 보내고, 돌아온 점수를 케이스 id로 다시 붙입니다.

🛠 할 일 — 두 조각
①

metrics.py — ragas_scores()

— P1 STEP 7의 evaluate.py를 함수 하나로
metrics.py — 맨 아래에 추가
import pandas as pd                                                  # ← 파일 맨 위 import에 추가

# ─────────────────────────────────────────────────────────────
# STEP 4 · RAGAS — 케이스를 모아 한 번에 채점한다 (한 건씩 부르면 오버헤드가 크다)
# ─────────────────────────────────────────────────────────────
RAGAS_METRICS = ["faithfulness", "answer_relevancy", "context_precision", "context_recall"]


def ragas_scores(rows: list[dict]) -> pd.DataFrame:
    """rows: [{id, question, answer, contexts, ground_truth}, ...]
    → id를 인덱스로, RAGAS 지표 4개를 열로 가진 표를 돌려준다."""
    # ragas는 무겁다(임포트에 수 초). 이 함수를 부를 때만 들여온다.
    from datasets import Dataset
    from langchain.chat_models import init_chat_model
    from langchain_openai import OpenAIEmbeddings
    from ragas import evaluate
    from ragas.embeddings import LangchainEmbeddingsWrapper
    from ragas.llms import LangchainLLMWrapper
    from ragas.metrics import answer_relevancy, context_precision, context_recall, faithfulness

    records = [{"question": r["question"], "answer": r["answer"],
                "contexts": r["contexts"], "ground_truth": r["ground_truth"]} for r in rows]
    result = evaluate(
        Dataset.from_list(records),
        metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
        # gpt-5 계열은 temperature를 기본값으로만 받는다 → bypass_temperature로 RAGAS가 건드리지 않게 한다 (P1 STEP 7과 동일)
        llm=LangchainLLMWrapper(init_chat_model("gpt-5-mini"), bypass_temperature=True),
        embeddings=LangchainEmbeddingsWrapper(OpenAIEmbeddings(model="text-embedding-3-small")),
    )
    df = result.to_pandas()[RAGAS_METRICS]
    df.index = [r["id"] for r in rows]
    return df

import를 함수 안에 둔 건 --ragas 없이 돌 때(Agent 평가, 빠른 smoke) ragas를 아예 안 읽게 하려는 겁니다. 임포트에만 몇 초가 걸리거든요. 돌아온 표의 인덱스를 케이스 id로 바꿔 두면 러너의 표와 join 한 줄로 붙습니다.

🎓 한 줄 정리

비싼 채점은 모아서 한 번에, 돌아온 점수는 id로 다시 붙인다. 러너의 나머지는 손대지 않았다 — 숫자 열이 늘면 요약은 알아서 따라온다.

더 알아보기 — 얼마나 드나 / NaN이 보이면 / 심판을 바꾸려면

한 번 돌리면 얼마나 드나

케이스 15개 × 지표 4개 — faithfulness는 답을 주장 단위로 쪼개 주장마다 묻기 때문에 실제 호출은 수십 회입니다. 3~5분, 몇백 원 수준이에요. 그래서 smoke는 3개로 돌리고, --ragas는 "이 실행을 비교에 쓸 것이다"라고 마음먹었을 때만 켭니다.

NaN이 보이면

심판 LLM의 응답을 RAGAS가 파싱하지 못한 케이스는 그 지표만 NaN이 됩니다. 요약의 평균은 그 케이스를 빼고 계산되니 표는 나오지만, results.csv에서 NaN이 몇 개인지는 확인하세요. 서너 개 이상이면 심판 모델이나 bypass_temperature 설정을 먼저 봅니다.

심판을 바꾸려면

init_chat_model("gpt-5-mini") 한 줄입니다. 시험 대상(P1)도 gpt-5-mini로 답을 만드니, 심판을 다른 계열로 두면 "자기 답에 후한" 편향을 줄일 수 있어요. 바꾸면 점수 절대값이 달라지므로 비교는 같은 심판으로 잰 실행끼리만 합니다 — summary.json에 심판 모델을 적어 두는 것도 좋은 습관입니다.
