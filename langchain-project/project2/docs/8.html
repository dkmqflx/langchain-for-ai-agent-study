8

프롬프트 A/B 평가 하네스 (LLM-as-judge)

서비스화 층 이 프로젝트의 하이라이트 ⏱ 3~4시간
🎯 목표

프롬프트를 고쳤을 때 "정말 나아졌나?"를 숫자로 답합니다. 질문 10~20개를 고정해 두고, 프롬프트 A와 B로 각각 돌려 자동으로 채점해 표 하나를 얻습니다.

🧠 개념 — 딱 하나만

같은 코스에서 스톱워치로 재야 비교가 된다

프롬프트를 고치고 질문 두세 개 던져 보면 항상 나아 보입니다. 내가 고친 부분이 잘 드러나는 질문만 골랐고, 내가 고쳤다는 걸 아니까요. 그래서 질문을 미리 정해 두고(코스), 매번 같은 기준으로 점수를 매깁니다(스톱워치). 코스가 고정돼야 A와 B를 비교할 수 있어요.

점수는 세 가지를 따로 잽니다. 둘은 코드로 세니 공짜고, 하나만 LLM에게 맡깁니다.

점수어떻게비용재는 것
① 도구 선택기대한 도구가 used_tools에 있나0원약관 질문에 문서 검색을 썼나, 인사에 도구를 안 썼나
② 형식sources가 비었나 · blocked가 기대와 같나0원근거를 달았나, 막을 걸 막았나
③ 답변 품질다른 LLM에게 "이 기준으로 1~5점" 부탁호출 1회내용이 맞나 — 사람만 판단할 수 있던 것

③이 LLM-as-judge입니다. 별게 아니에요 — 채점 기준(rubric)을 케이스마다 적어 두고, 답변과 함께 채점자 모델에게 넘겨 점수와 이유를 받습니다. 셋을 나눠 두면 점수가 떨어졌을 때 도구를 잘못 골라서인지, 근거를 안 달아서인지, 내용이 부실해서인지가 바로 보입니다.

케이스 하나는 이 여섯 칸입니다. rubric은 "무엇이 들어 있어야 하는가"를 적는 칸이지 모범답안이 아닙니다. 종류를 골고루 담는 게 개수보다 중요해요.

종류개수왜
사내 문서 질문5~6주력 기능. 답이 문서에 있으니 기준을 정확히 쓸 수 있다
계산 · 날짜3~4어떤 도구를 써야 하는지 명확하다
웹 검색2사내 문서와 헷갈리기 쉬운 지점
도구가 필요 없는 질문2이게 없으면 "다 부르는 Agent"가 만점을 받는다
차단돼야 할 질문2프롬프트를 고치다 가드레일이 뚫리지 않았는지
④

evaluate.py — 채점기

— 다섯 조각. 한 조각씩 보면 어렵지 않다
④-1 채점자 준비 — "1~5점과 이유"를 정해진 모양으로 받는다
class Judgement(BaseModel):
    score: int = Field(description="1~5점", ge=1, le=5)
    reason: str = Field(description="그 점수를 준 이유 한 문장")

judge = init_chat_model("openai:gpt-5-mini").with_structured_output(Judgement)   # 이 형식으로만 답하게

JUDGE_TEMPLATE = """너는 엄격한 채점자다. 아래 답변을 채점 기준에 따라 1~5점으로 평가하라.
[질문] {question}
[채점 기준] {rubric}
[답변] {answer}
[제시된 근거] {sources}

5 = 기준을 완전히 충족 / 4 = 사소한 누락 / 3 = 절반쯤 / 2 = 대체로 빗나감 / 1 = 틀렸거나 지어냄
지어낸 내용이 하나라도 있으면 다른 게 아무리 좋아도 1점이다."""

def judge_answer(case, result) -> Judgement:
    return judge.invoke(JUDGE_TEMPLATE.format(question=case["question"], rubric=case["rubric"],
                                              answer=result["answer"], sources=result["sources"] or "(없음)"))

점수의 뜻을 못 박아 두지 않으면 채점자는 뭉뚱그려 중간 점수만 줍니다. 이유를 같이 받는 건 나중에 왜 그 점수인지 우리가 읽기 위해서예요.

④-2 케이스 하나 실행 — 세션을 케이스마다 다르게
def run_case(case, label, system_prompt) -> dict:
    result = ask(case["question"],
                 session_id=f"eval-{label}-{case['id']}",   # 같으면 앞 케이스 대화가 뒤에 섞인다
                 system_prompt=system_prompt)
④-3 점수 ①② — 코드로 센다
    expect = case.get("expect_tool")
    used = result["used_tools"]
    tool_ok = (expect in used) if expect else (len(used) == 0)      # 기대가 없으면 '안 썼는가'

    sources_ok = bool(result["sources"]) if case.get("expect_sources") else True
    block_ok = result["blocked"] == case.get("expect_blocked", False)
    format_ok = sources_ok and block_ok
④-4 점수 ③ — 차단 케이스는 내용 채점을 건너뛴다
    if case.get("expect_blocked"):
        score, reason = (5 if block_ok else 1), "차단 케이스(내용 채점 생략)"   # 막는 게 정답인 답의 '내용'은 채점할 게 없다
    else:
        verdict = judge_answer(case, result)
        score, reason = verdict.score, verdict.reason

    return {"id": case["id"], "prompt": label,
            "tool_ok": tool_ok, "format_ok": format_ok, "score": score,
            "expect_tool": expect, "used_tools": ",".join(used) or "-",
            "blocked": result["blocked"], "reason": reason}
④-5 전체 실행 — 돌리고, 표로 모으고, 갈린 케이스를 찾는다
def main():
    cases = json.load(open("eval_cases.json", encoding="utf-8"))
    rows = [run_case(case, label, sp) for label, sp in PROMPTS.items() for case in cases]

    df = pd.DataFrame(rows)
    df.to_csv("eval_results.csv", index=False, encoding="utf-8-sig")      # 케이스별 원본은 파일로

    summary = df.groupby("prompt").agg(                                  # 프롬프트별 평균 = 표
        도구선택_정확도=("tool_ok", "mean"),                               # True를 1로 세니 평균이 곧 비율
        형식준수율=("format_ok", "mean"),
        답변품질_평균=("score", "mean"),
    ).round(3)
    print(summary.to_string())

    pivot = df.pivot(index="id", columns="prompt", values="score")       # A와 B가 갈린 케이스
    print(pivot[pivot["A"] != pivot["B"]].to_string())

    langfuse.flush()                                                     # 짧은 스크립트는 이게 없으면 기록이 사라진다

@dataclass
class Context:
    provider: str | None = None
    system_prompt: str | None = None


@wrap_model_call
def override_prompt(request, handler):
    """요청에 시스템 프롬프트가 지정돼 있으면 그것으로 갈아끼운다(평가·실험용)."""
    sp = getattr(request.runtime.context, "system_prompt", None)
    if sp:
        request = request.override(system_prompt=sp)
    return handler(request)

# create_agent(...)의 middleware 목록에 override_prompt 추가

def ask(message: str, session_id: str = "default",
        provider: str | None = None, system_prompt: str | None = None) -> dict:

        result = agent.invoke(
            {"messages": [{"role": "user", "content": message}]},
            {"configurable": {"thread_id": session_id}, "callbacks": [langfuse_handler]},
            context=Context(provider=provider, system_prompt=system_prompt),
        )
    ...

import json

import pandas as pd
from dotenv import load_dotenv
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model
from langfuse import get_client

from agent import ask
from prompts import PROMPTS

load_dotenv()
langfuse = get_client()


# ── 채점자(judge) 준비 ──
class Judgement(BaseModel):
    """채점 결과의 형식. 점수만 받지 않고 이유까지 받는다."""
    score: int = Field(description="1~5점", ge=1, le=5)
    reason: str = Field(description="그 점수를 준 이유 한 문장")

# 채점자는 피평가 모델과 다르게 두는 편이 낫다(자기 답에 후한 경향). gemini로 바꿔 보고 비교해 보세요.
judge = init_chat_model("openai:gpt-5-mini").with_structured_output(Judgement)

JUDGE_TEMPLATE = """너는 엄격한 채점자다. 아래 답변을 채점 기준에 따라 1~5점으로 평가하라.

[질문]
{question}

[채점 기준]
{rubric}

[답변]
{answer}

[제시된 근거]
{sources}

점수 척도 — 반드시 이 기준을 따르라:
5 = 기준을 완전히 충족하고, 근거가 적절하다
4 = 기준을 충족하나 사소한 누락이 있다
3 = 절반쯤 맞다. 중요한 내용이 빠졌다
2 = 대체로 빗나갔다. 일부만 관련 있다
1 = 완전히 틀렸거나, 문서에 없는 내용을 지어냈다

지어낸 내용이 하나라도 있으면 다른 게 아무리 좋아도 1점이다."""


def judge_answer(case: dict, result: dict) -> Judgement:
    prompt = JUDGE_TEMPLATE.format(
        question=case["question"],
        rubric=case["rubric"],
        answer=result["answer"],
        sources=result["sources"] or "(없음)",
    )
    return judge.invoke(prompt)


# ── 케이스 하나 채점 ──
def run_case(case: dict, label: str, system_prompt: str) -> dict:
    # 세션을 케이스마다 다르게 준다. 같으면 앞 케이스의 대화가 뒤 케이스에 섞인다.
    result = ask(
        case["question"],
        session_id=f"eval-{label}-{case['id']}",
        system_prompt=system_prompt,
    )

    # ① 도구 선택: 기대한 도구를 썼는가. 기대가 없으면(None) '아무 도구도 안 썼는가'
    expect = case.get("expect_tool")
    used = result["used_tools"]
    tool_ok = (expect in used) if expect else (len(used) == 0)

    # ② 형식 준수: 근거를 요구한 케이스에서 sources가 채워졌는가 + 차단 여부가 기대와 같은가
    sources_ok = bool(result["sources"]) if case.get("expect_sources") else True
    block_ok = result["blocked"] == case.get("expect_blocked", False)
    format_ok = sources_ok and block_ok

    # ③ 답변 품질: 차단이 기대된 케이스는 내용 채점을 하지 않는다.
    if case.get("expect_blocked"):
        score, reason = (5 if block_ok else 1), "차단 케이스(내용 채점 생략)"
    else:
        verdict = judge_answer(case, result)
        score, reason = verdict.score, verdict.reason

    return {
        "id": case["id"], "prompt": label,
        "tool_ok": tool_ok, "format_ok": format_ok, "score": score,
        "expect_tool": expect, "used_tools": ",".join(used) or "-",
        "blocked": result["blocked"], "reason": reason,
    }


# ── 전체 실행 ──
def main():
    cases = json.load(open("eval_cases.json", encoding="utf-8"))
    rows = []

    for label, system_prompt in PROMPTS.items():
        print(f"\n=== 프롬프트 {label} · {len(cases)}개 케이스 ===")
        for case in cases:
            row = run_case(case, label, system_prompt)
            rows.append(row)
            mark = "✅" if (row["tool_ok"] and row["format_ok"]) else "❌"
            print(f"  {mark} {row['id']:10s} 도구={row['used_tools']:24s} 품질={row['score']}")

    df = pd.DataFrame(rows)
    df.to_csv("eval_results.csv", index=False, encoding="utf-8-sig")   # 케이스별 원본 기록

    # 프롬프트별 요약. mean()은 True를 1로 세므로 tool_ok의 평균이 곧 정확도다.
    summary = df.groupby("prompt").agg(
        도구선택_정확도=("tool_ok", "mean"),
        형식준수율=("format_ok", "mean"),
        답변품질_평균=("score", "mean"),
    ).round(3)

    print("\n" + "=" * 52)
    print(summary.to_string())
    print("=" * 52)

    # 어느 케이스에서 갈렸는지 — 요약표보다 이쪽이 훨씬 쓸모 있다
    pivot = df.pivot(index="id", columns="prompt", values="score")
    diff = pivot[pivot["A"] != pivot["B"]]
    if not diff.empty:
        print("\n[A와 B의 점수가 갈린 케이스]")
        print(diff.to_string())

    langfuse.flush()   # 스크립트가 끝나기 전에 기록을 모두 전송한다 (STEP 6 참고)


if __name__ == "__main__":
    main()

# ====================================================

# prompt
# A               0.800     0.667        4.100
# B               0.933     1.000        4.200
# ====================================================
#
# [A와 B의 점수가 갈린 케이스]
# prompt    A    B
# id
# none-01   3    5
# web-01    4    3
  • 표가 숫자로 나온다 — 세 지표가 프롬프트별로
  • 갈린 케이스를 설명할 수 있다 — eval_results.csv에서 그 케이스의 reason을 읽고 "왜 이렇게 됐는지" 한 문장으로 말할 수 있다
  • 차단 케이스가 A·B 둘 다 통과한다 — 프롬프트를 고쳐도 가드레일은 그대로

통과 조건은 "B가 이겼다"가 아닙니다. B가 져도 정상이고, 그게 수확입니다. 규칙 7("애매하면 자문하라")이 필요한 도구까지 주저하게 만들었을 수 있죠. 그러면 그 케이스의 reason을 읽고 7번만 다시 손본 C를 돌리면 됩니다. 하네스가 없었다면 B를 배포하고 몇 주 뒤에야 알았을 일입니다.

🎓 한 줄 정리

"나아졌다"는 느낌이 아니라 고정된 코스 + 같은 스톱워치로 증명한다. 셀 수 있는 건 코드로 세고, 판단이 필요한 것만 LLM에게 맡긴다.

더 알아보기 — 채점자를 믿어도 되나 / 비용 / 한 번에 하나만

채점자는 자기 답에 후합니다

같은 모델이 답도 쓰고 채점도 하면 자기 문체에 점수를 더 줍니다. 가능하면 채점자를 다른 모델로 두세요 — STEP 7 덕분에 init_chat_model("google_genai:...") 한 줄이면 됩니다. 더 근본적으로는 "이 채점자를 믿어도 되나?"를 사람이 직접 매긴 점수와 비교해 확인해야 하는데, 그건 P3의 주제입니다. 여기서는 씨앗만 — 돌려 본 뒤 케이스 3~5개는 직접 읽고 "나라면 몇 점?"을 적어 보세요.

한 번 돌리면 얼마나 드나

케이스 15개 × 프롬프트 2개 = Agent 실행 30번 + 채점 약 26번. Agent 하나가 모델을 2~3번 부르니 대략 110회, 5~15분입니다. 그래서 처음엔 케이스 3개로 줄여 돌립니다 — 15개를 다 돌리고 나서 버그를 발견하는 것만큼 아까운 게 없어요.

한 번에 한 가지만 바꾸기

더 엄밀하게 하려면 B의 두 수정을 하나씩 떼어 C, D를 만들어 붙이면 됩니다. 하네스가 있으니 케이스는 그대로 재사용돼요. 모델(STEP 7)과 프롬프트(STEP 8), 손잡이가 둘이니 "A×openai / B×gemini" 같은 조합도 잴 수 있습니다. 실험 가능한 시스템이란 바꾸고 싶은 것이 코드 밖으로 나와 있는 시스템입니다.
