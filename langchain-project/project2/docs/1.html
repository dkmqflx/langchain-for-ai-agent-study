Agent 코어 ① — Tool 3종과 첫 Agent

🟢 랭체인 집중 ⏱ 1~2시간
🎯 목표

도구 세 개(날짜 · 계산 · 웹검색)를 만들어 create_agent로 묶습니다. 그리고 질문에 따라 LLM이 스스로 다른 도구를 고르는 것을 눈으로 확인합니다.

🧠 개념 — 딱 하나만

LLM은 도구를 주문할 뿐, 실행하지 않습니다

여기가 처음에 가장 헷갈립니다. @tool을 붙였다고 LLM이 파이썬을 돌리는 게 아니에요. LLM이 하는 일은 딱 하나 — "calculate를 expression="1234*5678"로 불러 주세요"라는 주문서를 쓰는 것입니다. 실제로 함수를 실행하는 것도, 결과를 다시 LLM에게 돌려주는 것도 랭체인이 합니다.

🙋 질문"1234 곱하기 5678은?"
→
🤖 LLM — 주문서tool_calls만 있고
본문은 비어 있다
→
⚙️ 랭체인 — 실행진짜로 calculate()를 부른다
→
📄 ToolMessage"7006652"를 대화에 붙인다
→
🤖 LLM — 판단더 필요하면 주문서를 또
됐으면 답변

마지막 칸에서 두 번째 칸으로 되돌아갈 수 있다는 게 핵심입니다. "오늘부터 100일 뒤는 며칠이야?"라면 날짜 도구 한 바퀴, 계산 도구 한 바퀴를 돕니다. P1의 RAG는 "검색 → 생성"으로 끝이었죠. 코드에 그렇게 적혀 있었으니까요. Agent는 몇 바퀴 돌지가 코드에 없습니다. 그게 Agent의 힘이자, 뒤에서 관측(STEP 6)과 평가(STEP 8)가 필요해지는 이유입니다.

🍽 비유 — 주방 없는 셰프

LLM은 레시피는 완벽히 아는데 손이 없는 셰프입니다. "양파 200g을 채썰어 줘"라고 주문서는 쓸 수 있지만 칼을 쥘 수는 없어요. 랭체인이 그 주문서를 받아 실제로 썰고, "썬 양파 200g 나왔습니다" 하고 셰프에게 되돌려 줍니다. 셰프는 그걸 보고 다음 주문서를 쓰거나, 이제 됐다 싶으면 요리를 내놓습니다.

그래서 도구 설명(docstring)이 곧 메뉴판입니다. 메뉴판에 없는 요리는 셰프가 주문할 수 없고, 설명이 애매하면 엉뚱한 걸 주문해요. LLM이 보는 건 이름 · 타입 힌트 · docstring 셋뿐입니다. 함수 본문은 못 봅니다.

단계주체하는 일
1사용자HumanMessage("1234 곱하기 5678이 얼마야?")
2LLM"이건 calculate를 써야겠군" 판단
3LLMAIMessage(content='', tool_calls=[{"name":"calculate","args":{"expression":"1234*5678"}}]) — 내용은 비어 있고 주문서만 있다
4랭체인실제로 calculate("1234*5678") 실행
5랭체인ToolMessage("7006652")를 대화에 추가
6LLM결과를 보고 판단 — 더 필요하면 2번으로 돌아가고, 됐으면 최종 답변
🛠 할 일 — 파일 둘, 네 조각

도구 하나를 만들 때 신경 쓸 건 함수 본문 · 타입 힌트 · docstring · @tool 네 가지입니다. 이 중 뒤의 셋만 LLM에게 전달됩니다.

①

tools.py — 준비물과 날짜 도구

— LLM은 '오늘'이 며칠인지 모른다
# ═══════════════════════════════════════════════════════════════════
# tools.py — Agent가 골라 쓸 능력들. 'LLM이 언제 이걸 써야 하는지 아는가'가 관건이다.
# ═══════════════════════════════════════════════════════════════════
import ast
import operator
from datetime import datetime
from zoneinfo import ZoneInfo          # 파이썬 3.9+ 내장. 시간대를 다룰 때 쓴다

from langchain.tools import tool       # 평범한 함수를 '도구'로 등록해 주는 데코레이터
from ddgs import DDGS                  # DuckDuckGo 검색 클라이언트 (API 키 불필요)


# ── 도구 1 · 오늘 날짜 ────────────────────────────────────────────
@tool
def get_today() -> str:
    """오늘 날짜와 현재 시각(한국 시간)을 알려준다.

    '오늘', '지금', '이번 주', '며칠 남았는지'처럼 현재 시점을 알아야 답할 수 있는
    질문에는 다른 무엇보다 먼저 이 도구를 호출한다.
    """
    now = datetime.now(ZoneInfo("Asia/Seoul"))
    weekday = "월화수목금토일"[now.weekday()]      # weekday()는 월=0 … 일=6
    return now.strftime(f"%Y-%m-%d %H:%M ({weekday}요일)")

LLM은 학습 데이터가 끝난 시점까지만 알고, 지금 이 순간이 언제인지는 알 방법이 없습니다. 그래서 날짜는 추측이 아니라 도구로 알려 줘야 해요. docstring에 "오늘·지금·이번 주" 같은 실제로 나올 법한 말을 적어 두면 LLM이 훨씬 잘 집어냅니다.

②

계산기 — 실행하지 않고 분해한다

— 수식을 나무로 쪼개 허용한 연산만 통과시킨다
# ── 도구 2 · 계산기 ──────────────────────────────────────────────
_OPS = {
    ast.Add: operator.add, ast.Sub: operator.sub,
    ast.Mult: operator.mul, ast.Div: operator.truediv,
    ast.Pow: operator.pow, ast.USub: operator.neg,   # USub = -5 같은 단항 마이너스
}

def _eval_node(node):
    """수식을 해석한 나무(AST)를 타고 내려가며 계산한다. 허용한 연산만 통과시킨다."""
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value                                        # 숫자면 그대로
    if isinstance(node, ast.BinOp) and type(node.op) in _OPS:     # a + b 같은 2항 연산
        return _OPS[type(node.op)](_eval_node(node.left), _eval_node(node.right))
    if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS:   # -a 같은 1항 연산
        return _OPS[type(node.op)](_eval_node(node.operand))
    raise ValueError("허용되지 않은 식")                           # 그 외는 전부 거부

@tool
def calculate(expression: str) -> str:
    """사칙연산과 거듭제곱으로 이루어진 수식을 계산한다.

    예: "1234 * 5678", "(120 - 45) / 3", "2 ** 10"
    숫자 계산이 필요하면 직접 암산하지 말고 반드시 이 도구를 사용한다.
    """
    try:
        # ast.parse(..., mode="eval") = 문자열을 '실행'하지 않고 '구조로 분해'만 한다.
        # .body가 그 구조의 뿌리 노드이고, _eval_node가 이걸 타고 내려가며 계산한다.
        return str(_eval_node(ast.parse(expression, mode="eval").body))
    except Exception:
        return f"계산할 수 없는 식입니다: {expression}"

expression은 LLM이 지어낸 문자열이고, LLM은 사용자 입력에 휘둘립니다. 그래서 실행하지 않고 ast로 분해만 한 뒤 _OPS에 적어 둔 연산만 통과시킵니다. 원칙 하나로 외워 두면 편합니다 — LLM이 만든 문자열은 사용자 입력과 똑같이 다룬다. 자세한 이야기는 아래 더 알아보기에 있습니다.

③

웹 검색 — 그리고 "여기 없는 것"까지 적기

— 실패는 예외가 아니라 문자열로 돌려준다
# ── 도구 3 · 웹 검색 ─────────────────────────────────────────────
@tool
def web_search(query: str, max_results: int = 3) -> str:
    """웹에서 최신 정보를 검색한다.

    뉴스, 시세, 최근에 일어난 일처럼 모델이 알 수 없는 '지금'의 정보가 필요할 때 사용한다.
    사내 문서나 약관의 내용은 이 도구로 찾을 수 없다.
    """
    try:
        hits = DDGS().text(query, max_results=max_results)
    except Exception as e:
        return f"웹 검색에 실패했습니다: {e}"     # 예외를 던지지 않고 '보고'한다
    if not hits:
        return "검색 결과가 없습니다."
    # LLM이 읽을 문자열로 정리한다. 출처(url)를 함께 넣어야 답변에 근거를 달 수 있다.
    return "\n\n".join(
        f"- {h.get('title')}\n  {h.get('body')}\n  ({h.get('href')})" for h in hits
    )

docstring 마지막 줄 — "사내 문서나 약관의 내용은 이 도구로 찾을 수 없다" — 을 눈여겨보세요. 언제 쓰는지만큼 언제 쓰면 안 되는지가 중요합니다. STEP 2에서 사내 문서 도구가 들어오면 이 한 줄이 둘을 갈라 줍니다.

그리고 세 도구 모두 실패를 문자열로 돌려줍니다. 도구가 예외를 던지면 Agent 실행 전체가 멈추고 사용자는 500 에러를 봅니다. "웹 검색에 실패했습니다: ..."를 돌려주면 그 문장이 ToolMessage로 LLM에게 전달되고, LLM은 "검색이 안 되니 다른 방법으로 답하자"고 스스로 대처해요. 도구의 반환값은 사람이 아니라 LLM에게 하는 보고입니다. 그래서 실패도 보고 대상입니다.

④

agent.py — 조립

— create_agent 한 번. 대신 지침서를 같이 준다
# ═══════════════════════════════════════════════════════════════════
# STEP 1 · Agent 조립: 모델 + 도구 + 시스템 프롬프트를 하나로 묶는다.
# 이 파일이 앞으로 메모리(STEP 3) · 가드레일(STEP 4) · 관측(STEP 6)을 얹어 가며 자란다.
# ═══════════════════════════════════════════════════════════════════
from dotenv import load_dotenv
from langchain.agents import create_agent

from tools import get_today, calculate, web_search

load_dotenv()                                        # .env의 OPENAI_API_KEY 로드

# 시스템 프롬프트 = Agent의 '행동 지침서'. 매 요청마다 대화 맨 앞에 조용히 붙는다.
SYSTEM_PROMPT = """너는 정확성을 최우선으로 하는 업무 비서다.

규칙:
1. 오늘 날짜·현재 시각이 필요하면 반드시 get_today를 호출한다. 날짜를 추측하지 않는다.
2. 숫자 계산은 반드시 calculate를 호출한다. 암산하지 않는다.
3. 최신 정보가 필요하면 web_search를 호출하고, 답변에 출처 URL을 함께 적는다.
4. 도구로도 확인할 수 없는 내용은 모른다고 말한다. 지어내지 않는다."""

# 모델은 "provider:model" 문자열로도 넘길 수 있다. STEP 7에서 이 부분을 갈아끼운다.
agent = create_agent(
    model="openai:gpt-5-mini",
    tools=[get_today, calculate, web_search],
    system_prompt=SYSTEM_PROMPT,
)


def ask(message: str):
    """질문 하나를 던지고, 오간 메시지 전체를 돌려준다.

    최종 답변만이 아니라 messages 전체를 돌려주는 게 지금 단계에서는 중요하다.
    '어떤 도구를 왜 골랐는지'가 그 안에 다 들어 있고, 그걸 봐야 학습이 된다.
    """
    result = agent.invoke({"messages": [{"role": "user", "content": message}]})
    return result["messages"]


if __name__ == "__main__":
    import sys
    question = sys.argv[1] if len(sys.argv) > 1 else "오늘 며칠이야? 그리고 1234 곱하기 5678은?"

    for m in ask(question):
        # AIMessage는 도구를 부를 때 content가 비어 있고 tool_calls에만 내용이 있다 —
        # 그래서 둘 다 찍어야 무슨 일이 있었는지 보인다.
        print(f"\n[{m.type}] {m.content}")
        if getattr(m, "tool_calls", None):
            print(f"    ↳ 호출: {[(c['name'], c['args']) for c in m.tool_calls]}")

도구를 쥐여 줬다고 알아서 쓰지는 않습니다. LLM은 "1234 × 5678" 정도는 도구 없이 답하려 들고, 종종 틀려요. "반드시 도구를 써라"라고 못 박는 게 시스템 프롬프트의 일입니다.

ask()가 최종 답변이 아니라 메시지 전체를 돌려주는 것도 지금은 일부러 그런 겁니다. 어떤 도구를 왜 골랐는지가 그 안에 다 들어 있고, 이 STEP에서 확인해야 할 게 정확히 그거니까요.

전체 코드 한 번에 보기 — tools.py 
# ═══════════════════════════════════════════════════════════════════
# STEP 1 · 도구(Tool) 정의: Agent가 골라 쓸 수 있는 능력들을 함수로 만든다.
# 여기서 중요한 건 '함수가 잘 도는가'보다 'LLM이 언제 이걸 써야 하는지 아는가'다.
# → 그 정보는 오직 함수 이름 · 타입 힌트 · docstring 세 가지로만 전달된다.
# ═══════════════════════════════════════════════════════════════════
import ast
import operator
from datetime import datetime
from zoneinfo import ZoneInfo

from langchain.tools import tool
from ddgs import DDGS


# ── 도구 1 · 오늘 날짜 ────────────────────────────────────────────
@tool
def get_today() -> str:
    """오늘 날짜와 현재 시각(한국 시간)을 알려준다.

    '오늘', '지금', '이번 주', '며칠 남았는지'처럼 현재 시점을 알아야 답할 수 있는
    질문에는 다른 무엇보다 먼저 이 도구를 호출한다.
    """
    now = datetime.now(ZoneInfo("Asia/Seoul"))
    weekday = "월화수목금토일"[now.weekday()]
    return now.strftime(f"%Y-%m-%d %H:%M ({weekday}요일)")


# ── 도구 2 · 계산기 ──────────────────────────────────────────────
_OPS = {
    ast.Add: operator.add, ast.Sub: operator.sub,
    ast.Mult: operator.mul, ast.Div: operator.truediv,
    ast.Pow: operator.pow, ast.USub: operator.neg,
}

def _eval_node(node):
    """수식을 해석한 나무(AST)를 타고 내려가며 계산한다. 허용한 연산만 통과시킨다."""
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in _OPS:
        return _OPS[type(node.op)](_eval_node(node.left), _eval_node(node.right))
    if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS:
        return _OPS[type(node.op)](_eval_node(node.operand))
    raise ValueError("허용되지 않은 식")

@tool
def calculate(expression: str) -> str:
    """사칙연산과 거듭제곱으로 이루어진 수식을 계산한다.

    예: "1234 * 5678", "(120 - 45) / 3", "2 ** 10"
    숫자 계산이 필요하면 직접 암산하지 말고 반드시 이 도구를 사용한다.
    """
    try:
        return str(_eval_node(ast.parse(expression, mode="eval").body))
    except Exception:
        return f"계산할 수 없는 식입니다: {expression}"


# ── 도구 3 · 웹 검색 ─────────────────────────────────────────────
@tool
def web_search(query: str, max_results: int = 3) -> str:
    """웹에서 최신 정보를 검색한다.

    뉴스, 시세, 최근에 일어난 일처럼 모델이 알 수 없는 '지금'의 정보가 필요할 때 사용한다.
    사내 문서나 약관의 내용은 이 도구로 찾을 수 없다.
    """
    try:
        hits = DDGS().text(query, max_results=max_results)
    except Exception as e:
        return f"웹 검색에 실패했습니다: {e}"
    if not hits:
        return "검색 결과가 없습니다."
    return "\n\n".join(
        f"- {h.get('title')}\n  {h.get('body')}\n  ({h.get('href')})" for h in hits
    )

  • 맞는 걸 고른다 — web_search를 부르고 답변에 출처 URL이 붙는다
  • 안 부르기도 한다 — 인사에는 ↳ 호출: 줄이 하나도 없다
  • 주문서가 보인다 — 도구를 부른 [ai] 줄은 본문이 비어 있고 호출 줄만 있다. 개념에서 본 3단계가 이것이다

세 번째가 핵심입니다. 모든 질문에 도구를 부르는 Agent는 고르는 게 아니라 그냥 다 부르는 것이고, 비용과 지연만 늘어요. "안 쓰는 판단"까지 되어야 통과입니다.

🎓 한 줄 정리

LLM은 도구를 주문하고, 랭체인이 실행한다. 그러니 도구를 만드는 일은 함수를 짜는 일이 아니라 설명서를 쓰는 일이다 — LLM이 보는 건 이름 · 타입 힌트 · docstring, 그 셋뿐이다.

더 알아보기 — 왜 eval을 쓰지 않나 / 잘 안 될 때 / ddgs 반환 모양

계산기를 eval() 한 줄로 만들지 않는 이유

return str(eval(expression))이면 한 줄로 끝납니다. 그런데 expression은 LLM이 만든 문자열이고, LLM은 사용자가 쓴 말을 그대로 옮겨 담기도 합니다. 누군가 "이걸 계산해 줘: __import__('os').system(...)"처럼 유도하면 그 코드가 내 서버에서 실행됩니다.

ast.parse(..., mode="eval")은 문자열을 실행하지 않고 구조로 분해만 합니다. 우리가 _OPS에 적어 둔 연산자를 만나면 계산하고, 그 밖의 것(함수 호출, 속성 접근, 이름)을 만나면 raise ValueError로 거부하죠. 허용 목록을 두는 방식이라, 모르는 공격도 기본적으로 막힙니다.

도구를 엉뚱하게 고른다면 docstring부터

안 불러야 할 때 부르거나 불러야 할 때 안 부른다면, 코드보다 설명이 원인일 확률이 훨씬 높습니다. LLM이 보는 정보가 이름·타입 힌트·docstring뿐이라는 걸 떠올려 보세요. "언제 쓰는지"와 "언제 쓰면 안 되는지"를 둘 다 적으면 정확도가 확실히 올라갑니다. 인자 설명(Args:)에 "무엇을 어떤 형태로 넣어라"까지 적으면 인자 품질도 같이 좋아집니다.
