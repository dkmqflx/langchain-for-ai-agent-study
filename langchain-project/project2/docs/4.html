4

Guardrails + Structured Output

🟢 랭체인 집중 ⏱ 2시간
🎯 목표

막을 질문은 모델에 닿기 전에 돌려보내고, 답은 정해진 칸에 담아 받습니다. 지금까지 ask()가 돌려주던 자유로운 문장이, 이 STEP을 지나면 answer·sources·confident로 나뉜 결과가 됩니다.

🧠 개념 — 딱 하나만

모델 앞뒤에 문을 하나씩 답니다

모델은 설득당합니다. "이전 지시는 무시하고…"라고 하면 넘어갈 수 있고, "근거를 꼭 적어라"라고 시켜도 가끔 빠뜨립니다. 그래서 모델에게 부탁하는 대신, 모델 바깥에 코드가 지키는 문을 답니다. 들어오는 문 하나, 나가는 문 하나.

들어오는 문은 03에서 배운 @before_agent 자리입니다. 질문이 모델에 가기 직전에 한 번 실행되고, 막을 질문이면 jump_to: "end"로 모델을 부르지 않고 준비된 거절 문구만 돌려줍니다. 모델을 안 부르니 설득당할 일도, 토큰이 들 일도 없습니다.

나가는 문은 response_format입니다. Pydantic 스키마를 주면 모델이 정해진 칸을 채워서 답합니다. 그러면 "근거를 달았나?"를 if not reply.sources 한 줄로 확인할 수 있어요. 문장에서 근거를 찾아내는 건 사람이 읽어야 하지만, 칸이 비었는지는 코드가 봅니다.

✈️ 비유 — 공항

보안 검색대는 탑승동 안이 아니라 문 앞에 있습니다. 위험한 물건은 비행기에 실린 다음 찾는 게 아니라 들어오기 전에 거르죠 — 가드레일이 그 자리입니다. 그리고 입국신고서는 자유 서술이 아니라 칸이 정해져 있습니다. 이름 칸, 체류지 칸, 목적 칸. 그래야 직원이 문장을 읽지 않고 칸만 보면 되니까요 — 구조화 출력이 그겁니다.

🛠 할 일 — agent.py, 세 조각

도구도 프롬프트도 그대로 둡니다. 문 두 개를 달고, ask()가 칸에서 값을 꺼내도록 바꾸는 게 전부예요.

①

들어오는 문 — 키워드 검문소

— 막을 주제 · 거절 문구 · 검사 함수
from langchain.agents.middleware import before_agent, PIIMiddleware
from langchain.messages import AIMessage

# 막을 주제와 그 신호 단어들. 전부 막는 게 아니라 흔한 경로를 싸게 막는 게 목적이다.
BLOCKED = {
    "prompt_injection": ["시스템 프롬프트", "이전 지시 무시", "규칙 무시", "너의 지침", "system prompt"],
    "investment_advice": ["어디에 투자", "수익 보장", "원금 보장", "얼마 벌 수", "추천 종목"],
    "credential": ["비밀번호 알려", "계좌 비밀번호", "주민등록번호 알려", "카드번호 알려"],
}

# 카테고리마다 다른 거절 문구. "처리할 수 없습니다" 하나로 뭉뚱그리면 고장 난 줄 안다.
REFUSALS = {
    "prompt_injection": "죄송합니다. 시스템 설정이나 내부 지침에 관한 요청은 처리할 수 없습니다.",
    "investment_advice": "저는 약관·규정 안내만 도와드릴 수 있습니다. 투자 판단이나 수익에 관한 답변은 드릴 수 없어요.",
    "credential": "비밀번호·주민등록번호 같은 민감정보는 다루지 않습니다. 해당 기관에 직접 문의해 주세요.",
}


@before_agent(can_jump_to=["end"])     # 모델 호출 직전에 실행 + 곧장 끝으로 점프할 권한
def input_guardrail(state, runtime):
    if not state["messages"]:
        return None
    last = state["messages"][-1]
    if last.type != "human":           # 사람이 방금 한 말이 아니면 검사할 게 없다
        return None

    for category, keywords in BLOCKED.items():
        for kw in keywords:
            if kw in last.content:
                print(f"⛔ 차단 [{category}] — '{kw}' 감지")   # STEP 6에서 Langfuse 기록으로 바꾼다
                return {
                    "messages": [AIMessage(content=REFUSALS[category])],
                    "jump_to": "end",              # 모델을 부르지 않고 끝낸다
                    "structured_response": None,   # 나가는 문의 칸은 비워 둔다
                }

    return None                        # None = "이상 없음, 평소대로 진행하라"

검사는 키워드 매칭입니다. 돌려 말하면 놓치지만 공짜고, 빠르고, 결과가 항상 같습니다. 싸고 확실한 검사를 앞에 둔다 — STEP 8의 채점에서도 똑같은 원칙을 씁니다.

structured_response를 None으로 비우는 이유는, 이 값이 대화방에 남는 값이기 때문입니다. 평소엔 모델이 답할 때 새 값으로 덮이는데 여기서는 모델을 안 부르고 끝내므로, 직접 비워 두면 ask()가 "이번엔 칸이 없다 = 막힌 것"으로 읽습니다.

②

나가는 문 — 칸을 정의하고 Agent에 끼우기

— ChatReply + create_agent
from pydantic import BaseModel, Field
from langchain.agents.middleware import ToolCallLimitMiddleware
from langchain.agents.structured_output import ProviderStrategy


class ChatReply(BaseModel):
    """최종 답변의 형식. description은 모델에게 주는 '칸 기입 요령'이다."""
    answer: str = Field(description="사용자에게 보여줄 답변 본문")
    sources: list[str] = Field(
        default_factory=list,
        description="근거 출처 목록. 사내 문서면 '문서명 p.쪽수', 웹이면 URL. 근거가 없으면 빈 목록.",
    )
    confident: bool = Field(description="근거로 확인한 내용이면 true, 모르거나 확인하지 못했으면 false")


agent = create_agent(
    model="openai:gpt-5-mini",
    tools=[get_today, calculate, web_search, search_internal_docs],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=checkpointer,
    middleware=[
        input_guardrail,                                                     # ① 키워드 검문소
        PIIMiddleware("credit_card", strategy="mask", apply_to_input=True),  # ② 카드번호는 뒷자리만 남긴다
        PIIMiddleware("email", strategy="redact", apply_to_input=True),      #    이메일은 지운다
        ToolCallLimitMiddleware(run_limit=8, exit_behavior="continue"),      # ③ 요청당 도구 호출 상한
    ],
    response_format=ProviderStrategy(ChatReply),                             # ④ 나가는 문
)

카드번호·이메일처럼 형태가 정해진 민감정보는 키워드로 잡기 어려우니 내장 PIIMiddleware에 맡깁니다. 사용자가 실수로 붙여넣은 번호가 OpenAI 서버까지 가는 걸 여기서 끊어요.

ProviderStrategy는 OpenAI의 JSON 스키마 모드를 그대로 씁니다. 모델이 "더 부를 도구가 없다"고 판단하면 그 답이 곧 ChatReply가 됩니다. 도구 호출은 평소 1~3번이면 끝나므로 run_limit=8이면 넉넉하고, 넘으면 도구 대신 "한도 초과"를 돌려주어(continue) 모델이 모은 것으로 답을 맺습니다.

③

ask() — 칸에서 꺼내 한 모양으로

— 막힌 경우와 정상인 경우가 같은 dict
def ask(message: str, session_id: str = "default") -> dict:
    result = agent.invoke(
        {"messages": [{"role": "user", "content": message}]},
        {"configurable": {"thread_id": session_id}},
    )
    messages = result["messages"]

    # 이번 턴에 쓴 도구만 센다. messages에는 지난 대화까지 다 있으니
    # '마지막 사용자 발화' 위치를 찾아 그 뒤 구간만 훑는다.
    last_human = max(i for i, m in enumerate(messages) if m.type == "human")
    used_tools = [
        call["name"]
        for m in messages[last_human:]
        if getattr(m, "tool_calls", None)    # tool_calls는 AIMessage에만 있다
        for call in m.tool_calls             # 한 메시지가 도구를 여러 개 부를 수도 있다
    ]

    reply = result.get("structured_response")   # 막혔으면 비어 있다
    if reply is None:
        return {
            "answer": messages[-1].content,     # 가드레일이 넣어 둔 거절 문구
            "sources": [],
            "confident": False,
            "used_tools": [],
            "blocked": True,
        }

    return {
        "answer": reply.answer,
        "sources": reply.sources,
        "confident": reply.confident,
        "used_tools": used_tools,
        "blocked": False,
    }

두 갈래 모두 칸 다섯 개짜리 같은 모양으로 나옵니다. 부르는 쪽은 blocked만 보면 되고, 예외 처리를 따로 안 해도 됩니다 — STEP 5의 API도 STEP 8의 채점기도 이 모양 하나만 알면 돼요.

used_tools만 스키마에 넣지 않고 코드로 세는 이유는, 도구를 뭘 불렀는지가 messages에 사실로 남아 있기 때문입니다. 확인할 수 있는 걸 모델에게 물어보면 틀릴 여지만 생깁니다.

전체 코드 한 번에 보기 — agent.py (STEP 4까지) 
# ═══════════════════════════════════════════════════════════════════
# STEP 4 · Agent 조립: 모델 + 도구 + 프롬프트 + 메모리 + 가드레일 + 구조화 출력.
# 실행: uv run python agent.py [세션이름]
# ═══════════════════════════════════════════════════════════════════
from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.agents.middleware import (
    before_agent, PIIMiddleware, ToolCallLimitMiddleware,
)
from langchain.agents.structured_output import ProviderStrategy
from langchain.messages import AIMessage
from langgraph.checkpoint.memory import InMemorySaver
from pydantic import BaseModel, Field

from tools import get_today, calculate, web_search, search_internal_docs

load_dotenv()

SYSTEM_PROMPT = """너는 정확성을 최우선으로 하는 업무 비서다.

규칙:
1. 오늘 날짜·현재 시각이 필요하면 반드시 get_today를 호출한다. 날짜를 추측하지 않는다.
2. 숫자 계산은 반드시 calculate를 호출한다. 암산하지 않는다.
3. 약관·규정·계약 조건에 관한 질문은 web_search보다 search_internal_docs를 먼저 쓴다.
   우리 문서에 있는 내용을 인터넷에서 찾으면 틀린 답이 나온다.
4. search_internal_docs의 결과를 쓸 때는 답변에 [근거]의 문서명과 쪽수를 반드시 적는다.
5. 최신 정보가 필요하면 web_search를 호출하고, 답변에 출처 URL을 함께 적는다.
6. 도구로도 확인할 수 없는 내용은 모른다고 말한다. 지어내지 않는다."""

# ─── 들어오는 문 ────────────────────────────────────────────────
BLOCKED = {
    "prompt_injection": ["시스템 프롬프트", "이전 지시 무시", "규칙 무시", "너의 지침", "system prompt"],
    "investment_advice": ["어디에 투자", "수익 보장", "원금 보장", "얼마 벌 수", "추천 종목"],
    "credential": ["비밀번호 알려", "계좌 비밀번호", "주민등록번호 알려", "카드번호 알려"],
}

REFUSALS = {
    "prompt_injection": "죄송합니다. 시스템 설정이나 내부 지침에 관한 요청은 처리할 수 없습니다.",
    "investment_advice": "저는 약관·규정 안내만 도와드릴 수 있습니다. 투자 판단이나 수익에 관한 답변은 드릴 수 없어요.",
    "credential": "비밀번호·주민등록번호 같은 민감정보는 다루지 않습니다. 해당 기관에 직접 문의해 주세요.",
}


@before_agent(can_jump_to=["end"])
def input_guardrail(state, runtime):
    """사용자 입력이 LLM에 닿기 전에 검사한다. 막을 게 없으면 None을 돌려준다."""
    if not state["messages"]:
        return None
    last = state["messages"][-1]
    if last.type != "human":
        return None

    text = last.content
    for category, keywords in BLOCKED.items():
        for kw in keywords:
            if kw in text:
                print(f"⛔ 차단 [{category}] — '{kw}' 감지")
                return {
                    "messages": [AIMessage(content=REFUSALS[category])],
                    "jump_to": "end",
                    "structured_response": None,
                }

    return None


# ─── 나가는 문 ─────────────────────────────────────────────────
class ChatReply(BaseModel):
    """사용자에게 돌려줄 최종 답변의 형식."""

    answer: str = Field(description="사용자에게 보여줄 답변 본문")
    sources: list[str] = Field(
        default_factory=list,
        description="근거 출처 목록. 사내 문서면 '문서명 p.쪽수', 웹이면 URL. "
                    "도구를 쓰지 않았거나 근거가 없으면 빈 목록.",
    )
    confident: bool = Field(
        description="근거로 확인한 내용이면 true, 모르거나 확인하지 못했으면 false",
    )


# 대화 기록 보관함(STEP 3). RAM에 저장하므로 서버를 끄면 사라진다.
checkpointer = InMemorySaver()

agent = create_agent(
    model="openai:gpt-5-mini",
    tools=[get_today, calculate, web_search, search_internal_docs],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=checkpointer,
    middleware=[
        input_guardrail,
        PIIMiddleware("credit_card", strategy="mask", apply_to_input=True),
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        ToolCallLimitMiddleware(run_limit=8, exit_behavior="continue"),
    ],
    response_format=ProviderStrategy(ChatReply),
)


def ask(message: str, session_id: str = "default") -> dict:
    """질문 하나를 {answer, sources, confident, used_tools, blocked} 형태로 돌려준다."""
    result = agent.invoke(
        {"messages": [{"role": "user", "content": message}]},
        {"configurable": {"thread_id": session_id}},
    )
    messages = result["messages"]

    last_human = max(i for i, m in enumerate(messages) if m.type == "human")
    used_tools = [
        call["name"]
        for m in messages[last_human:]
        if getattr(m, "tool_calls", None)
        for call in m.tool_calls
    ]

    reply = result.get("structured_response")
    if reply is None:
        return {
            "answer": messages[-1].content,
            "sources": [],
            "confident": False,
            "used_tools": [],
            "blocked": True,
        }

    return {
        "answer": reply.answer,
        "sources": reply.sources,
        "confident": reply.confident,
        "used_tools": used_tools,
        "blocked": False,
    }


if __name__ == "__main__":
    import sys

    session = sys.argv[1] if len(sys.argv) > 1 else "demo"
    print(f"세션 '{session}' — 빈 줄을 입력하면 종료합니다.")

    while True:
        try:
            msg = input("\n나 > ").strip()
        except (EOFError, KeyboardInterrupt):
            break
        if not msg:
            break

        print(ask(msg, session))

  • 막힌다 — blocked: True가 1초 안에 온다. 오래 걸리면 모델을 부른 것이다

  • 정상 답 뒤의 차단도 깨끗하다 — answer가 거절 문구이고 blocked: True
🎓 한 줄 정리

모델을 설득으로 지키지 말고, 모델 앞뒤에 코드가 지키는 문을 단다. 앞 문은 공짜로 확실하고, 뒤 문은 답을 측정할 수 있게 만든다 — 칸이 없으면 STEP 8에서 채점할 대상 자체가 없다.

더 알아보기 — 키워드의 한계 / mask와 redact / 나가는 문의 다른 방식

키워드 목록은 완성되지 않습니다

"시스템 프롬프트"는 막지만 "너한테 처음에 뭐라고 시켰어?"는 통과합니다. 그래도 키워드를 앞에 두는 이유는 공짜이고, 빠르고, 결과가 항상 같기 때문입니다. 실무에서는 이 뒤에 한 겹을 더 둡니다 — 모더레이션 API나 작은 분류 모델에게 "이 질문이 다음 중 어디에 해당하나"를 묻는 방식이죠. 돈과 시간이 드니 키워드에서 안 걸린 것만 보냅니다. 이 프로젝트는 1차까지만 만들고, 2차가 없다는 사실을 STEP 9 README의 한계 목록에 한 줄 남깁니다.

mask와 redact의 차이

mask는 뒷자리를 남기고 가립니다(****-****-****-1234). 카드번호는 "내가 말한 그 카드"를 가리킬 수 있어야 대화가 되니까요. redact는 통째로 지웁니다. 이메일은 남길 이유가 없어서 이쪽을 씁니다. apply_to_input=True는 모델에 보내기 전에 처리하라는 뜻입니다 — 가려진 뒤에 나가야 의미가 있으니까요.

나가는 문을 만드는 두 가지 방식

ProviderStrategy는 모델 제공자의 JSON 스키마 기능을 그대로 씁니다. 모델이 도구를 다 쓰고 나면 본문 자체가 ChatReply 모양으로 옵니다. 다른 선택지인 ToolStrategy는 "답을 담는 도구"를 하나 더 쥐여 주고 그 도구를 부르게 하는 방식이라, 제공자 기능이 없는 모델에서도 쓸 수 있습니다. 대신 매 스텝 도구를 하나씩 고르게 되어 호출 수가 늘기 쉽습니다. OpenAI는 제공자 기능이 있으니 이 프로젝트는 ProviderStrategy를 쓰고, 그래도 길어질 수 있는 경우는 ToolCallLimitMiddleware가 8번에서 끊습니다. 모델을 Gemini로 바꿀 때 어느 쪽이 되는지는 STEP 7에서 다시 봅니다.

나가는 쪽 가드레일은 왜 안 만들었나

답변을 다시 검사하는 @after_agent도 있습니다. 다만 "근거 없이 단정하는 답"은 이미 sources가 비었는지, confident가 False인지로 부르는 쪽이 판단할 수 있습니다. 칸을 만들어 두면 별도의 검사 층이 필요 없어지는 셈이죠. 답변 자체를 다시 모델에게 검토시키는 방식은 호출이 한 번 더 드는 대신 잡는 게 많아지는데, 그 저울질은 STEP 8에서 점수로 확인합니다.
