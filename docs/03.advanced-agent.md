## 1장. Advanced Agent

### 1.1 Context Engineering

<img src='../images/03.advanced-agent/02.png'>

"프롬프트 엔지니어링"보다 "**컨텍스트 엔지니어링**"이라는 용어가 더 중요해지고 있습니다.

> _"Context Engineering is the delicate art and science of filling the context window with just the right information for the next step."_

LLM 앱을 개발할 때 컨텍스트 엔지니어링(Context Engineering)은 필요한 정보를 Context Window에 아주 적절하게 채워 넣는, 섬세한 예술이자 과학의 영역입니다.

- 정보가 너무 적거나 형식이 잘못되면 LLM은 최적의 성능을 낼 수 없습니다.
- 반대로 정보가 너무 많거나 불필요한 내용이 가득하면 비용은 증가하고 성능은 오히려 떨어질 수 있습니다.

### 1.2 Runtime & State

<img src='../images/03.advanced-agent/03.png'>

Advanced Agent를 구현하기 위한 핵심 개념 두 가지입니다.

#### Runtime — Agent 실행에 필요한 공유 정보

| 구성 요소         | 설명                                                       | 역할              |
| :---------------- | :--------------------------------------------------------- | :---------------- |
| **Context**       | 사용자 Id나 DB 연결 URL처럼 Agent 실행 시 변하지 않는 정보 | 보안 및 권한 제어 |
| **Store**         | 사용자의 선호도, 이름 등 장기 메모리                       | 개인화 및 제어    |
| **Stream writer** | Agent 내부 작동 로그 등 실시간 이벤트 출력 기능            | 모니터링          |

#### State — Agent가 작동하며 만든 결과물

| 구성 요소        | 설명                                     | 역할           |
| :--------------- | :--------------------------------------- | :------------- |
| **Message**      | Model이 Runtime을 참조해가며 만든 결과물 | 대화 흐름 제어 |
| **tool_results** | Tool이 만든 정보 모음                    | 도구 실행 결과 |

<img src='../images/03.advanced-agent/04.png'>

> 💡 **State**가 Agent 내부 흐름(대화, 도구 결과)을 제어한다면, **Runtime**은 그 외부 환경(사용자 정보, 저장소, 스트림)을 제어합니다.

### 1.3 dataclass — Context 클래스 작성 도구

<img src='../images/03.advanced-agent/06.png'>

**`dataclass`** 는 Python에서 데이터 중심 클래스(data container)를 쉽게 만드는 문법입니다. (Python 3.7+ 내장)

일반 클래스를 만들 때 반복적으로 작성해야 하는 `__init__`, `__repr__` 등의 메서드를 `@dataclass` 데코레이터 하나로 자동 생성해 줍니다.

<img src='../images/03.advanced-agent/07.png'>

| 메서드          | 설명                              |
| :-------------- | :-------------------------------- |
| `__init__`      | 필드 초기화 메서드 자동 생성      |
| `__repr__`      | 보기 좋은 문자열 표현 자동 생성   |
| `__eq__`        | 객체 비교(`==`) 자동 구현         |
| `__hash__`      | (옵션) 해시 가능하게 설정 가능    |
| `__post_init__` | 생성자 이후 추가 초기화 로직 가능 |

```python
from dataclasses import dataclass

@dataclass
class Context:
    user_name: str
    age: int = 20  # 기본값 가능

ctx1 = Context("Jay")
ctx2 = Context("Jay")
print(ctx1)        # Context(user_name='Jay', age=20)
print(ctx1 == ctx2)  # True
```

### 1.4 Middleware에서 Runtime 접근하기 — 방법 1: Node-style (데코레이터)

<img src='../images/03.advanced-agent/09.png'>

`create_agent`에 `context_schema=Context`를 전달하면 Middleware 함수가 `runtime`을 통해 Context 정보에 접근할 수 있습니다.

```python
from langchain.agents import create_agent
from dataclasses import dataclass

@dataclass
class Context:
    user_name: str

agent = create_agent(
    model="gpt-5-mini",
    tools=[],
    middleware=[log_before_model],
    context_schema=Context,   # Context 스키마 전달
)

agent.invoke(
    {"messages": [{"role": "user", "content": "제 이름이 뭐죠?"}]},
    context=Context(user_name="Jay"),  # 호출 시 Context 인스턴스 주입
)
```

<img src='../images/03.advanced-agent/10.png'>

#### Node-style vs Wrap-style Hook 비교

| 구분              | Node-style Hook                                                  | Wrap-style Hook                                                  |
| :---------------- | :--------------------------------------------------------------- | :--------------------------------------------------------------- |
| **동작 방식**     | 특정 실행 지점(before/after)에서 **순차적**으로 동작             | 실행 흐름(model call, tool call 등)을 **감싸서(intercept)** 조작 |
| **입력 파라미터** | `state`, `runtime`                                               | `request`, `handler`                                             |
| **적합한 용도**   | 상태 확인, 로깅, 유효성 검사                                     | 동적 프롬프트 삽입, 흐름 건너뛰기 등 흐름 제어 및 변형           |
| **데코레이터**    | `@before_agent`, `@before_model`, `@after_model`, `@after_agent` | `@wrap_model_call`, `@wrap_tool_call`                            |

<img src='../images/03.advanced-agent/11.png'>

**Node-style 예시** — `@before_model` 데코레이터 사용:

```python
from langchain.agents.middleware import before_model

@before_model
def log_before_model(state, runtime):
    print(f"(step1)before_model_state : \n{state}")
    print(f"(step2)before_model_runtime : \n{runtime}")
    print(f"(step3)사용자 이름 : {runtime.context.user_name}")
    return None
```

> 📝 `@before_model` 은 **Model이 호출될 때마다** 실행됩니다. (Tool 호출 → Model 재호출 시에도 반복 실행)
> 반면 `@before_agent` 는 Agent 실행 시 **딱 한 번**만 실행됩니다.

### 1.5 Middleware에서 Runtime 접근하기 — 방법 2: Wrap-style

<img src='../images/03.advanced-agent/13.png'>

**Wrap-style** 은 model이나 tool이 호출될 때 실행과 제어를 **가로채는(intercept)** 방식입니다.  
입력 파라미터는 `request`(요청 객체)와 `handler`(실제 실행 함수)입니다.

<img src='../images/03.advanced-agent/14.png'>

#### `ModelRequest` 구조

```python
ModelRequest(
    model=...,           # 어떤 모델을 쓸지 (예: ChatOpenAI)
    system_prompt=...,   # 시스템 프롬프트 (없을 수도 있음)
    messages=...,        # 대화 메시지 목록
    tool_choice=...,     # 특정 tool을 강제 선택하도록 지정할 때
    tools=...,           # 사용 가능한 도구 목록
    response_format=..., # 출력 포맷 (예: JSON schema)
    state=...,           # 실행 상태 (메시지 기록 등)
    runtime=...,         # 실행 환경 정보 (context, store, stream 등)
    model_settings=...,  # 모델 설정 (온도, 토큰 제한 등)
)
```

<img src='../images/03.advanced-agent/15.png'>

**Wrap-style 예시** — `@wrap_model_call`로 사용자 이름을 시스템 메시지에 동적 삽입:

```python
from langchain.agents.middleware import wrap_model_call
from langchain.messages import SystemMessage

@wrap_model_call
def inject_user_name(request, handler):
    # ① 요청 가로채기
    print(f"request : \n{request}")

    # ② request.runtime.context.user_name 접근
    user_name = request.runtime.context.user_name

    # ③ 시스템 메시지 삽입 (요청 수정)
    if user_name:
        system_message = f"사용자의 이름은 {user_name}입니다"
        request = request.override(system_prompt=system_message)

    # ④ 수정된 요청을 다음 단계(LLM 호출)로 넘김
    return handler(request)
```

<img src='../images/03.advanced-agent/16.png'>

> 💡 **Context + Middleware 조합의 실용 예시**: 로그인한 사용자는 고급 모델(GPT-5)을, 비로그인 사용자는 기본 모델(GPT-5-nano)을 사용하도록 하는 Agent 서비스를 구축할 수 있습니다.

### 1.6 Custom Middleware — Node-style 심화

<img src='../images/03.advanced-agent/17.png'>

#### `@before_agent` vs `@before_model` 실행 횟수

- **`@before_agent`** : Agent 전체 실행에서 **딱 한 번** 실행
- **`@before_model`** : **Model이 호출될 때마다** 실행 (Tool 결과를 받은 후 재호출 시에도)

**`@before_agent` + `can_jump_to` 예시** — 암구호 감지 후 응답 차단:

```python
from langchain.agents.middleware import before_agent
from langchain.messages import AIMessage

@before_agent(can_jump_to=["end"])
def validate_input(state: AgentState, runtime):
    last_message = state["messages"][-1]
    if "암구호" in last_message.content:
        print("암구호 감지됨 - 응답 차단")
        return {
            "messages": [AIMessage(content="이 요청은 처리할 수 없습니다.")],
            "jump_to": "end"  # 모델 호출 없이 바로 에이전트 종료
        }
    print("✅ 정상 입력, 모델 호출 계속 진행")
    return None
```

<img src='../images/03.advanced-agent/19.png'>

> 📌 `return None`은 "점프하지 않고 평소대로 다음 단계를 진행하라"는 신호입니다. 반면 `jump_to: "end"` 를 반환하면 모델 호출 없이 Agent가 종료됩니다. → **AI Model에게 민감 정보가 유출되는 것을 사전에 방지**할 수 있습니다.

### 1.7 Custom Middleware — Wrap-style 심화

<img src='../images/03.advanced-agent/20.png'>

**Wrap-style 예시** — 메시지 길이에 따른 동적 모델 선택:

```python
from langchain_openai import ChatOpenAI

@wrap_model_call
def dynamic_model_selector(request, handler):
    # 최근 사용자 입력 메시지 추출
    last_msg = request.messages[-1].content if request.messages else ""
    msg_len = len(last_msg)

    # 길이에 따라 모델 선택
    if msg_len < 10:
        model_name = "gpt-5-nano"
    elif msg_len < 30:
        model_name = "gpt-5-mini"
    else:
        model_name = "gpt-5"

    print(f"메시지 길이: {msg_len}, 선택된 모델: {model_name}")

    # request.model을 새로운 모델로 교체
    new_model = ChatOpenAI(model_name=model_name)
    new_request = request.override(model=new_model)

    # 수정된 요청으로 LLM 호출
    return handler(new_request)
```

### 2.1 Built-in Guardrails

<img src='../images/03.advanced-agent/22.png'>

LangChain이 지원하는 내장 가드레일 목록입니다.

| 가드레일                            | 설명                                         |
| :---------------------------------- | :------------------------------------------- |
| **개인정보(PII) 유출 방지**         | 이메일, 카드번호, IP 등 개인정보 탐지·마스킹 |
| **Human-in-the-loop**               | 위험 작업 전 사용자 승인 요청                |
| **Prompt Injection 방지**           | 악의적인 프롬프트 조작 탐지                  |
| **유해 컨텐츠 생성 방지**           | 폭력, 성인물 등 유해 내용 생성 차단          |
| **법률 및 규정에 입각한 답변 생성** | 특정 도메인 규정 준수                        |
| **답변 품질 체크**                  | 할루시네이션, 부적절한 답변 검증             |

<img src='../images/03.advanced-agent/25.png'>

#### 구현 방식 — 결정론적 vs 모델 기반

| 방식                        | 설명                      | 장점                      | 단점                       | 대표 예시         |
| :-------------------------- | :------------------------ | :------------------------ | :------------------------- | :---------------- |
| **결정론적(Deterministic)** | 정규식, 키워드 매칭 활용  | 비용 저렴, 빠름           | 미묘한 부분을 놓칠 수 있음 | PII 커스텀 탐지기 |
| **모델 기반**               | LLM 모델의 평가 기반 탐지 | 미세한 문제까지 포착 가능 | 비용 및 시간 소요          | Human-in-the-loop |

### 2.2 Custom Guardrails

<img src='../images/03.advanced-agent/26.png'>

커스텀 가드레일은 Middleware를 이용해 Agent 흐름의 앞·뒤에 검증 로직을 직접 추가합니다.

| 방식                            | 설명                                                     |
| :------------------------------ | :------------------------------------------------------- |
| **Before Agent Guardrails**     | 사용자 입력이 LLM에 도달하기 **전** 필터링               |

#### 2.2.1 Before Agent Guardrails — 입력 필터

<img src='../images/03.advanced-agent/27.png'>

차단할 키워드를 사전에 정의합니다.

```python
# 차단 및 제재 키워드 정의
forbidden_topics = {
    "cheating": ["답지", "정답 알려줘", "숙제 대신", "써줘", "베끼기"],  # 부정행위 관련
    "distraction": ["롤", "게임", "유튜브", "아이돌", "웹툰"],           # 학습 방해 요소
    "harmful": ["담배", "술", "폭력", "싸움", "바보"],                   # 유해 콘텐츠
}
```

<img src='../images/03.advanced-agent/28.png'>

```python
from langchain.agents.middleware import before_agent
from langchain.messages import AIMessage

@before_agent(can_jump_to=["end"])
def education_guardrail(state, runtime):
    # 1. 메시지 유효성 검사
    if not state["messages"]:
        return None
    last_message = state["messages"][-1]
    if last_message.type != "human":
        return None

    user_text = last_message.content

    # 2. 카테고리별 검사 로직
    # Case A: 부정행위 방지 (Cheating Prevention)
    for keyword in forbidden_topics["cheating"]:
        if keyword in user_text:
            return {
                "messages": [AIMessage(
                    role="assistant",
                    content="🚫 스스로 고민해봐야 실력이 늘어요!..."
                )],
                "jump_to": "end"  # 차단 키워드 감지 시 바로 return
            }
```

> 💡 `can_jump_to=["end"]`는 이 미들웨어가 `"end"` 노드로 바로 점프할 수 있는 권한을 가진다는 선언입니다. 반환값에 `"jump_to": "end"`를 포함하면 LLM 호출 없이 Agent가 바로 종료됩니다.

#### 2.2.2 After Agent Guardrails — 출력 필터

<img src='../images/03.advanced-agent/29.png'>

**After Agent Guardrails** 는 AI Model이 생성한 답변을 **사용자에게 보여주기 전에** 검증합니다.  
주로 **LLM 모델 기반** 검증을 활용해 미묘한 문제까지 포착합니다.

```python
# 평가용 감시자(Safety) 모델 정의
safety_model = init_chat_model("gpt-5-nano")
```

<img src='../images/03.advanced-agent/30.png'>

```python
from langchain.agents.middleware import after_agent
from langchain.messages import AIMessage

@after_agent
def answer_leakage_guardrail(state, runtime):
    """AI가 답변을 생성한 직후, 사용자에게 보여주기 전에 내용을 검사."""
    # 1. 메시지 유효성 검사
    if not state["messages"]:
        return None
    last_message = state["messages"][-1]
    if not isinstance(last_message, AIMessage):
        return None
```

#### 2.2.3 After Agent 응용 — 검증 + 교정(Correction/Regeneration)

<img src='../images/03.advanced-agent/33.png'>

`"LEAKED"` 감지 시 단순히 차단하는 것에서 나아가, **교정 모델에 "힌트로 바꿔라"고 지시해 새 답변을 재생성** 할 수도 있습니다.

```python
if "LEAKED" in result.content:
    # 원본 질문을 가져오기 (문맥 파악용)
    original_question = state["messages"][0].content

    # 교정 프롬프트
    correction_prompt = f"""
    절대 정답을 말하지 말고, 학생이 스스로 생각할 수 있도록 유도하는 질문이나 핵심 개념(힌트)만 설명해 주세요.
    사용자 질문: {original_question}
    """
    corrected_response = safety_model.invoke([
        SystemMessage(content="당신은 소크라테스식 교육을 사용하는 튜터입니다."),
        HumanMessage(content=correction_prompt)
    ])
    last_message.content = corrected_response.content
```

#### 2.2.4 Before vs After Guardrails 비교

<img src='../images/03.advanced-agent/34.png'>

| 특징          | Before Agent Guardrail (입력 필터)            | After Agent Guardrail (출력 필터)                     |
| :------------ | :-------------------------------------------- | :---------------------------------------------------- |
| **작동 시점** | 사용자의 질문이 LLM에 도달하기 직전           | LLM이 답변을 생성한 직후 (사용자에게 보이기 전)       |
| **주 목적**   | 비용 절감, 보안(PII), 정책 위반 차단          | 품질 관리, 환각(Hallucination) 방지, 답변 안전성 검증 |
| **방식**      | 주로 규칙 기반 (Keywords, Regex), 가벼운 로직 | 주로 모델 기반 (LLM에게 평가 요청), 검증 로직         |
| **비용**      | 매우 저렴함 (LLM 호출 자체를 막음)            | 추가 비용 발생 (메인 LLM + 감시자 LLM 비용)           |
| **속도**      | 매우 빠름                                     | 감시자 모델이 검사하는 시간만큼 느려짐                |

#### 2.2.5 Combine Multiple Guardrails — 다중 레이어 방어

<img src='../images/03.advanced-agent/35.png'>

여러 미들웨어를 `middleware=[...]` 리스트에 나열하면 **레이어 방어막** 구조를 만들 수 있습니다.

```python
agent = create_agent(
    model="gpt-5-nano",
    tools=[],
    middleware=[
        education_guardrail,              # Layer 1: 입력 필터 (규칙 - 판짓/부정행위)
        student_safety_middleware,        # Layer 2: 개인정보 보호 (전화번호 마스킹)
        counseling_escalation_middleware, # Layer 3: 상담 이관 (휴먼 에스컬레이션)
        answer_leakage_guardrail,         # Layer 4: 출력 필터 (모델 기반 교정)
    ],
)
```

미들웨어는 **리스트 순서대로** 실행됩니다. 각 레이어가 통과된 요청만 다음 단계로 진행합니다.

## 3장. Memory

### 3.1 Long-term Memory

<img src='../images/03.advanced-agent/39.png'>

**Long-term Memory** 는 대화방(thread_id)이 바뀌어도 유지되는, 스레드 및 세션을 **넘나드는** 저장소입니다.

- **Short-term (Checkpointer)**: 한 대화 스레드(thread_id) 내에서만 유지
- **Long-term (Store)**: 여러 대화방에서 공통으로 공유 (`user_id` 또는 `namespace` 기반)

예시: _"A라는 유저는 짧은 응답을 선호한다"_, _"이전에 Jay라고 이름을 말했다"_

#### Store 구성

| 구성 요소     | 설명                                                   |
| :------------ | :----------------------------------------------------- |
| **namespace** | 폴더와 유사한 개념 (튜플로 생성 — 충돌 방지)           |
| **key**       | 파일 이름과 유사한 개념 (각 메모리 항목의 고유 식별자) |

### 3.3 Store → Model에 메모리 주입

<img src='../images/03.advanced-agent/45.png'>

Store에 저장된 메모리를 **Model이 참고해 답변을 생성**하게 하려면 두 단계가 필요합니다.

1. **namespace 정보를 담을 Context 정의** — `user_id`, `app_name` 등
2. **Store 정보를 주입할 Middleware 정의** — `@wrap_model_call`을 사용해 system_prompt에 메모리 내용 삽입

<img src='../images/03.advanced-agent/46.png'>

```python
from dataclasses import dataclass

@dataclass
class Context:
    user_id: str
    app_name: str
```

<img src='../images/03.advanced-agent/47.png'>

```python
from langchain.agents.middleware import wrap_model_call

@wrap_model_call
def inject_memory(request, handler):
    # ① Context에서 user_id, app_name 추출
    current_user = request.runtime.context.user_id
    current_app = request.runtime.context.app_name

    # ② Store에서 해당 namespace의 메모리 검색
    memories = request.runtime.store.search((current_user, current_app))

    memory_content = "기록된 정보 없음"
    if memories:
        # 검색된 메모리들을 텍스트로 변환
        extracted_facts = []
        for item in memories:
            if "facts" in item.value:
                extracted_facts.extend(item.value["facts"])
        memory_content = "\n- ".join(extracted_facts)

    # ③ System Message에 메모리 삽입
    system_message = f"사용자 관련 장기 메모리 : {memory_content}"
    request = request.override(system_prompt=system_message)
    return handler(request)
```

```python
from langchain.agents import create_agent

agent = create_agent(
    model="gpt-5-nano",
    store=store,            # store 연결
    context_schema=Context,
    middleware=[inject_memory],
)
```

### 3.5 Tool 기반 메모리 관리

<img src='../images/03.advanced-agent/51.png'>

LLM이 대화 중 중요한 정보를 **스스로 판단하여 Store에 저장하고 조회**합니다.

#### ① UserInfo 구조 정의

```python
from typing import TypedDict

class UserInfo(TypedDict):
    personal_information: str  # 이름, 나이, 직업 등 개인 정보
    preference: str            # 선호도, 취향 등
```

#### ② Context와 Store 정의

<img src='../images/03.advanced-agent/52.png'>

```python
from dataclasses import dataclass
from langgraph.store.memory import InMemoryStore

@dataclass
class Context:
    user_id: str
    app_name: str

store = InMemoryStore()
```

#### ③ 사용자 정보 조회 Tool

<img src='../images/03.advanced-agent/53.png'>

```python
from langchain_core.runnables import RunnableConfig
from langchain.tools import tool, ToolRuntime

@tool
def get_user_info(runtime: ToolRuntime) -> str:
    """현재 사용자의 정보를 조회 (시스템 내부용 도구)."""
    user_id = runtime.context.user_id
    app = runtime.context.app_name

    # 해당 네임스페이스의 모든 메모리 검색
    memories = runtime.store.search((user_id, app))

    if not memories:
        return "기록된 정보 없음"

    results = []
    for item in memories:
        data = item.value
        if "personal_information" in data:
            results.append(f"- 개인정보: {data['personal_information']}")
        if "preference" in data:
            results.append(f"- 선호도: {data['preference']}")

    return "\n".join(results) if results else "데이터 형식 불일치로 읽을 수 없음"
```

#### ④ 사용자 정보 저장 Tool

<img src='../images/03.advanced-agent/54.png'>

```python
import uuid

@tool
def save_user_info(user_info: UserInfo, runtime: ToolRuntime) -> str:
    """사용자의 정보를 저장하거나 업데이트."""
    user_id = runtime.context.user_id
    app = runtime.context.app_name
    store = runtime.store

    # Store의 key를 매번 다르게 지정하기 위한 uuid 활용
    memory_key = str(uuid.uuid4())
    store.put((user_id, app), memory_key, user_info)

    return f"정보가 안전하게 저장되었습니다. (ID: {memory_key})"
```

#### ⑤ Agent 생성

<img src='../images/03.advanced-agent/55.png'>

```python
from langchain.agents import create_agent

agent = create_agent(
    model="gpt-5-nano",
    tools=[get_user_info, save_user_info],
    store=store,            # 에이전트에 store 연결
    context_schema=Context,
)
```

> 💡 **Middleware 방식 vs Tool 방식 비교**
>
> | 방식                         | 특징                                                             | 적합한 상황                                  |
> | :--------------------------- | :--------------------------------------------------------------- | :------------------------------------------- |
> | **Middleware inject_memory** | 매 LLM 호출 시 자동으로 메모리를 시스템 프롬프트에 삽입          | 정보가 많지 않고 항상 참고해야 할 때         |
> | **Tool 기반**                | LLM이 스스로 필요할 때만 `get_user_info`/`save_user_info`를 호출 | 정보가 많고 선택적으로 조회할 때 (토큰 절약) |

## 📚 3장 정리

- **Runtime** 은 Agent 실행 중 공유되는 환경 정보(Context, Store, Stream writer)이고, **State** 는 Agent가 실행하며 만든 결과물(Messages, tool_results)이다.
- **dataclass** 를 사용해 Context를 정의하고, `context_schema=Context` 로 Agent에 주입한다.
- **Node-style Hook** (`@before_agent`, `@before_model` 등)은 특정 시점에 순차 실행하고, **Wrap-style Hook** (`@wrap_model_call`)은 LLM 호출 자체를 감싸 동적으로 제어한다.
- **Guardrails** 는 Before Agent(입력 필터)와 After Agent(출력 필터)로 나뉜다. 여러 미들웨어를 리스트로 쌓아 다중 레이어 방어막을 구성할 수 있다.
- **Long-term Memory** 는 `InMemoryStore` + `namespace`/`key` 구조로 저장하고, `inject_memory` 미들웨어로 System Prompt에 주입한다.
- **Tool 기반 메모리 관리** 를 통해 AI가 스스로 정보를 판단하고 저장/조회하게 만들 수 있다.
