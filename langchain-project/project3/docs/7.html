7

Langfuse datasets · scores

플랫폼화 ⏱ 2~3시간
🎯 목표

지금까지의 결과는 내 컴퓨터의 runs/에만 있습니다. 이 STEP에서 골든셋을 Langfuse 데이터셋으로 올리고, --langfuse 플래그로 실행을 run, 케이스를 trace, 지표를 score로 남깁니다. 끝나면 대시보드에서 실행별 점수 추이를 보고, 점수가 낮은 케이스에서 P2가 실제로 무슨 도구를 불렀는지까지 클릭으로 따라갈 수 있습니다.

🧠 개념 — 딱 하나만

우리 단어 넷이 Langfuse 단어 넷에 하나씩 대응된다

P3에서Langfuse에서연결 열쇠
시험지 rag_v1.jsonDataset rag_v1이름이 같다
케이스 rag-05Dataset itemid를 item id로 그대로 쓴다
실행 runs/rag_v1__rerank__…Dataset runrun_id를 run 이름으로
케이스 하나 실행Trace케이스마다 상자 하나. item과 run에 묶인다
지표 하나 (source_hit …)Scoretrace에 이름·값으로 붙는다

대응이 1:1이라 새로 배울 개념이 없습니다. STEP 1에서 id를 잠근 덕에 케이스와 item은 찾을 필요 없이 바로 연결되고, STEP 3에서 실행마다 run_id를 만든 덕에 run 이름도 이미 있어요.

Dataset · rag_v1 (15 items) ├── Run · rag_v1__rerank__20260826-143012 │ ├── item rag-01 ── trace eval-case ── scores: ok 1 · source_hit 1 · faithfulness 0.92 · judge_score 5 │ ├── item rag-02 ── trace eval-case ── scores: … │ └── … └── Run · rag_v1__baseline__20260826-151540 ├── item rag-01 ── trace eval-case ── scores: ok 1 · source_hit 0 · faithfulness 0.88 · judge_score 4 └── … → 대시보드의 Runs 탭에서 두 run을 나란히 놓으면 STEP 6의 판정표를 케이스 단위로 본다
🗄 비유 — 내 노트를 팀 게시판에 옮겨 붙인다

runs/는 내 실험 노트라 나만 봅니다. Langfuse는 팀 게시판이에요 — 같은 시험지를 같은 칸에 붙여 두면 누구든 "지난주 대비 어디가 떨어졌나"를 볼 수 있고, 점수 옆의 trace를 누르면 그 케이스의 답변과 근거, 같은 프로젝트의 P2 기록까지 이어집니다.

①

sync_dataset.py — 시험지 올리기

— 같은 id로 다시 올리면 덮어쓴다
sync_dataset.py
import sys

from dotenv import load_dotenv
from langfuse import get_client

from schemas import load_dataset

load_dotenv()
langfuse = get_client()

name = sys.argv[1] if len(sys.argv) > 1 else "rag_v1"
ds = load_dataset(name)

langfuse.create_dataset(
    name=ds.name, description=ds.description,
    metadata={"version": ds.version, "target": ds.target},
)
for c in ds.cases:
    langfuse.create_dataset_item(
        dataset_name=ds.name,
        id=c.id,                                                   # ← 러너가 trace를 연결할 때 이 id를 쓴다
        input={"question": c.question},
        expected_output=c.ground_truth if ds.target == "rag" else c.rubric,
        metadata=c.model_dump(exclude={"id", "question"}),          # expect_tool·tags 같은 나머지 칸
    )
langfuse.flush()
print(f"☁️  {ds.name} ({ds.version}) · {len(ds.cases)}개 케이스 업로드 완료")

시험지의 원본은 여전히 datasets/*.json(git)입니다. Langfuse는 그 사본이에요. 케이스를 고치면 버전을 올리고 이 스크립트를 다시 돌립니다 — id가 같으면 덮어쓰니 중복이 생기지 않습니다.

②

tracing.py — 함수 넷

— 상자 열기 · 점수 붙이기 · run에 묶기 · 나중에 온 점수 붙이기
tracing.py
import math
from contextlib import contextmanager

from dotenv import load_dotenv
from langfuse import get_client

load_dotenv()
langfuse = get_client()                       # .env의 LANGFUSE_* 를 알아서 읽는다


@contextmanager
def case_span(run_id: str, case, params: dict):
    """케이스 하나를 트레이스(상자)로 감싼다. 이 안에서 일어난 HTTP 호출·채점이 전부 자식으로 들어간다."""
    with langfuse.start_as_current_observation(
        name="eval-case", as_type="evaluator", input=case.question,
        metadata={"run_id": run_id, "case_id": case.id, **params},
    ) as span:
        yield span


def record(span, output: str, scores: dict) -> None:
    """답변과 점수를 트레이스에 붙인다. 점수는 트레이스 단위(score_trace)로 — 대시보드가 그 단위로 모아 보여 준다."""
    span.update(output=output)
    for name, value in scores.items():
        if value is None or (isinstance(value, float) and math.isnan(value)):
            continue                          # '해당 없음'은 점수가 아니다
        span.score_trace(name=name, value=float(value))


def link(span, run_id: str, case_id: str, params: dict) -> None:
    """이 트레이스를 데이터셋의 해당 케이스(item)와 이번 실행(run)에 묶는다.
    케이스 id를 dataset item id로 그대로 썼기 때문에(sync_dataset.py) 찾을 필요 없이 바로 연결된다."""
    langfuse.api.dataset_run_items.create(
        run_name=run_id, dataset_item_id=case_id, trace_id=span.trace_id, metadata=params,
    )


def add_scores(trace_id: str, scores: dict) -> None:
    """트레이스가 닫힌 뒤에 나온 점수(RAGAS는 모아서 채점한다)를 trace_id로 나중에 붙인다."""
    for name, value in scores.items():
        if value is None or (isinstance(value, float) and math.isnan(value)):
            continue
        langfuse.create_score(trace_id=trace_id, name=name, value=float(value))


def flush() -> None:
    """스크립트가 끝나기 전에 모아 둔 기록을 전부 보낸다. 없으면 마지막 몇 건이 사라진다."""
    langfuse.flush()

add_scores가 따로 있는 이유는 STEP 4의 설계 때문입니다. RAGAS는 케이스를 모아 한 번에 채점하니, 그 점수가 나올 때쯤엔 케이스 상자가 이미 닫혀 있어요. 그래서 상자의 trace_id를 기억해 뒀다가 나중에 붙입니다.

전체 코드 한 번에 보기 — runner.py (STEP 7까지 완성본) 
# ═══════════════════════════════════════════════════════════════════
# STEP 3 · 러너: 골든셋 × 시험 대상 → 케이스별 점수표 + 요약. 명령 한 번이 실행 하나(run)다.
# STEP 4 · --ragas   : RAG 지표 4개를 표에 붙인다
# STEP 5 · --judge   : LLM 채점 점수를 표에 붙인다
# STEP 7 · --langfuse: 케이스마다 트레이스를 남기고 점수를 붙여 Langfuse 데이터셋 run에 연결한다
#
# 실행:  uv run python runner.py --target rag   --dataset rag_v1   --label rerank --param mode=rerank
#        uv run python runner.py --target agent --dataset agent_v1 --label prompt-A
# 결과:  runs/<dataset>__<label>__<시각>/results.csv, summary.json
# ═══════════════════════════════════════════════════════════════════
import argparse
import json
import math
import time
from contextlib import nullcontext
from pathlib import Path

import pandas as pd

from metrics import ragas_scores, score_case                          # ← ragas_scores 추가(STEP 4)
from schemas import load_dataset
from targets import call_target, health
from judge import judge_answer, rubric_for                            # ← 추가(STEP 5)
import tracing                                                        # ← 추가(STEP 7)


def parse_params(pairs: list[str]) -> dict:
    """['mode=rerank', 'k=4'] → {'mode': 'rerank', 'k': '4'}"""
    return dict(p.split("=", 1) for p in pairs)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--target", required=True, choices=["rag", "agent"])
    ap.add_argument("--dataset", required=True)                       # datasets/<name>.json
    ap.add_argument("--label", required=True)                         # 이 실행의 이름표. "rerank", "prompt-B"
    ap.add_argument("--param", nargs="*", default=[])                 # 시험 대상에 넘길 손잡이. mode=baseline
    ap.add_argument("--limit", type=int)                              # 처음엔 3개로 하네스가 도는지부터
    ap.add_argument("--ragas", action="store_true")                   # ← 추가(STEP 4)
    ap.add_argument("--judge", action="store_true")                   # ← 추가(STEP 5)
    ap.add_argument("--langfuse", action="store_true")                # ← 추가(STEP 7)
    args = ap.parse_args()
    params = parse_params(args.param)

    ds = load_dataset(args.dataset)
    assert ds.target == args.target, f"{ds.name}은 {ds.target}용 데이터셋입니다"
    if not health()[args.target]:
        raise SystemExit(f"❌ {args.target} 서비스가 응답하지 않습니다. 서버를 먼저 띄우세요.")

    cases = ds.cases[: args.limit] if args.limit else ds.cases
    run_id = f"{ds.name}__{args.label}__{time.strftime('%Y%m%d-%H%M%S')}"
    out_dir = Path("runs") / run_id
    out_dir.mkdir(parents=True)
    print(f"▶ {run_id} · {len(cases)}개 · params={params}")

    rows, outputs = [], {}                                            # outputs: id → RunResult (RAGAS가 contexts를 쓴다)
    for i, case in enumerate(cases, 1):
        # --langfuse가 켜져 있을 때만 케이스를 트레이스(상자)로 감싼다. 꺼져 있으면 nullcontext = 아무것도 안 함
        span_cm = tracing.case_span(run_id, case, params) if args.langfuse else nullcontext()   # ← 추가(STEP 7)
        with span_cm as span:
            result = call_target(ds.target, case, params, run_id)
            scores = score_case(ds.target, case, result)
            row = {"id": case.id, "question": case.question, "answer": result.answer,
                   "sources": " / ".join(result.sources), "used_tools": ",".join(result.used_tools),
                   "error": result.error, **scores}

            # STEP 5 · 내용 채점. 차단이 기대된 케이스는 '내용'이 없으니 건너뛴다. 서비스 에러도 마찬가지.
            if args.judge and result.error is None and not getattr(case, "expect_blocked", False):   # ← 추가(STEP 5)
                v = judge_answer(case.question, rubric_for(ds.target, case), result.answer, result.sources)
                row["judge_score"], row["judge_reason"] = v.score, v.reason
                scores["judge_score"] = v.score

            if span:                                                                               # ← 추가(STEP 7)
                tracing.record(span, result.answer, scores)          # 점수를 트레이스에 붙이고
                tracing.link(span, run_id, case.id, params)          # 데이터셋 run에 연결한다
                row["trace_id"] = span.trace_id

        rows.append(row)
        outputs[case.id] = result
        mark = "✅" if scores["ok"] else "❌"
        print(f"  {mark} {i:2d}/{len(cases)} {case.id:10s} {result.latency_ms:6d}ms  {row.get('judge_score', '')}")

    df = pd.DataFrame(rows).set_index("id")

    # STEP 4 · RAGAS는 모아서 한 번에. 응답이 없던 케이스는 채점할 게 없으니 뺀다.
    if args.ragas and ds.target == "rag":                                                          # ← 추가(STEP 4)
        ragas_rows = [{"id": c.id, "question": c.question, "answer": outputs[c.id].answer,
                       "contexts": outputs[c.id].contexts, "ground_truth": c.ground_truth}
                      for c in cases if outputs[c.id].error is None]
        rdf = ragas_scores(ragas_rows)
        df = df.join(rdf)
        if args.langfuse:                                                                          # ← 추가(STEP 7)
            for cid, r in rdf.iterrows():
                tracing.add_scores(df.loc[cid, "trace_id"], r.to_dict())

    df.to_csv(out_dir / "results.csv", encoding="utf-8-sig")

    # 요약 = 숫자 열의 평균. True/False를 1/0으로 넣어 뒀으니 평균이 곧 비율이다.
    metrics = df.select_dtypes("number").mean().round(3).to_dict()
    summary = {"run_id": run_id, "dataset": ds.name, "version": ds.version, "target": ds.target,
               "label": args.label, "params": params, "n": len(df),
               "metrics": {k: (None if math.isnan(v) else v) for k, v in metrics.items()}}
    (out_dir / "summary.json").write_text(json.dumps(summary, ensure_ascii=False, indent=2), encoding="utf-8")

    if args.langfuse:
        tracing.flush()                                                                            # ← 추가(STEP 7)

    print("\n" + "=" * 52)
    print(pd.Series(summary["metrics"]).to_string())
    print("=" * 52)
    print(f"📁 {out_dir}")


if __name__ == "__main__":
    main()

🎓 한 줄 정리

시험지 = dataset, 케이스 = item, 실행 = run, 지표 = score. 열쇠는 STEP 1에서 잠근 id와 STEP 3의 run_id다. 로컬 결과는 항상 남고, Langfuse는 그 위에 얹는 층이다.

더 알아보기 — P2의 트레이스와 P3의 트레이스 / 왜 score_trace인가 / 비용·지연도 점수로

P2의 트레이스와 P3의 트레이스는 별개입니다

P3의 eval-case 상자 안에는 P2로 보낸 HTTP 호출만 있고, P2가 안에서 부른 도구·토큰은 P2 자신의 트레이스(P2 STEP 6의 agent-chat)에 있습니다. 프로세스가 다르니 당연한 일이에요. 둘을 잇는 실마리는 세션 id입니다 — P3가 eval-<run_id>-<case_id>로 보냈으니 P2 트레이스를 그 세션으로 검색하면 나옵니다. 완전히 한 트리로 묶고 싶다면 요청 헤더로 trace id를 전파하는 방법(W3C traceparent)이 있는데, 다음 단계의 과제로 남겨 둡니다.

왜 span.score()가 아니라 score_trace()인가

점수를 자식 observation에 붙이면 대시보드의 run 화면에서 모이지 않습니다. run 비교 화면은 trace 단위 점수를 열로 보여 주기 때문에, 케이스의 점수는 트레이스에 붙여야 STEP 6의 판정표가 그대로 대시보드에 나타납니다.

비용과 지연도 점수입니다

latency_ms는 이미 score로 올라갑니다. 비용은 P2의 트레이스에 있으니(P2 STEP 6), 원한다면 P2의 /chat 응답에 cost 칸을 열고 RunResult에 받아 지표로 세면 "프롬프트 B가 정확도 +5%p, 비용 +30%"처럼 품질과 비용을 한 표에 놓을 수 있습니다. 토스 공고의 "비용·지연 지표화"가 정확히 이것입니다.
