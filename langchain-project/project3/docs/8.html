8

자동 리포트 + 품질 게이트

플랫폼화 ⏱ 2~3시간
🎯 목표

실행마다 사람이 읽을 한 장(마크다운 리포트)과 기계가 판정할 한 줄(pytest)을 만듭니다. 믿을 만한 실행을 baselines/로 승격해 두면, 이후 어떤 실행이든 uv run pytest 한 번으로 "baseline보다 나빠졌나"가 통과/실패로 나옵니다. 마지막에 (선택) CI에 붙이는 모양을 봅니다.

🧠 개념 — 딱 하나만

baseline은 "지금까지 믿고 쓰는 실행"이고, 승격은 폴더를 복사하는 것이다

STEP 6에서는 비교할 두 실행을 매번 손으로 골랐습니다. 게이트가 되려면 한쪽은 고정돼 있어야 해요 — 그게 baseline입니다. 복잡한 등록 절차 대신, 실행 폴더를 baselines/<시험지>/로 복사하면 승격입니다. 되돌리는 것도 복사예요. compare.py는 폴더 둘만 있으면 되니 코드가 한 줄도 안 늘어납니다.

📁 baselines/rag_v1/승격된 실행
(cp -r 한 것)
📁 runs/…최신…이번 실행
→
⚖️ compare()STEP 6 그대로
→
📄 reports/…md표 + 회귀 케이스
+ 최저 3건
✅ pytest회귀 있으면 실패
없으면 통과
🚧 비유 — 검문소는 기준표를 벽에 붙여 두고 매번 그것과 비교한다

검문소 직원은 통과 기준을 매번 새로 정하지 않습니다. 벽에 붙은 기준표(baseline)와 비교하고, 기준표는 상관이 승인할 때만 바꿉니다(승격). 리포트는 그 검문 기록이고, pytest는 차단기예요.

🛠 할 일 — 네 조각
①

report.py — 마크다운 한 장

— compare.py의 함수를 그대로 쓴다
report.py
import sys
from pathlib import Path

from compare import case_diffs, compare, load_run


def build(base: dict, base_df, cand: dict, cand_df) -> str:
    table = compare(base, cand)
    regressed = table[table["verdict"] == "회귀"].index.tolist()

    lines = [
        f"# 평가 리포트 · {cand['run_id']}",
        "",
        f"- 시험지: `{cand['dataset']}` ({cand['version']}) · 케이스 {cand['n']}개 · 대상 `{cand['target']}`",
        f"- baseline: `{base['label']}` {base['params']}",
        f"- candidate: `{cand['label']}` {cand['params']}",
        f"- 판정: **{'🚨 회귀 ' + ', '.join(regressed) if regressed else '✅ 회귀 없음'}**",
        "",
        "## 지표",
        "",
        table.reset_index().to_markdown(index=False),                  # tabulate가 있어야 한다 (STEP 0)
        "",
    ]
    for m in regressed:
        lines += [f"## 🚨 {m} — 달라진 케이스", "", case_diffs(base_df, cand_df, m).to_markdown(), ""]

    if "judge_score" in cand_df:
        worst = cand_df.nsmallest(3, "judge_score")[["question", "judge_score", "judge_reason"]]
        lines += ["## candidate에서 가장 낮은 점수 3건", "", worst.to_markdown(), ""]
    return "\n".join(lines)


if __name__ == "__main__":
    base, base_df = load_run(sys.argv[1])
    cand, cand_df = load_run(sys.argv[2])
    out = Path("reports") / f"{cand['run_id']}.md"
    out.parent.mkdir(exist_ok=True)
    out.write_text(build(base, base_df, cand, cand_df), encoding="utf-8")
    print(f"📄 {out}")

리포트에 새 계산은 없습니다. compare()와 case_diffs()를 부르고 마크다운으로 찍을 뿐이에요. "가장 낮은 점수 3건"은 리포트를 여는 사람이 표 다음에 바로 읽을 구체적인 답변입니다 — 숫자만 있는 리포트는 아무도 안 읽어요.

②

baseline 승격 — 명령 한 줄

— 코드가 아니라 폴더 복사
# STEP 7에서 만든 rerank 실행과 prompt-A 실행을 baseline으로 승격
cp -r runs/rag_v1__rerank__<시각>     baselines/rag_v1
cp -r runs/agent_v1__prompt-A__<시각>  baselines/agent_v1

# 이제 어떤 실행이든 baseline과 바로 비교할 수 있다
uv run python compare.py baselines/rag_v1 runs/rag_v1__baseline__<시각>
uv run python report.py  baselines/rag_v1 runs/rag_v1__baseline__<시각>

baselines/는 git에 올립니다. 그래야 팀원이 같은 기준표를 보고, 승격 이력이 커밋 로그에 남아요. runs/는 실행마다 쌓이니 .gitignore에 넣어도 되지만, 비교에 쓴 실행 몇 개는 남겨 두면 README의 표에 근거가 됩니다.

③

tests/test_quality_gate.py — 차단기

— 최신 실행 vs baseline, 회귀면 실패
tests/test_quality_gate.py
import os
from pathlib import Path

import pytest

from compare import compare, load_run

DATASETS = ["rag_v1", "agent_v1"]


def latest_run(dataset: str) -> Path | None:
    runs = list(Path("runs").glob(f"{dataset}__*"))
    # run_id는 <dataset>__<label>__<시각> — 맨 뒤 시각으로 골라야 '가장 최근'이다
    return max(runs, key=lambda p: p.name.rsplit("__", 1)[-1]) if runs else None


@pytest.mark.parametrize("dataset", DATASETS)
def test_no_regression(dataset):
    baseline_dir = Path("baselines") / dataset
    if not baseline_dir.exists():
        pytest.skip(f"{baseline_dir} 없음 — 먼저 baseline을 승격하세요")
    run_dir = Path(os.environ["EVAL_RUN"]) if os.getenv("EVAL_RUN") else latest_run(dataset)
    if run_dir is None:
        pytest.skip(f"{dataset} 실행 결과가 없습니다")

    base, _ = load_run(baseline_dir)
    cand, _ = load_run(run_dir)
    table = compare(base, cand)
    regressed = table[table["verdict"] == "회귀"]
    assert regressed.empty, f"\n{run_dir} 에서 회귀:\n{regressed.to_string()}"

테스트는 시험 대상을 부르지 않습니다. 이미 돌아간 실행 폴더를 읽어 판정만 해요. 그래서 1초 안에 끝나고 API 키도 필요 없습니다. "실행"과 "판정"을 나눠 두면 CI에서 비싼 실행은 하루 한 번, 판정은 커밋마다 돌릴 수 있습니다.

④

(선택) 한 줄로 묶기 — gate.sh, 그리고 CI

— 실행 → 리포트 → 판정
gate.sh
#!/usr/bin/env bash
# 실행 → 리포트 → 판정. 회귀가 있으면 pytest가 실패해 종료 코드 1로 끝난다.
set -e
uv run python runner.py --target rag   --dataset rag_v1   --label nightly --param mode=rerank --ragas --judge --langfuse
uv run python runner.py --target agent --dataset agent_v1 --label nightly --judge --langfuse
uv run python report.py baselines/rag_v1   "$(ls -d runs/rag_v1__nightly__*   | sort | tail -1)"
uv run python report.py baselines/agent_v1 "$(ls -d runs/agent_v1__nightly__* | sort | tail -1)"
uv run pytest -q
GitHub Actions 예시 — P1·P2가 같은 job 안에서 뜰 수 있을 때만

name: eval-gate

      P1_API_URL: http://localhost:8000
      P2_API_URL: http://localhost:8001
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
      - run: (cd project1 && uv sync && uv run uvicorn main:app --port 8000 &)   # 시험 대상 둘을 백그라운드로
      - run: (cd project2 && uv sync && uv run uvicorn main:app --port 8001 &)
      - run: sleep 60                                                       # 리랭커 모델 로딩 대기
      - run: cd project3 && uv sync && bash gate.sh
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: eval-reports, path: project3/reports/ }

P1은 PDF와 Chroma DB, 리랭커 모델이 필요해 CI 러너에서 뜨려면 저장소에 chroma_db/를 포함하거나 인제스천을 job 안에서 돌려야 합니다. 그래서 이 부분은 선택이에요. 로컬에서 gate.sh를 하루 한 번 돌리는 것만으로도 "회귀 게이트가 있다"는 서사는 완성됩니다.

✅ 검증
# 1) 리포트
uv run python report.py baselines/rag_v1 runs/rag_v1__baseline__<시각>
cat reports/rag_v1__baseline__<시각>.md

# 2) 게이트 — 최신 실행이 나쁜 것(baseline 구성)이면 실패해야 한다
uv run pytest -q
# FAILED tests/test_quality_gate.py::test_no_regression[rag_v1] - AssertionError: … 회귀: source_hit, context_recall

# 3) 좋은 실행을 지정하면 통과해야 한다
EVAL_RUN=runs/rag_v1__rerank__<시각> uv run pytest -q
# 1 passed, 1 skipped   (agent_v1은 최신 실행이 prompt-A와 같은 구성이면 통과, 없으면 skip)
  • 리포트가 생긴다 — reports/에 md 파일이 있고, 지표 표 · 회귀 케이스 · 최저 3건이 들어 있다
  • 게이트가 막는다 — 나쁜 실행이 최신일 때 pytest가 FAILED이고 메시지에 회귀 지표가 찍힌다
  • 게이트가 연다 — EVAL_RUN으로 좋은 실행을 지정하면 passed
  • 1초 안에 끝난다 — 테스트가 서버를 부르지 않는다. P1·P2를 꺼도 pytest는 돈다
🎓 한 줄 정리

실행(비싸다)과 판정(공짜다)을 나누고, baseline은 폴더 복사로 승격한다. 리포트는 사람을 위해, 종료 코드는 기계를 위해 남긴다.

더 알아보기 — smoke 세트 / 게이트를 언제 돌리나 / 실패했을 때 할 일

smoke 세트를 따로 두기

전체 시험지는 RAGAS·judge 포함 10분 안팎이라 커밋마다 돌리기엔 무겁습니다. 케이스 5개짜리 rag_smoke.json을 따로 두고(버전 관리는 똑같이), 커밋마다는 smoke, 하루 한 번은 전체 — 일반 테스트의 unit/integration 나누기와 같은 발상이에요.

게이트가 실패하면

리포트의 "달라진 케이스"를 열어 results.csv 두 개의 그 케이스를 나란히 읽습니다. 원인이 시험 대상의 변경이면 고치고, 흔들림(STEP 6의 더 알아보기)이면 같은 설정을 한 번 더 돌려 확인합니다. 두 번 연속 회귀면 진짜입니다. 임계값을 올려서 통과시키는 건 마지막 수단이고, 올린다면 이유를 커밋 메시지에 남기세요.

baseline을 언제 바꾸나

candidate가 "개선"으로 나오고 사람이 리포트를 읽고 동의했을 때만 승격합니다. 개선처럼 보여도 다른 지표가 회귀면 승격하지 않아요. 승격은 cp -r + 커밋이니, 커밋 메시지가 곧 승격 사유 기록입니다.
