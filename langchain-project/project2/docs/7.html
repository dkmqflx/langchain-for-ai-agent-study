7

Multi-LLM Provider 추상화

서비스화 층 Model Router 축소판 ⏱ 2시간
🎯 목표

지금 agent.py에는 "openai:gpt-5-mini"가 박혀 있습니다. 이걸 코드 밖으로 꺼냅니다. 평소 모델은 .env로 정하고, 특정 요청만 다른 모델로 돌리고 싶으면 요청에 provider 칸을 적습니다. 그리고 같은 질문을 OpenAI와 Gemini로 돌려 비용·속도·행동을 비교합니다.

🧠 개념 — 딱 하나만

Agent는 "모델 하나 주세요"라고만 한다

모델 이름이 코드 한복판에 있으면, 더 싼 모델이 나와도·OpenAI가 장애여도·다른 모델을 써 보고 싶어도 코드를 고치고 다시 배포해야 합니다. 그래서 사이에 얇은 창구 하나를 둡니다. Agent는 창구에 "모델 주세요"라고만 하고, 어떤 회사의 어떤 모델이 오는지는 창구가 정합니다.

🔌 비유 — 콘센트

가전마다 전선을 벽에 직접 납땜해 놨다면 청소기를 바꿀 때 벽을 뜯어야 합니다. 콘센트 규격을 하나 두면 가전은 플러그만 꽂으면 되죠. get_model("openai")가 그 콘센트입니다.

모델을 정하는 자리는 세 층입니다. 이번 STEP에서 ①②를 만들고 ③은 선택입니다.

①

providers.py — 콘센트 만들기

— 이름 하나 → 모델 객체
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()                                   # GOOGLE_API_KEY·OPENAI_API_KEY를 읽는다

PROVIDERS = {                                   # 이름 → "회사:모델". 모델을 늘리는 건 여기 한 줄
    "openai": "openai:gpt-5-mini",
    "gemini": "google_genai:gemini-2.5-flash",
}
DEFAULT_PROVIDER = os.getenv("LLM_PROVIDER", "openai")   # .env에 LLM_PROVIDER=gemini 라고 쓰면 갈아탄다

_models = {}                                    # 한 번 만든 모델은 보관해 두고 재사용

def get_model(name: str | None = None):
    name = name or DEFAULT_PROVIDER
    if name not in PROVIDERS:                   # 오타는 조용히 넘기지 않고 바로 알린다
        raise ValueError(f"unknown provider: {name} (가능: {list(PROVIDERS)})")
    if name not in _models:
        _models[name] = init_chat_model(PROVIDERS[name])   # "회사:모델" 문자열을 보고 알맞은 패키지를 고른다
    return _models[name]

P1에서 get_retriever(mode)로 검색기를 갈아끼운 것과 같은 모양입니다 — 문자열을 받아 객체를 돌려주고, 만든 건 보관합니다.

②

agent.py — 요청별로 바꿔치기

— 요청에 provider가 있으면 모델 호출 직전에 끼어들어 바꾼다
from dataclasses import dataclass
from langchain.agents.middleware import wrap_model_call
from providers import get_model


@dataclass
class Context:                      # 요청마다 달라지는 '설정'을 담는 상자. 대화 내용(state)과는 별개
    provider: str | None = None     # None이면 기본 모델


@wrap_model_call                    # 모델을 부르기 직전에 끼어드는 훅
def select_provider(request, handler):
    name = getattr(request.runtime.context, "provider", None)   # 상자에서 provider를 꺼내
    if name:
        request = request.override(model=get_model(name))       # 요청의 모델만 바꿔치기
    return handler(request)                                     # 바뀐 요청으로 실제 호출 진행


agent = create_agent(
    model=get_model(),              # ← "openai:gpt-5-mini" 대신 콘센트
    tools=[get_today, calculate, web_search, search_internal_docs],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=checkpointer,
    context_schema=Context,         # ← 이 Agent가 받을 상자의 모양
    middleware=[
        input_guardrail,
        select_provider,            # ← 추가
        PIIMiddleware("credit_card", strategy="mask", apply_to_input=True),
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        ToolCallLimitMiddleware(run_limit=8, exit_behavior="continue"),
    ],
    response_format=ChatReply,      # ← ProviderStrategy(ChatReply) 에서 클래스만 넘기는 것으로
)
요청{"message": …, "provider": "gemini"}
→
select_provider상자에 provider가 있네 → 모델을 get_model("gemini")로 교체
→
모델 호출Gemini가 답한다

Context는 "이 요청을 어떻게 처리할지"를 담는 상자입니다. 대화 내용처럼 저장되지 않고, 요청 한 번 도는 동안만 살아 있어요. @wrap_model_call은 모델 호출을 감싸는 훅이라, 들어가는 요청을 고친 뒤 handler로 넘기면 그대로 반영됩니다.

마지막 줄 response_format=ChatReply가 바뀐 이유: Gemini 2.5는 도구 호출과 JSON 스키마 모드를 동시에 못 씁니다. 클래스만 넘기면 랭체인이 모델을 보고 알맞은 방식을 고릅니다 — OpenAI는 STEP 4와 같은 JSON 스키마 모드, Gemini는 "형식 제출용 도구" 방식. Gemini 쪽은 도구를 계속 부르기 쉬운데, STEP 4에서 단 ToolCallLimitMiddleware가 8번에서 끊어 줍니다.

ask()와 main.py — provider 칸 하나씩 뚫기

— 요청 JSON → ask() → Context 상자로 전달
# agent.py — ask()
def ask(message: str, session_id: str = "default", provider: str | None = None) -> dict:
    with langfuse.start_as_current_observation(name="agent-chat", as_type="span"):
        langfuse.update_current_trace(session_id=session_id, input=message,
                                      metadata={"provider": provider or DEFAULT_PROVIDER})  # 비교할 때 쓴다
        result = agent.invoke(
            {"messages": [{"role": "user", "content": message}]},
            {"configurable": {"thread_id": session_id}, "callbacks": [langfuse_handler]},
            context=Context(provider=provider),       # ← 상자를 채워서 넘긴다
        )
        ...                                           # 나머지는 STEP 6 그대로


# main.py
class ChatIn(BaseModel):
    message: str
    session_id: str = "default"
    provider: str | None = None                       # ← 추가. 안 보내면 기본 모델

@app.post("/chat", response_model=ChatOut)
def chat(body: ChatIn):
    result = ask(body.message, session_id=body.session_id, provider=body.provider)   # ← 전달
    return {**result, "session_id": body.session_id}

🎓 한 줄 정리

모델 이름을 코드 밖(.env·요청)으로 꺼내면, 바꾸는 데 배포가 필요 없고 비교가 가능해진다. @wrap_model_call 훅이 바로 그 "바꿔치기"가 일어나는 자리다.

더 알아보기 — 대체 모델(선택) / 실무에서는 / 자주 보는 두 가지

③ 대체 모델 — 기본 모델이 죽었을 때

select_provider에 try/except를 더하면 됩니다. 랭체인 내장 ModelFallbackMiddleware를 써도 좋아요.

@wrap_model_call
def select_provider(request, handler):
    name = getattr(request.runtime.context, "provider", None)
    if name:
        request = request.override(model=get_model(name))
    try:
        return handler(request)
    except Exception as e:
        fallback = "gemini" if (name or DEFAULT_PROVIDER) != "gemini" else "openai"
        print(f"⚠️ {name or DEFAULT_PROVIDER} 실패({e}) → {fallback}로 대체")
        langfuse.update_current_trace(tags=["fallback", fallback])
        return handler(request.override(model=get_model(fallback)))

어떤 예외에서 넘길지는 골라야 합니다. 인증 오류로 넘기면 두 번째 모델도 똑같이 실패하고 비용·지연만 두 배가 됩니다.

실무라면 provider를 아무나 고르게 두지 않습니다

공개 API에서 클라이언트가 모델을 고르면 가장 비싼 모델만 쓰는 사람이 생깁니다. 실제로는 서버가 사용자 등급·실험 그룹·질문 난이도를 보고 정하고, select_provider가 바로 그 규칙이 들어갈 자리입니다. 여기에 라우팅 규칙·요금 기록·재시도를 얹으면 그게 Model Router예요.

Gemini 비용이 0으로 보인다면

Langfuse는 모델별 단가표로 비용을 계산합니다. 등록 안 된 모델은 토큰은 찍히는데 비용이 0이나 공란으로 나와요. 토큰 수로 비교하거나 단가를 등록하면 됩니다.

모델 이름은 자주 바뀝니다

gemini-2.5-flash 같은 이름은 몇 달이면 새 버전이 나오고 옛 이름이 사라집니다. model not found가 뜨면 제공사의 현재 모델 목록부터 확인하세요. 이름을 딕셔너리 한 곳에 모아 둔 이유입니다.
