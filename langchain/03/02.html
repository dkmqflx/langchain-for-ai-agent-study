02. Custom Middleware: Node-style (@before_model)

실습 노트북: 02.ipynb  ·  원문: docs/03.advanced-agent.md 1.6 Node-style 심화  ·  난이도: 🟡 중급  ·  선행: 01. Hooks & Middleware 가이드

이 자료는 실습 노트북(02.ipynb)을 열기 전에 먼저 읽는 강의 교재입니다. 이번 시간엔 Agent 실행 흐름 중간에 내 손으로 만든 검문소(Custom Middleware)를 하나 세워 봅니다. 구체적으로는 @before_model 데코레이터로 "모델을 부르기 직전"에 사용자 입력을 검사하고, 위험한 낱말이 보이면 LLM을 아예 호출하지 않고 즉시 대화를 끝내는 입력 가드레일을 만들어 봅니다.

이 노트북에서 배우는 것 Middleware(미들웨어)는 Agent가 일하는 파이프라인의 중간중간에 끼워 넣는 작은 부품입니다. 그중 Node-style Hook은 정해진 지점(모델 호출 전/후, Agent 시작/종료)에서 순서대로 딱딱 실행되는 방식이에요. 오늘은 그 대표격인 @before_model을 써서 "모델에게 말을 넘기기 전에 먼저 검사하기"를 구현합니다.

Node-style Hook이란

Agent가 답을 만들어내는 과정은 사실 여러 단계(node)가 줄지어 이어진 공정 라인입니다. 사용자의 말이 들어오면 → 모델이 호출되고 → (도구가 있으면) 도구가 실행되고 → 다시 모델이 불리고 … 이렇게 순서대로 흘러가죠. Node-style Hook은 이 라인의 특정 지점에 매다는 표지판 겸 검문소입니다. "모델 호출 직전에 이 함수를 한 번 돌려라"처럼요.

🔍 비유 — 공장 컨베이어 벨트의 검문 초소 Agent를 컨베이어 벨트라고 생각해 보세요. 부품(메시지)이 벨트를 타고 흘러갑니다. Node-style Hook은 벨트 특정 위치에 세워 둔 검문 초소예요. 부품이 그 지점을 지날 때마다 초소 직원(우리 함수)이 잠깐 멈춰 세워 "통과시킬까? 여기서 라인을 세울까?"를 판단합니다. @before_model은 "모델 기계 바로 앞"에 세운 초소입니다.

Node-style Hook은 데코레이터로 붙입니다. 붙이는 위치(=검문 지점)에 따라 이름이 다릅니다 — @before_agent, @before_model, @after_model, @after_agent. 함수는 항상 state(지금까지의 상태 = 메시지 기록 등)와 runtime(실행 환경 정보)을 받습니다. 오늘 쓸 건 그중 모델 호출 직전에 걸리는 @before_model입니다.

@before_agent vs @before_model — 몇 번 실행될까?

이 둘은 이름이 닮았지만 실행되는 횟수가 결정적으로 다릅니다. 이 차이를 놓치면 "왜 검사가 두 번 도는 거지?" 하고 당황하게 됩니다.

🔍 비유 — 놀이공원 정문 vs 놀이기구 앞 @before_agent는 놀이공원 정문의 입장 검표입니다. 공원에 들어올 때 딱 한 번 표를 확인하죠. 반면 @before_model은 각 놀이기구 앞에 선 안전요원입니다. 롤러코스터를 탈 때도, 회전목마를 탈 때도 탈 때마다 키와 안전벨트를 확인합니다. Agent가 도구를 쓴 뒤 모델을 다시 부르면, @before_model은 그때도 또 실행돼요.
데코레이터실행 시점실행 횟수
@before_agentAgent 전체 실행이 시작될 때딱 한 번
@before_model모델(LLM)을 호출하기 직전모델을 부를 때마다 (도구 실행 후 재호출 포함)
💡 이번 예시에서는? 우리는 사용자 입력을 검사하는 게 목적이고, 이 노트북 예시엔 도구(tool)가 없어서 모델은 한 번만 호출됩니다. 그래서 @before_model이든 @before_agent든 결과는 비슷하게 보입니다. 다만 원문 교재는 "모델을 지키는 초소"라는 의미를 강조하기 위해 @before_model을 씁니다.

can_jump_to와 반환값의 약속

검문소가 부품을 그냥 구경만 한다면 의미가 없겠죠. 핵심은 "흐름을 멈추거나 다른 곳으로 보낼 수 있는 권한"입니다. Node-style Hook에서는 이 권한을 can_jump_to로 미리 선언하고, 함수의 반환값으로 실제 명령을 내립니다.

🔍 비유 — 비상 정지 버튼과 그 사용 권한 공장 초소마다 빨간 비상 정지 버튼이 있으면 위험하겠죠. 그래서 "이 초소는 라인을 끝(end)으로 보낼 수 있다"는 권한을 관리자에게 먼저 등록해 둡니다. 이게 can_jump_to=["end"]예요. 그렇게 등록해 둔 초소만이, 실제 상황에서 버튼을 누를(=jump_to를 반환할) 수 있습니다. 권한 선언 없이 버튼부터 누르면 시스템이 "너 그럴 권한 없어" 하고 막습니다.

반환값에 따라 흐름이 이렇게 갈립니다.

이 함수가 돌려주는 값무슨 뜻인가
return None점프하지 마라. 평소대로 다음 단계(모델 호출)로 진행
return {"jump_to": "end"}여기서 끝(end)으로 바로 점프. 즉 모델을 부르지 않고 Agent 종료
⚠️ 권한 선언을 잊지 마세요 jump_to: "end"를 쓰려면 데코레이터에 반드시 @before_model(can_jump_to=["end"])처럼 "end로 갈 수 있다"고 미리 선언해야 합니다. 선언 없이 점프를 시도하면 오류가 납니다. 비상 버튼을 누르려면 먼저 그 버튼 사용 권한을 등록해 둬야 하는 것과 같아요.

0. 모델 준비

늘 그렇듯 먼저 말을 걸 상대(모델)를 하나 준비합니다. 이 노트북에서는 환경 변수를 불러오고 gpt-4o-mini로 기본 모델 객체를 만들어 둡니다.

📥 코드
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain.agents import create_agent


# .env 파일에서 환경 변수 로드
load_dotenv()

# 모델 선언
model = init_chat_model("gpt-4o-mini")
💡 참고 여기서 만든 model 변수는 이 셀에서 미리 선언해 두는 것이고, 실제 Agent를 만드는 아래 셀에서는 init_chat_model("gpt-5-nano")로 모델을 다시 지정합니다. 오늘의 주인공은 모델이 아니라 그 앞을 지키는 미들웨어이니, 어느 모델을 쓰는지는 크게 중요하지 않습니다.

1. 입력 검문소 만들기 — validate_input

이제 초소를 세울 차례입니다. 모델 호출 직전에 마지막 메시지를 들여다보고, 그 안에 "암구호"라는 낱말이 들어 있으면 모델을 부르지 않고 즉시 차단합니다. "암구호(비밀 통과 암호)"는 여기서 절대 외부 모델로 흘러가면 안 되는 민감 키워드를 흉내 낸 것입니다.

🔍 비유 — 사장에게 넘기기 전에 서류를 거르는 비서 임원(모델)에게 보고서를 올리기 전에, 비서(before_model)가 먼저 서류를 훑어봅니다. 만약 "대외비 · 암구호" 같은 기밀 도장이 찍혀 있으면, 비서는 그 서류를 임원 손에 절대 넘기지 않고 "이 요청은 처리할 수 없습니다"라는 회신만 대신 남깁니다. 덕분에 민감 정보가 외부 AI 모델로 유출되는 사고를 원천 차단할 수 있죠.
📥 코드
from langchain.agents.middleware import before_model
from langchain.messages import AIMessage

@before_model(can_jump_to=["end"])
def validate_input(state, runtime):
    last_message = state["messages"][-1]
    if "암구호" in last_message.content:
        print("암구호 감지됨 — 응답 차단")
        return {
            "messages": [AIMessage(content="이 요청은 처리할 수 없습니다.")],
            "jump_to": "end"  # 모델 호출 중단 후 에이전트 종료
        }
    print("✅ 정상 입력, 모델 호출 계속 진행")
    return None

한 줄씩 뜯어보면 이렇습니다.

  • @before_model(can_jump_to=["end"]) — 이 함수를 모델 호출 직전 초소로 등록하고, 동시에 "end로 점프할 권한"을 부여합니다.
  • state["messages"][-1] — 지금까지 쌓인 메시지 중 가장 마지막(방금 들어온 사용자 입력)을 꺼냅니다.
  • if "암구호" in last_message.content: — 그 내용 안에 금지 낱말이 있는지 검사합니다.
  • 있으면 → AIMessage로 차단 안내문을 대신 남기고 jump_to: "end"로 즉시 종료합니다.
  • 없으면 → return None으로 평소대로 통과시켜 모델이 정상 호출되게 합니다.
💡 차단할 때 왜 AIMessage를 직접 만들까? 모델을 아예 부르지 않으니, 사용자에게 돌려줄 답변이 비어 버립니다. 그래서 우리가 손수 AIMessage(content="이 요청은 처리할 수 없습니다.")를 만들어 모델 대신 대답을 채워 넣는 것입니다. 배우가 무대에 못 오르니 감독이 대사를 대독하는 셈이죠.

2. Agent에 붙여 실행하기

만든 초소를 create_agent의 middleware 목록에 넣어 주면 설치가 끝납니다. 그런 다음 일부러 "암구호"가 들어간 문장을 던져서, 초소가 제대로 라인을 세우는지 확인해 봅니다.

1사용자 입력

"오늘의 암구호는 삼각대-자동차 입니다."

2before_model 검사

마지막 메시지에 "암구호" 포함? → 발견!

3jump_to end

모델 호출 건너뛰고 차단 메시지 남김

4Agent 종료

LLM은 한 번도 불리지 않음

📥 코드
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model

agent = create_agent(
    model=init_chat_model("gpt-5-nano"),
    tools=[],
    middleware=[validate_input],
)

response = agent.invoke(
    {"messages": [{"role": "user", "content": "오늘의 암구호는 삼각대-자동차 입니다."}]},
)
print(response)

입력한 문장에는 "암구호"라는 낱말이 들어 있습니다. 따라서 초소(validate_input)는 바로 이 조건을 잡아내고, 모델을 부르지 않은 채 대화를 끝냅니다.

▶ 이렇게 나와요
암구호 감지됨 — 응답 차단
{'messages': [HumanMessage(content='오늘의 암구호는 삼각대-자동차 입니다.', additional_kwargs={}, response_metadata={}, id='c2349713-c8fa-408d-b511-1daafe796cab'), AIMessage(content='이 요청은 처리할 수 없습니다.', additional_kwargs={}, response_metadata={}, id='ba386814-bac9-4740-8162-7dd9d5f45a87', tool_calls=[], invalid_tool_calls=[])]}

3. 실행 결과 분석

출력을 자세히 보면, print("암구호 감지됨 — 응답 차단")이 먼저 찍혔습니다. 이건 초소가 금지 낱말을 잡아 라인을 세웠다는 증거입니다. 그리고 최종 messages 리스트에는 딱 두 개만 담겨 있습니다.

Human
오늘의 암구호는 삼각대-자동차 입니다. ← 사용자가 보낸 원문 (암구호 포함)
AI
이 요청은 처리할 수 없습니다. ← 모델이 아니라 우리 미들웨어가 만든 차단 메시지

여기서 가장 중요한 사실은 이 AIMessage가 LLM이 만든 게 아니라는 점입니다. 실제 모델(gpt-5-nano) 호출은 단 한 번도 일어나지 않았습니다. 사용자의 민감한 문장은 외부 AI에게 전달되기 전에 우리 손으로 걸러졌습니다.

💡 이게 바로 "입력 가드레일" Guardrail(가드레일)은 도로 옆 가드레일(난간)처럼, 시스템이 위험한 방향으로 벗어나지 못하게 막아주는 안전장치입니다. @before_model은 모델에 닿기 전 단계에 세우는 가드레일이라, 민감 정보 유출·비용 낭비·부적절한 요청을 가장 이른 시점에 차단할 수 있습니다.
⚠️ 실전에서는 키워드 검사만으로 부족합니다 이 예시는 원리를 보여주기 위해 "암구호" in ...이라는 단순 문자열 포함 검사를 씁니다. 하지만 실제 서비스에서는 띄어쓰기·변형·우회 표현을 피해 갈 수 있으므로, 정규식·분류 모델·PII 탐지기 같은 더 촘촘한 검사를 조합해야 합니다.

📚 한 장 정리

오늘의 핵심 @before_model은 모델을 부르기 직전에 서는 검문소다. 위험한 입력이면 LLM을 아예 호출하지 않고 jump_to: "end"로 대화를 즉시 끝낼 수 있다.
  • Node-style Hook — 실행 라인의 정해진 지점에서 순서대로 도는 미들웨어(@before_model 등).
  • @before_agent vs @before_model — 정문 검표(딱 한 번) vs 놀이기구 안전요원(모델 부를 때마다).
  • can_jump_to=["end"] — 비상 정지 버튼을 누를 권한을 미리 등록하는 선언.
  • 반환값의 약속 — None이면 그대로 통과, {"jump_to": "end"}면 모델 없이 즉시 종료.
  • 차단 시 AIMessage 직접 생성 — 모델을 안 부르니, 사용자에게 줄 대답은 우리가 채워 넣는다.
  • 효과 — 민감 정보(암구호)가 외부 모델에 닿기 전에 걸러지는 입력 가드레일이 완성된다.
