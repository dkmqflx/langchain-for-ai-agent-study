4

검색 개선 ② Reranker (2-stage retrieval)

랭체인 집중 ⏱ 반나절
🎯 목표

후보를 넉넉히 뽑은 뒤 Cross-Encoder로 재정렬해 문맥의 정밀도를 끌어올린다. _build_retriever()에 "rerank" 분기를 추가한다.

🧠 개념

검색은 빠르지만 정밀도가 낮고, Cross-Encoder(질문·문서를 함께 보는 모델)는 느리지만 정밀합니다. 그래서 1단계로 top-10을 빠르게 검색 → 2단계로 rerank해 상위 4개만 남기는 것이 실무 표준(2-stage retrieval). 노이즈 청크가 걸러져 생성 품질이 오릅니다.

❓ 그래서 Cross-Encoder가 대체 뭔가요?

인코더(Encoder)는 텍스트를 숫자 벡터로 바꾸는 모델입니다. STEP 1에서 쓴 임베딩 모델이 바로 인코더예요. 지금까지 쓴 방식은 정확히는 Bi-Encoder(bi = 둘) — 인코더를 질문에 한 번, 문서에 한 번 따로 돌리기 때문입니다.

질문 → 인코더 → 벡터 A
문서 → 인코더 → 벡터 B
두 벡터 사이 거리 계산
두 줄이 끝까지 따로 흐릅니다 — 아래쪽 벡터 B는 질문이 오기 전에 미리 계산해 둔 것.

여기서 핵심은 문서를 벡터로 만드는 시점에 질문이 뭔지 모른다는 점입니다. 그래서 164개를 미리 다 계산해 Chroma에 넣어 둘 수 있었고, 검색이 순식간에 끝났죠.

Cross-Encoder는 질문과 문서를 한 덩어리로 이어붙여 모델에 한 번에 넣습니다. 출력은 벡터가 아니라 관련도 점수 하나예요.

질문환불은 며칠 안에 신청해야 하나요? [SEP] 문서환불 신청 기한은 14일입니다
Cross-Encoder · 모델 한 번 실행
▼
0.94
질문과 문서가 한 상자 안에 들어가고, 나오는 건 벡터가 아니라 관련도 점수 하나.

이름이 cross(교차)인 이유는, 모델 안에서 질문의 단어 하나하나가 문서의 단어 하나하나를 교차로 들여다보기 때문입니다. Bi-Encoder에서는 이 교차가 원천적으로 불가능합니다 — 문서를 벡터로 만들 때 질문이 아직 존재하지 않으니까요.

순위가 실제로 어떻게 바뀌나? 질문이 "환불은 며칠 안에 신청해야 하나요?"이고 문서 A는 "교환은 수령 후 7일 이내 신청", 문서 B는 "환불 신청 기한은 14일"이라고 해 봅시다. Bi-Encoder에게 A와 B는 둘 다 "반품 정책·기한·며칠"이라는 비슷한 주제 덩어리로 뭉개져 A가 위로 올라오기 쉽습니다. 벡터 하나로 압축하는 순간 "환불이냐 교환이냐"는 결정적 차이가 씻겨 나가거든요. Cross-Encoder는 질문의 "환불"과 문서 A의 "교환"을 정면으로 맞대 보고 A를 떨어뜨립니다.

대신 문서 10개를 재채점하려면 모델을 10번 돌려야 합니다. 질문이 와야 계산이 시작되니 미리 계산해 둘 방법이 없어요. 그래서 1단계로 10개까지 좁힌 다음에야 쓸 수 있습니다. 아래 코드의 BAAI/bge-reranker-base가 바로 이 Cross-Encoder 모델이고, 출력이 점수 하나뿐이라 검색용 인덱스를 만들 수 없어 오직 재정렬 전용입니다.

🛠 할 일

STEP 3에서 만든 _build_retriever()에 "rerank" 분기 하나를 더하는 작업입니다. 세 조각으로 나눠 보고, 맨 아래 전체 코드를 붙여 넣으세요.

🎯 비유 — 서류 심사 다음에 면접

채용에서 지원자 500명을 전부 면접할 수는 없습니다. 그래서 먼저 이력서 키워드로 10명을 빠르게 추리고, 그 10명만 면접해서 4명을 고릅니다. 서류 심사는 거칠지만 빠르고, 면접은 느리지만 정확하죠. 2-stage retrieval이 정확히 이 구조입니다 — 1단계로 넓게 top-10을 검색하고, 2단계로 정밀 모델이 4개를 고릅니다.

🧭 세 조각 한눈에

① 리랭커 부품 3개 불러오기  →  ② "rerank" 분기 추가(넓게 뽑고 → 좁게 고르기)  →  ③ answer()의 기본 mode 승격

① 부품 세 개 불러오기

이름이 길지만 역할은 모델 / 로직 / 껍데기 세 층으로 나뉩니다.

rag.py (STEP 3 코드에 이어서)
# 껍데기 — 기존 검색기를 감싸서 '검색한 뒤 후처리'를 덧붙이는 검색기
from langchain_classic.retrievers import ContextualCompressionRetriever
# 로직 — 점수를 매겨 재정렬하고 상위 N개만 남기는 부분
from langchain_classic.retrievers.document_compressors import CrossEncoderReranker
# 모델 — 실제로 점수를 매기는 AI 모델을 내 컴퓨터에서 돌리는 래퍼
from langchain_community.cross_encoders import HuggingFaceCrossEncoder
# ImportError가 나면 경로 후보: langchain.retrievers / langchain.retrievers.document_compressors
부품층하는 일
HuggingFaceCrossEncoder모델실제로 점수를 매기는 로컬 AI 모델
CrossEncoderReranker로직그 점수로 재정렬하고 상위 N개만 남김
ContextualCompressionRetriever껍데기기존 검색기를 감싸서 "검색 후 후처리"를 붙임

이 감싸기(wrapping) 패턴이 랭체인의 중요한 설계 감각입니다. 기존 검색기를 고치지 않고 겉을 한 겹 둘러 기능을 더하는 것 — 그래서 baseline·hybrid 코드는 손대지 않아도 됩니다.

② "rerank" 분기 — 넓게 뽑고, 좁게 고르기

여기서 눈여겨볼 건 k가 4에서 10으로 늘어난다는 점입니다. 1단계의 목표가 정확히 고르기가 아니라 정답을 빠뜨리지 않기로 바뀌었기 때문이에요. 정밀하게 고르는 일은 2단계가 맡습니다.

rag.py (_build_retriever에 분기 추가)
    if mode == "rerank":
        # ── 1단계 (빠르게, 넓게) ────────────────────────────────────
        # 여기서는 '정확히 고르기'가 목표가 아니라 '정답을 빠뜨리지 않기'가 목표다.
        # 그래서 hybrid에서 4였던 k를 10으로 늘려 후보를 넉넉히 확보한다.
        bm25.k = 10                                       # 키워드 검색도 10개
        wide = vs.as_retriever(search_kwargs={"k": 10})   # 의미 검색도 10개
        base = EnsembleRetriever(retrievers=[bm25, wide], weights=[0.4, 0.6])  # 둘을 섞어 넓은 후보군을 만든다

        # ── 2단계 (느리지만 정밀하게) ───────────────────────────────
        # Cross-Encoder는 질문과 청크를 '한 쌍으로 묶어' 모델에 함께 넣고 관련도를 직접 채점한다.
        # 미리 계산해 둘 수 없어 느리므로, 위에서 10개로 좁힌 뒤에야 쓸 수 있다.
        reranker = CrossEncoderReranker(
            model=HuggingFaceCrossEncoder(model_name="BAAI/bge-reranker-base"),  # 무료 로컬 모델(첫 실행 시 자동 다운로드)
            top_n=4,                                      # 재채점 후 최종적으로 남길 청크 수
        )

        # 두 단계를 하나로 묶는다. base_retriever로 넓게 뽑고 → base_compressor로 걸러 낸다.
        # 기존 검색기를 고치지 않고 '감싸서' 기능을 더하는 방식이라 baseline·hybrid는 그대로 남는다.
        return ContextualCompressionRetriever(base_compressor=reranker, base_retriever=base)
🧩 왜 Cross-Encoder가 더 정확한가요?

지금까지의 임베딩 검색은 질문과 문서를 따로따로 벡터로 만든 뒤 거리를 쟀습니다. 문서 벡터는 미리 계산해 둘 수 있어서 빠르지만, 문서를 벡터로 압축하는 순간 질문과의 미묘한 관계는 사라집니다.

Cross-Encoder는 질문과 문서를 한 쌍으로 묶어 모델에 함께 넣고 "이 둘이 얼마나 맞나"를 직접 점수로 냅니다. 미리 계산해 둘 수 없어 매번 10번을 새로 돌려야 하니 느리지만, 훨씬 정확합니다. 그래서 전체 164개에는 못 쓰고, 10개로 좁힌 뒤에야 쓸 수 있는 겁니다.

⚠️ 첫 실행은 오래 걸립니다 (고장 아닙니다)

bge-reranker-base는 내 컴퓨터에서 도는 무료 모델이라, 처음 한 번은 수백 MB를 내려받습니다. 몇 분 걸릴 수 있고 그동안 화면이 멈춘 것처럼 보여요. 두 번째부터는 캐시에서 바로 뜹니다. 다만 매 질문마다 로컬 연산이 붙으니 rerank는 hybrid보다 느립니다 — 이게 STEP 7에서 재보게 될 속도↔정확도 맞바꿈입니다.

📄 전체 코드 (rag.py에 추가·교체할 부분)
rag.py (_build_retriever에 rerank 분기 추가)
# ═══════════════════════════════════════════════════════════════════
# STEP 4 · Reranker(2-stage retrieval): 후보를 넉넉히 뽑은 뒤 정밀 모델로 재정렬한다.
# 1단계(빠름): 하이브리드로 top-10을 넓게 검색  →  2단계(정밀): Cross-Encoder가 질문·문서를
# 함께 보며 다시 채점해 상위 4개만 남긴다. 노이즈 청크가 걸러진다.
# _build_retriever()에 "rerank" 분기를 추가하고, answer()의 기본 mode를 "rerank"로 올린다.
# ═══════════════════════════════════════════════════════════════════
from langchain_classic.retrievers import ContextualCompressionRetriever          # 검색 결과를 후처리(압축·재정렬)로 감싸는 검색기
from langchain_classic.retrievers.document_compressors import CrossEncoderReranker  # rerank 로직
from langchain_community.cross_encoders import HuggingFaceCrossEncoder            # 로컬 Cross-Encoder 모델 래퍼
# ImportError 시 경로 후보: langchain.retrievers / langchain.retrievers.document_compressors

def _build_retriever(mode: str):
    """mode 이름 → 검색기 객체. baseline | hybrid | rerank"""
    dense = vs.as_retriever(search_kwargs={"k": 4})
    if mode == "baseline":
        return dense
    bm25 = BM25Retriever.from_documents(chunks)
    bm25.k = 4
    if mode == "hybrid":
        return EnsembleRetriever(retrievers=[bm25, dense], weights=[0.4, 0.6])
    if mode == "rerank":
        # 1단계: 후보를 넉넉히(top-10) — 여기선 '빠뜨리지 않기'가 목표, 정밀도는 2단계가 맡는다
        bm25.k = 10
        wide = vs.as_retriever(search_kwargs={"k": 10})
        base = EnsembleRetriever(retrievers=[bm25, wide], weights=[0.4, 0.6])
        # 2단계: Cross-Encoder가 질문·청크를 함께 보고 재채점 → 상위 4개만 남긴다
        reranker = CrossEncoderReranker(
            model=HuggingFaceCrossEncoder(model_name="BAAI/bge-reranker-base"),   # 무료 로컬 모델(첫 실행 시 자동 다운로드)
            top_n=4,                                                              # 재정렬 후 남길 청크 수
        )
        return ContextualCompressionRetriever(base_compressor=reranker, base_retriever=base)
    raise ValueError(f"unknown mode: {mode}")

def answer(question: str, mode: str = "rerank"):   # 기본 mode 승격: hybrid → rerank
    ...  # 본문은 STEP 3과 동일
