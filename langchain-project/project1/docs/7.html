7

골든 평가셋 + RAGAS — 세 구성을 숫자로 비교

서비스화 층 · 핵심 ⏱ 반나절~1일
🎯 목표

"hybrid·rerank로 좋아진 것 같다"를 숫자로 바꾼다. 같은 골든셋으로 baseline / hybrid / rerank 세 구성을 채점해 개선 스토리를 표로 완성한다 — STEP 3에서 만든 mode 팩토리가 여기서 빛을 발합니다.

🧠 개념

개선을 주장하려면 측정이 필요합니다. RAGAS의 대표 지표 4개:

지표무엇을 재나낮으면 손볼 곳
faithfulness답이 검색 문맥에 충실한가(환각 여부)생성 프롬프트(STEP 2)
answer_relevancy답이 질문에 맞는가생성/질문 이해(STEP 2)
context_precision검색된 문맥이 군더더기 없이 관련 있나검색 노이즈 → rerank의 top_n·후보 폭(STEP 4)
context_recall정답 근거를 검색이 빠짐없이 가져왔나검색 누락 → hybrid 가중치·k(STEP 3)
🛠 할 일

만들 것은 정답지(eval_data.json)와 채점기(evaluate.py) 둘입니다. 네 조각으로 나눠 보고, 맨 아래 전체 코드를 복사하세요.

🧭 네 조각 한눈에

① 골든셋(정답지) 만들기  →  ② 채점기 준비  →  ③ 질문마다 실제 RAG 돌리기  →  ④ RAGAS로 채점하고 CSV로 저장

① 골든셋 — 손으로 만드는 정답지

시험을 채점하려면 답안지가 먼저 있어야 합니다. 골든셋이 그 답안지예요. 그리고 이건 직접 만들 수밖에 없습니다 — 내 문서에 대한 정답을 아는 건 나뿐이니까요. 이 프로젝트에서 가장 귀찮지만 가장 중요한 작업이고, 실무 RAG도 똑같습니다.

eval_data.json
[
  {"question": "질문 1?", "ground_truth": "문서 기준 정답 1"},
  {"question": "질문 2?", "ground_truth": "문서 기준 정답 2"}
]

처음엔 5개로 시작해 20~50개까지 늘리세요. 5개로도 파이프라인이 도는지는 확인되지만, 그 정도로는 점수가 질문 하나에 크게 출렁여서 "좋아졌다"고 말하기 어렵습니다.

⚠️ ground_truth는 "내 상식"이 아니라 "문서에 쓰인 말"로

평가는 우리 시스템이 이 문서에서 정답을 잘 찾아오는가를 재는 것입니다. 그러니 정답도 문서에 실제로 적힌 내용이어야 해요. 문서에 없는 내용을 정답으로 적으면 시스템은 영원히 틀린 것으로 채점됩니다. 질문은 골고루 섞으세요 — 조항 번호나 고유 용어가 든 질문(BM25가 유리), 풀어쓴 일상적인 질문(의미 검색이 유리), 여러 쪽을 합쳐야 답이 되는 질문까지요. 그래야 세 구성의 차이가 드러납니다.

② 채점기 준비 — 부품 불러오고 mode 받기

evaluate.py
import json, sys                                    # json: 골든셋 파일 읽기 / sys: 터미널 인자 읽기
from datasets import Dataset                        # RAGAS에 넣을 '표' 형식
from ragas import evaluate                          # 채점을 실행하는 함수
from ragas.metrics import faithfulness, answer_relevancy, context_precision, context_recall  # 지표 4종
from ragas.llms import LangchainLLMWrapper          # 어댑터 — RAGAS가 우리 랭체인 LLM을 쓸 수 있게 모양을 맞춰 준다
from ragas.embeddings import LangchainEmbeddingsWrapper  # 어댑터 — 임베딩용
from langchain.chat_models import init_chat_model
from langchain_openai import OpenAIEmbeddings
from rag import answer                              # 평가 대상 — 우리가 만든 RAG 파이프라인

# 어떤 검색 구성을 채점할지 터미널에서 받는다. 파일 하나로 세 구성을 각각 돌리기 위한 장치.
#   uv run python evaluate.py hybrid  →  mode = "hybrid"
#   uv run python evaluate.py         →  mode = "baseline" (기본값)
mode = sys.argv[1] if len(sys.argv) > 1 else "baseline"

# 골든셋(정답지)을 읽어 온다. 형식: [{"question": ..., "ground_truth": ...}, ...]
rows = json.load(open("eval_data.json", encoding="utf-8"))

mode를 실행 인자로 받는 게 핵심입니다. 파일 하나로 세 구성을 각각 채점하려는 것이고, 이게 가능한 건 STEP 3에서 검색기를 문자열로 갈아끼울 수 있게 만들어 뒀기 때문입니다. Wrapper가 붙은 둘은 어댑터예요 — RAGAS가 우리 랭체인 모델을 쓸 수 있게 모양을 맞춰 주는 변환 플러그입니다.

③ 질문마다 실제 RAG를 돌려 답안 모으기

채점 전에 답안지를 실제로 작성하는 단계입니다. 골든셋의 질문을 하나씩 우리 시스템에 넣습니다.

evaluate.py (이어서)
records = []                               # 채점기에 넘길 '표'의 행들을 모을 리스트
for r in rows:                             # 골든셋의 질문을 하나씩 꺼내
    out = answer(r["question"], mode=mode) # 실제로 RAG를 돌린다 (여기서 STEP 3~4의 mode 팩토리가 쓰인다)
    records.append({
        "question": r["question"],         # 물어본 질문
        "answer": out["answer"],           # 우리 시스템이 낸 답  → ground_truth와 비교해 '답의 품질'을 잰다
        "contexts": out["contexts"],       # 검색된 원문 전체    → 이게 없으면 검색 관련 지표를 계산할 수 없다
        "ground_truth": r["ground_truth"], # 사람이 만든 정답    → 모든 비교의 기준
    })
# ※ 여기서 API 비용이 발생한다. 질문 수만큼 검색 + LLM 호출이 실제로 일어나기 때문.
🔗 STEP 2의 contexts가 여기서 쓰입니다

STEP 2에서 answer()가 contexts(검색된 원문 전체)를 함께 돌려주게 만들었죠. 사람에게는 필요 없어서 STEP 5의 API 응답에서도 뺐던 그 값입니다. 그 이유가 지금 드러납니다 — 검색 관련 지표 두 개는 이게 없으면 계산 자체가 안 됩니다. 답만 보고는 "검색이 정답 근거를 가져오긴 했나"를 알 수 없으니까요.

네 항목이 각각 채점의 재료입니다. answer와 contexts를 비교하면 환각 여부가, contexts와 ground_truth를 비교하면 검색 누락이 드러납니다.

④ 채점하고 CSV로 남기기

evaluate.py (이어서)
result = evaluate(
    Dataset.from_list(records),   # 위에서 모은 행들을 RAGAS가 읽는 표 형식으로 변환
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],  # 이 4개 지표로 채점
    # 채점을 수행하는 '심판' LLM — 답을 만드는 모델이 아니라 판정하는 모델이다.
    # "이 답이 저 문맥에 근거하고 있나?" 같은 판단은 규칙으로 짜기 어려워 LLM에게 맡긴다.
    # → 그래서 평가를 돌릴 때도 API 비용이 든다 (질문 수 × 지표 4개만큼 호출)
    llm=LangchainLLMWrapper(init_chat_model("gpt-5-mini")),
    # 문장끼리 의미가 얼마나 가까운지 재는 데 쓰는 임베딩
    embeddings=LangchainEmbeddingsWrapper(OpenAIEmbeddings(model="text-embedding-3-small")),
)

print(f"[{mode}]", result)                                  # 지표별 '평균'을 화면에 출력
result.to_pandas().to_csv(f"eval_{mode}.csv", index=False)  # 문항별 상세 점수를 CSV로 저장
# 평균만 보면 '왜' 떨어졌는지 모른다. 어떤 질문이 점수를 깎아먹었는지는 이 CSV를 열어야 보인다.

llm=에 넘기는 모델은 답을 만드는 모델이 아니라 채점하는 심판입니다. "이 답이 저 문맥에 근거하고 있나?" 같은 판단은 규칙으로 짜기 어려워서, RAGAS는 LLM에게 채점을 시킵니다. 그래서 평가를 돌릴 때도 API 비용이 듭니다 — 질문 수 × 지표 4개만큼 호출이 나가니, 골든셋을 50개로 늘릴 때는 감안하세요.

print는 평균만 보여주지만, CSV에는 문항별 점수가 다 들어갑니다. 평균이 떨어졌을 때 어떤 질문이 깎아먹었는지는 CSV를 열어야 보이고, 보통 거기에 개선의 실마리가 있습니다.

📄 전체 코드 (위 세 조각을 이어 붙인 것)
evaluate.py
# ═══════════════════════════════════════════════════════════════════
# STEP 7 · RAGAS 평가: '좋아진 것 같다'를 숫자로 바꾼다.
# 골든셋(eval_data.json)에 answer(question, mode=...)를 돌려, 4개 지표로 채점한다:
#   faithfulness(환각 여부) · answer_relevancy(질문 적합) · context_precision(문맥 정확) · context_recall(누락 없음)
# 실행:  uv run python evaluate.py baseline   → eval_baseline.csv
#       uv run python evaluate.py hybrid     → eval_hybrid.csv
#       uv run python evaluate.py rerank     → eval_rerank.csv
# 세 번 실행해 나온 지표를 한 표에 모으면 '개선 스토리'가 완성된다.
# ═══════════════════════════════════════════════════════════════════
import json, sys
from datasets import Dataset                                   # RAGAS에 넣을 표(데이터셋) 형식
from ragas import evaluate                                     # 채점 실행 함수
from ragas.metrics import faithfulness, answer_relevancy, context_precision, context_recall  # 지표 4종
from ragas.llms import LangchainLLMWrapper                     # RAGAS가 LangChain LLM을 쓰게 감싸는 어댑터
from ragas.embeddings import LangchainEmbeddingsWrapper        # RAGAS가 쓸 임베딩 어댑터
from langchain.chat_models import init_chat_model
from langchain_openai import OpenAIEmbeddings
from rag import answer                                         # 평가 대상: 우리 RAG 파이프라인

mode = sys.argv[1] if len(sys.argv) > 1 else "baseline"     # 어떤 검색 구성(mode)을 채점할지
rows = json.load(open("eval_data.json", encoding="utf-8"))     # 골든셋 로드: [{question, ground_truth}, ...]
records = []
for r in rows:                                                 # 질문마다 실제로 RAG를 돌려 채점용 행을 만든다
    out = answer(r["question"], mode=mode)                     # STEP 3~4의 mode 팩토리가 여기서 쓰인다
    records.append({
        "question": r["question"],                             # 질문
        "answer": out["answer"],                               # 우리 시스템이 낸 답
        "contexts": out["contexts"],                           # 검색된 문맥(정확/누락 지표 계산에 필요)
        "ground_truth": r["ground_truth"],                     # 사람이 만든 정답(기준)
    })

result = evaluate(                                             # 4개 지표로 일괄 채점
    Dataset.from_list(records),
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
    llm=LangchainLLMWrapper(init_chat_model("gpt-5-mini")),                       # 채점을 수행하는 심판 LLM
    embeddings=LangchainEmbeddingsWrapper(OpenAIEmbeddings(model="text-embedding-3-small")),  # 유사도 계산용 임베딩
)
print(f"[{mode}]", result)                                    # 지표 평균을 화면에 출력
result.to_pandas().to_csv(f"eval_{mode}.csv", index=False)    # 문항별 상세 점수를 CSV로 저장 → 구성 간 비교

실행: uv run python evaluate.py baseline → hybrid → rerank 순서로 세 번.

💡 팁 RAGAS는 버전에 따라 evaluate() 인자/데이터 형식이 다를 수 있어요. 컬럼 이름은 question · answer · contexts · ground_truth가 기본이며, 에러가 나면 설치된 RAGAS 문서의 "EvaluationDataset" 예시에 맞춰 records 형식만 바꾸면 됩니다.
