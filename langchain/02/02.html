02. Tool 심화: 외부 API 호출 도구

실습 노트북: 02.ipynb  ·  원문: docs/02.agent-basic.md  ·  난이도: 🟡 중급  ·  선행: 01. Tool 기초

이 자료는 실습 노트북(02.ipynb)을 열기 전에 먼저 읽는 강의 교재입니다. 앞 장에서 만든 간단한 도구를 넘어, 이번에는 실제 인터넷에 있는 외부 API를 호출하는 도구를 만듭니다. "알라딘 서점의 베스트셀러 목록을 가져오는 도구"를 예로, 도구 정의 → 에이전트 장착 → 호출의 전 과정과, 실무에서 꼭 알아야 할 에러 처리 설계·Function Calling(자연어가 함수 인자로 바뀌는 원리)까지 비유와 함께 풀어봅니다.

🔍 비유 — 똑똑하지만 손발이 없는 천재 LLM은 방대한 지식을 가진 천재지만, 몸이 없어서 스스로는 아무것도 하지 못합니다. 인터넷에 접속할 수도, 오늘 날씨를 조회할 수도, 서점의 실시간 순위를 볼 수도 없죠. 그래서 우리는 이 천재에게 손발(도구, Tool)을 달아줍니다. "베스트셀러가 궁금하면 이 전화기(도구)로 알라딘에 전화해"라고 도구를 쥐여주면, 천재는 필요할 때 그 전화기를 직접 들어 정보를 가져와 답합니다. 이 장은 바로 그 전화기 하나를 만들어 달아주는 이야기입니다.
이 장에서 배우는 것 앞 장의 도구가 "계산기"처럼 스스로 답을 만드는 도구였다면, 이번 도구는 바깥 세상(외부 서버)에 물어보고 그 답을 받아오는 도구입니다. 핵심은 세 가지 — ① @tool로 API 호출을 함수로 감싸기, ② 그 도구를 create_agent로 에이전트에 장착하기, ③ 에이전트가 사용자 말에서 필요한 값을 뽑아 도구를 알아서 호출하게 만들기입니다.

그림으로 먼저 큰 그림을 그려봅시다. 사용자가 질문하면 에이전트는 다음 흐름으로 움직입니다.

1사용자 질문

"베스트셀러 5권 알려줘"

2도구 선택

LLM이 "이건 알라딘 도구가 필요해"라고 판단

3도구 실행

실제로 알라딘 API에 HTTP 요청을 보냄

4결과 회수

받은 도서 목록(데이터)을 LLM에게 다시 전달

5자연어 답변

LLM이 목록을 사람이 읽기 좋게 정리해 답변

⚠️ 실행 전 준비 이 노트북을 직접 돌리려면 .env 파일에 OPENAI_API_KEY(모델용)와 ALADIN_API_KEY(알라딘 서점 API용, 알라딘에서 발급하는 TTBKey)가 모두 들어 있어야 합니다. 키가 없으면 도구가 호출돼도 데이터를 가져오지 못합니다. 이 교재만 읽을 때는 필요 없습니다.

준비물 — requests와 typing

외부 API를 부르는 도구를 만들려면 두 가지 도구 상자가 필요합니다. 하나는 인터넷으로 편지를 주고받는 우체부(requests), 다른 하나는 이 함수가 어떤 데이터를 주고받는지 알려주는 라벨(typing)입니다.

① requests — 인터넷 우체부

🔍 비유 — 편지를 보내고 답장을 받는 우체부 requests는 인터넷 세계의 우체부입니다. 우리가 "이 주소(URL)로 이 내용(파라미터)을 담아 편지를 보내줘"라고 부탁하면(requests.get(...)), 우체부가 서버까지 달려가 편지를 전하고 답장(응답, response)을 받아 돌아옵니다. 파이썬 기본 도구(urllib)로도 편지를 보낼 수 있지만 절차가 번거로워서, "사람을 위한 HTTP 라이브러리"라 불릴 만큼 쉬운 requests를 거의 항상 씁니다.

가장 단순한 사용 예시는 이렇습니다.

📥 코드
import requests

# GET 요청 = "이 주소에 있는 정보 좀 보여줘" 라고 요청하는 것
response = requests.get("https://api.github.com")
print(response.status_code)  # 200 이면 "성공"이라는 뜻
  • GET — 서버에서 데이터를 가져올 때 (조회)
  • POST — 서버로 데이터를 보낼 때 (등록/제출)
  • status_code — 우체부가 가져온 배달 결과표. 200은 성공, 404는 "그런 주소 없음", 500은 "서버 고장" 등.

② typing — 데이터에 붙이는 설명 라벨

🔍 비유 — 택배 상자에 붙은 내용물 스티커 파이썬은 원래 변수의 타입을 깐깐하게 따지지 않습니다. 그래서 상자를 열기 전엔 안에 뭐가 들었는지 모르죠. typing의 타입 힌트는 상자 겉면에 붙이는 "내용물: 문자열 목록" 스티커입니다. 실행에는 영향을 주지 않지만, 코드를 읽는 사람과 에디터에게 "이 칸엔 이런 데이터가 들어와요"라고 미리 알려줍니다. 뒤에서 보겠지만, 이 라벨은 LLM이 도구를 이해하는 데도 결정적인 힌트가 됩니다.
표기뜻예시
Any어떤 타입이든 상관없음자유로운 값
List리스트(목록) 형태List[str] = 문자열들의 목록
Dict딕셔너리(사전) 형태Dict[str, int] = 키는 문자열·값은 정수
Union"A이거나 B일 수 있음"Union[int, str] = 정수 또는 문자열
📥 코드
from typing import Any, Dict, List

# data는 "문자열들의 리스트"여야 하고,
# 반환값은 "키는 문자열, 값은 아무거나인 딕셔너리"라는 뜻
def process_data(data: List[str]) -> Dict[str, Any]:
    return {"result": data[0]}
💡 한눈에 requests는 웹 서버와 대화하기 위한 도구(별도 설치 필요), typing은 데이터 구조를 명확히 설명하기 위한 라벨(파이썬 기본 포함)입니다. AI 에이전트 코드에서 requests는 외부 API를 부를 때, typing은 도구의 입출력 형태를 정의할 때 짝을 이뤄 자주 등장합니다.

0. 환경 준비

먼저 필요한 재료들을 불러오고, 모델과 API 키를 준비합니다. 앞 장들과 달리 이번엔 @tool, create_agent, 그리고 인터넷 통신용 requests가 새로 등장합니다.

📥 코드
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain.agents import create_agent
from typing import Any, Dict, List
import requests
import os

# .env 파일에서 환경 변수 로드
load_dotenv()

# 모델 선언
model = init_chat_model("gpt-4o-mini")

# 알라딘 API 키 로드
aladin_api_key = os.getenv("ALADIN_API_KEY")

마지막 줄이 이번 장의 새 얼굴입니다. os.getenv("ALADIN_API_KEY")는 .env 파일에 적어둔 알라딘 인증 키를 코드에 직접 쓰지 않고 안전하게 꺼내오는 방법입니다.

🚫 절대 하지 말 것 — API 키를 코드에 박아 넣기 aladin_api_key = "ttbabcd1234..."처럼 키를 코드에 직접 적고 그대로 GitHub 등에 올리면, 전 세계가 당신의 키를 볼 수 있게 됩니다. 남이 그 키로 무제한 호출을 해 요금 폭탄·계정 정지로 이어질 수 있어요. 키는 항상 .env 파일에 두고 os.getenv로 읽고, .env는 .gitignore에 넣어 커밋에서 제외하세요.

1. @tool로 외부 API 감싸기

이제 핵심입니다. 알라딘 베스트셀러 목록을 가져오는 함수를 만들고, 그 위에 @tool이라는 스티커 한 장을 붙여 에이전트가 쓸 수 있는 도구로 승격시킵니다.

🔍 비유 — 도서관 사서에게 거는 전화 이 함수는 알라딘이라는 거대한 도서관에 전화를 거는 것과 같습니다. 전화를 걸 때는 정해진 양식으로 말해야 하죠 — "저는 회원번호 ○○(ttbkey)이고요, 베스트셀러(QueryType) 목록을 5개(MaxResults)만, 도서(SearchTarget) 기준으로 주세요." 사서(서버)는 이 요청을 알아듣고 목록을 돌려줍니다. @tool은 이 "전화 거는 절차"를 에이전트가 언제든 눌러 쓸 수 있는 단축번호로 등록하는 일입니다.
📥 코드
@tool
def get_aladin_bestsellers(count: int = 10) -> List[Dict[str, Any]]:
    """
    알라딘 API를 사용하여 현재 가장 인기 있는 베스트셀러 도서 목록을 가져옵니다.

    Args:
        count (int): 가져올 도서의 수 (기본값 10, 최대 50).

    Returns:
        List[Dict]: 도서 제목, 저자, 가격, 링크 등을 포함한 딕셔너리 리스트.
    """
    # 2025-04-07 지침: 보안을 위해 TTBKey는 환경변수 사용 권장
    url = "http://www.aladin.co.kr/ttb/api/ItemList.aspx"

    # 알라딘 API 명세서 근거 파라미터 구성
    params = {
        "ttbkey": aladin_api_key,
        "QueryType": "Bestseller",  # 리스트 종류: 베스트셀러
        "MaxResults": min(count, 50), # 한 페이지 최대 50개 제한
        "start": 1,
        "SearchTarget": "Book",
        "output": "js",            # JSON 방식 출력
        "Version": "20131101"      # 최신 버전
    }

    try:
        response = requests.get(url, params=params)
        response.raise_for_status()
        # 요청 결과가 4xx 또는 5xx 에러(실패)일 때 예외(requests.exceptions.HTTPError)를 발생시킵니다.
        # 즉, 요청이 성공(200 OK 등)이 아니면 코드 실행을 중단하고 에러 처리를 하도록 만듭니다.
        # 이를 통해 API 호출 실패를 쉽게 감지하고, try-except로 예외를 처리할 수 있습니다.
        data = response.json()

        # 문서 응답 구조: 'item' 키 안에 도서 리스트가 담겨 있음
        items = data.get("item", [])

        # 에이전트가 이해하기 쉽도록 핵심 필드만 필터링 (Token 절약 및 가독성)
        return [
            {
                "title": item.get("title"),
                "author": item.get("author"),
                "publisher": item.get("publisher"),
                "price": item.get("priceSales"),
                "link": item.get("link")
            }
            for item in items
        ]
    except Exception as e:
        return [{"error": f"API 호출 실패: {str(e)}"}]

이 도구를 한 부분씩 뜯어보면 다음과 같습니다.

① Docstring과 타입 힌트 — "도구 설명서"

함수 바로 아래 삼중 따옴표("""...""")로 쓴 설명(Docstring)과 count: int = 10 같은 타입 힌트는 단순한 주석이 아닙니다. LLM은 이 설명을 읽고 "이 도구가 무슨 일을 하는지, 어떤 값을 넣어야 하는지"를 이해합니다. 사람이 아니라 AI가 읽는 사용 설명서인 셈이죠. 그래서 설명은 성실하게 써야 합니다.

② params — 전화할 때 대는 조건들

requests.get(url, params=params)는 URL 뒤에 이 딕셔너리를 질의 문자열(query string)로 붙여 보냅니다. QueryType=Bestseller는 "베스트셀러 목록", MaxResults=min(count, 50)는 "최대 이만큼", output=js는 "결과를 JSON으로 줘"라는 요청 조건입니다. min(count, 50)은 사용자가 100을 요청해도 알라딘 규정상 한도인 50을 넘지 않게 잘라주는 안전장치예요.

③ raise_for_status() — 배달 실패를 즉시 알리는 알람

🔍 비유 — 문 두드렸는데 아무도 없을 때 우체부가 편지를 전하러 갔는데 주소가 틀렸거나(404) 집이 무너졌다면(500), 그냥 조용히 돌아오면 곤란합니다. raise_for_status()는 "배달 실패!"라고 즉시 경보를 울리는 장치입니다. 응답이 성공(2xx)이 아니면 그 자리에서 예외를 일으켜, 잘못된 데이터를 붙잡고 계속 진행하는 사고를 막습니다.

④ 핵심 필드만 골라 반환 — 짐 줄이기

알라딘이 돌려주는 원본 데이터에는 수십 개의 필드가 들어 있습니다. 그중 제목·저자·출판사·가격·링크 다섯 개만 추려서 돌려주죠. 이유는 두 가지 — LLM에게 넘길 토큰(비용)을 아끼고, 불필요한 정보를 걷어내 답변 품질을 높이기 위해서입니다.

⚠️ except 블록을 눈여겨보세요 맨 아래 except에서 에러가 나도 프로그램을 멈추지 않고 [{"error": "..."}]라는 데이터를 반환합니다. 이 선택이 왜 중요한지는 아래 3장에서 자세히 다룹니다.

2. 에이전트에 도구 쥐여주고 호출하기

도구를 만들었으니 이제 천재(LLM)에게 전화기를 쥐여줄 차례입니다. create_agent에 모델과 도구 목록을 넘기면, "필요하면 이 도구를 알아서 써도 되는" 에이전트가 만들어집니다.

📥 코드
from pprint import pprint

agent = create_agent(
    model=model,
    tools=[get_aladin_bestsellers],)


result = agent.invoke({"messages": [
  {"role": "user", "content": "현재 알라딘에서 가장 인기 있는 베스트셀러 책 5권을 알려줘."},
]})

print("Agent의 응답:", result['messages'][-1].content)

여기서 벌어지는 일을 대화 형태로 보면 이렇습니다.

Human
현재 알라딘에서 가장 인기 있는 베스트셀러 책 5권을 알려줘. ← 사용자 질문
AI
(속으로) 이건 실시간 정보네. get_aladin_bestsellers(count=5)를 호출하자. ← 도구 선택
Tool
[{title: "프로젝트 헤일메리", ...}, ...] ← 도구가 API에서 받아온 목록
AI
받은 목록을 사람이 보기 좋게 정리해서 최종 답변 작성 ← 자연어로 마무리

우리는 get_aladin_bestsellers를 직접 부른 적이 없다는 점에 주목하세요. 사용자 문장만 던졌을 뿐인데, 에이전트가 스스로 판단해서 도구를 호출하고 결과를 받아 정리했습니다. 마지막 줄 result['messages'][-1].content는 대화의 맨 마지막 메시지(=최종 답변)의 본문을 꺼내는 코드입니다.

3. 에러는 "터뜨리지" 말고 "돌려줘라"

아까 도구의 except 블록에서, 에러가 나면 예외를 다시 던지지(raise) 않고 [{"error": "API 호출 실패: ..."}]라는 데이터를 반환했습니다. 이건 에이전트 설계에서 대단히 중요한 선택입니다.

🔍 비유 — 심부름 간 아이가 실패했을 때 아이에게 빵을 사 오라고 심부름을 보냈다고 합시다. 가게 문이 닫혀 있었다면 두 가지 반응이 가능합니다.
(A) 빈손으로 돌아와 "엄마, 가게 문 닫았어요"라고 말해주기 → 그럼 우리는 다른 가게로 보내는 등 다음 계획을 세울 수 있습니다.
(B) 실패에 충격받아 그 자리에서 기절해버리기(raise) → 심부름은 물론이고 집안 전체가 그 아이를 병원에 데려가느라 마비됩니다.
return [{"error": ...}]는 (A), raise는 (B)입니다. 에이전트에게는 (A)가 훨씬 낫습니다.

에이전트는 에러를 어떻게 받아들이나

도구가 에러 데이터를 돌려주면, 에이전트는 이를 "프로그램이 중단된 오류"가 아니라 "도구를 실행했더니 결과로 에러 메시지가 돌아왔다"고 인식합니다. 흐름은 이렇습니다.

1도구 호출

에이전트가 get_aladin_bestsellers 실행

2문제 발생

API 통신 실패 → except 블록 진입

3에러 데이터 반환

[{"error": "..."}]를 결과로 돌려줌

4정상 결과로 수용

에이전트는 이걸 도구의 정상 실행 결과로 받아들임

그 결과 에이전트는 사용자에게 상황을 차분히 설명하는 답변을 만들 수 있습니다. 예를 들면 이렇게요.

▶ 이렇게 나와요 (예상 출력)
죄송합니다. 현재 알라딘 API 서버와의 통신에 문제가 발생하여 베스트셀러 정보를
가져오지 못했습니다. (오류 내용: API 호출 실패: ...)
잠시 후 다시 시도해 주시겠어요?
📘 보충 — 왜 이 방식이 더 좋은가

except 블록에서 단순히 예외를 다시 던지면(raise) 전체 프로그램이 그 자리에서 멈춥니다. 반면 에러 내용을 데이터로 돌려주면 다음과 같은 장점이 생깁니다.

  • 프로그램이 죽지 않고 계속 실행됩니다. (심부름 아이가 기절하지 않음)
  • 에이전트(LLM)가 "지금은 이 API를 쓸 수 없구나"를 인식하고, 사용자에게 상황을 안내하거나 대안을 제시할 수 있습니다.
  • 여러 도구를 가진 에이전트라면, 한 도구가 실패해도 다른 도구로 우회를 시도할 여지가 생깁니다.
한 줄 요약 도구 안에서는 "실패했다는 사실"조차 하나의 결과값으로 만들어 돌려주는 것이 견고한 에이전트를 만드는 핵심 습관입니다.

4. "5권"은 어떻게 count 인자로 전달될까 — Function Calling

마지막 궁금증입니다. 우리는 코드에서 get_aladin_bestsellers(count=5)라고 직접 쓴 적이 없습니다. 그저 "베스트셀러 책 5권을 알려줘"라는 한국어 문장을 넣었을 뿐이죠. 그런데 어떻게 그 "5"가 함수의 count 인자로 쏙 들어갔을까요? 이 마법의 이름이 Function Calling(함수 호출)입니다.

🔍 비유 — 손님 말을 주문서로 옮기는 웨이터 식당에서 손님이 "스테이크 미디엄으로 2인분요"라고 말하면, 웨이터는 이 자연스러운 말을 듣고 주방용 주문서 양식에 메뉴=스테이크, 굽기=미디엄, 수량=2라고 정확한 칸에 옮겨 적습니다. LLM이 바로 이 웨이터입니다. "5권"이라는 말을 듣고 count=5라는 기계가 알아듣는 명령으로 번역해 도구에 전달하죠.

단계별로 보면

1도구 목록 확인

LLM이 쓸 수 있는 도구와 그 인자(count, 기본값 10)를 파악

2의도 분석

"5권"에서 숫자 5를 뽑아내 count에 넣기로 판단

3함수 호출

실제로 get_aladin_bestsellers(count=5) 실행

이때 함수 정의에 적힌 기본값 10은 무시되고, 사용자가 요청한 5가 적용됩니다. 반대로 사용자가 그냥 "베스트셀러 알려줘"라고만 하면, LLM은 count를 따로 지정하지 않고 함수에 설정된 기본값 10이 그대로 쓰입니다.

사용자 발화LLM이 만든 호출실제 count 값
"베스트셀러 5권 알려줘"get_aladin_bestsellers(count=5)5 (발화에서 추출)
"베스트셀러 알려줘"get_aladin_bestsellers()10 (기본값)
"베스트셀러 100권 줘"get_aladin_bestsellers(count=100)50 (min(count, 50)이 잘라줌)

이게 가능한 이유 — 설명서를 잘 써둔 덕분

이 모든 게 가능한 건, 앞에서 강조한 Docstring과 타입 힌트 덕분입니다. LLM은 도구를 호출하기 전에 이 설명서를 읽습니다.

📥 코드 (LLM이 읽는 "설명서" 부분)
def get_aladin_bestsellers(count: int = 10) -> List[Dict[str, Any]]:
    """알라딘 베스트셀러 목록을 가져옵니다. (count: 가져올 책의 권수)"""

LLM은 count: int를 보고 "여기엔 정수를 넣는구나", 설명을 보고 "권수를 뜻하는구나"를 이해합니다. 그래서 사용자의 자연어에서 숫자를 뽑아 올바른 인자로 전달할 수 있는 것이죠. 설명서를 대충 쓰면 LLM도 도구를 잘못 쓴다는 교훈이 여기서 나옵니다.

💡 Function Calling 한 줄 정리 사용자의 자연어를 LLM이 읽고, 도구 설명서를 참고해 "어떤 함수를, 어떤 인자로 부를지"를 스스로 결정하는 것. 이것이 에이전트가 "말귀를 알아듣고 알아서 일하는" 것처럼 보이는 진짜 원리입니다.

📚 한 장 정리

오늘의 핵심 LLM은 똑똑하지만 손발이 없다. @tool로 외부 API를 감싸 도구로 달아주면, 에이전트는 사용자 말에서 필요한 값을 뽑아 스스로 도구를 호출하고 결과를 정리해 답한다.
  • 준비물 — requests(인터넷 우체부)로 API에 요청하고, typing(내용물 라벨)으로 입출력 형태를 표시한다.
  • @tool — 함수 위에 붙이는 스티커. 함수를 에이전트가 쓸 수 있는 도구로 승격시킨다. Docstring·타입 힌트는 AI가 읽는 설명서.
  • create_agent — 모델에 도구 목록을 쥐여준다. 이후엔 우리가 도구를 직접 부르지 않아도 에이전트가 알아서 호출한다.
  • 역할 분담 — 도구는 데이터 수집, LLM은 그 데이터를 사람이 읽기 좋은 글로 표현.
  • 에러 처리 — 예외를 raise해 프로그램을 죽이지 말고, 에러를 데이터로 return해 에이전트가 상황을 안내하게 하라(심부름 아이가 기절하지 않게).
  • Function Calling — "5권" 같은 자연어를 LLM이 count=5라는 함수 인자로 번역해 전달한다(주문서를 쓰는 웨이터).
