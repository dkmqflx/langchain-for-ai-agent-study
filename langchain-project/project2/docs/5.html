5

FastAPI로 서빙

서비스화 층 ⏱ 1~2시간
🎯 목표

지금까지는 터미널에서 ask("질문")을 직접 불렀습니다. 이번엔 그 함수를 인터넷으로 부를 수 있게 만듭니다 — POST /chat에 질문을 보내면 답이 돌아오는 API.

🧠 개념 — 딱 하나만

HTTP는 매번 "처음 온 손님"입니다

STEP 3에서 대화를 이어 가려고 thread_id(대화방 번호)를 만들었죠. 그런데 HTTP 서버는 요청이 올 때마다 그게 누구인지 모릅니다. 두 번째 요청이 와도 첫 번째와 같은 사람인지 알 길이 없어요. 그래서 클라이언트가 대화방 번호를 들고 다니면서 매 요청에 같이 보내야 합니다.

📱 클라이언트질문 + session_id를 보낸다
"u1 방에서 하는 말이에요"
→
🚪 main.py (FastAPI)JSON을 받아 ask()에 그대로 넘긴다
새로 하는 일은 거의 없다
→
🤖 ask() (STEP 4)session_id를 thread_id로 쓴다
→
🗄 체크포인트u1 방의 대화 기록을 꺼내 이어 간다
🎫 비유 — 보관증

옷을 맡기면 보관증을 줍니다. 다음에 와서 보관증을 내밀면 직원은 얼굴을 기억 못 해도 번호로 옷을 찾아 주죠. session_id가 보관증이고, 체크포인트가 옷장입니다. 보관증은 손님이 들고 다니는 것 — 그게 이 STEP의 전부입니다.

🛠 할 일 — main.py 한 파일, 세 조각

Agent 코드는 한 줄도 안 고칩니다. ask()를 HTTP로 감싸기만 해요.

①

준비물

— FastAPI 앱 하나 만들고 ask()를 가져온다
from fastapi import FastAPI
from pydantic import BaseModel

from agent import ask                    # STEP 1~4에서 만든 함수 그대로

app = FastAPI(title="P2 Agent API")      # 이 변수 이름(app)을 실행 명령에서 쓴다
②

주고받을 모양 정하기

— 들어오는 JSON과 나가는 JSON의 칸
class ChatIn(BaseModel):                 # 들어오는 것
    message: str                         # 질문. 없으면 FastAPI가 알아서 422로 거절한다
    session_id: str = "default"          # 보관증. 안 보내면 "default" 방을 쓴다

class ChatOut(BaseModel):                # 나가는 것 — STEP 4의 ask() 결과 + 보관증
    answer: str
    sources: list[str] = []
    confident: bool = False              # 여기 안 적으면 FastAPI가 조용히 잘라 낸다
    used_tools: list[str] = []
    blocked: bool = False
    session_id: str                      # "다음에도 이 번호로 오세요"

pydantic 클래스가 곧 계약서입니다. 칸을 적어 두면 FastAPI가 검사·변환·문서화를 전부 대신해 줍니다. /docs 페이지가 공짜로 생기는 것도 이 덕분이에요.

③

창구 두 개

— 살아 있나 확인용 하나, 진짜 대화용 하나
@app.get("/health")                      # 서버가 떠 있는지만 본다. Agent를 안 태우니 공짜
def health():
    return {"status": "ok"}

@app.post("/chat", response_model=ChatOut)
def chat(body: ChatIn):                  # body = ChatIn 모양으로 검사된 요청
    result = ask(body.message, session_id=body.session_id)   # 보관증을 그대로 넘긴다
    return {**result, "session_id": body.session_id}         # 결과에 보관증을 얹어 돌려준다

{**result, ...}는 "result 딕셔너리를 펼치고 칸 하나 더 얹는다"는 파이썬 문법입니다. session_id를 돌려주는 이유는 클라이언트가 다음 요청에 그대로 실어 보내라는 뜻이에요.

전체 코드 한 번에 보기 — main.py 
# ═══════════════════════════════════════════════════════════════════
# STEP 5 · FastAPI 서빙: ask()를 HTTP(POST /chat)로 노출한다.
# 실행: uv run uvicorn main:app --reload --port 8001   (P1이 8000을 쓰므로 8001)
# 자동 문서: http://localhost:8001/docs
# ═══════════════════════════════════════════════════════════════════
from fastapi import FastAPI
from pydantic import BaseModel

from agent import ask

app = FastAPI(title="P2 Agent API")


class ChatIn(BaseModel):
    message: str
    session_id: str = "default"


class ChatOut(BaseModel):
    answer: str
    sources: list[str] = []
    confident: bool = False
    used_tools: list[str] = []
    blocked: bool = False
    session_id: str


@app.get("/health")
def health():
    return {"status": "ok"}


@app.post("/chat", response_model=ChatOut)
def chat(body: ChatIn):
    result = ask(body.message, session_id=body.session_id)
    return {**result, "session_id": body.session_id}

🎓 한 줄 정리

HTTP는 기억이 없으니 보관증(session_id)을 손님에게 쥐여 주고, 서버는 그 번호로 대화방을 찾는다. API 코드는 그 번호를 thread_id로 넘겨주는 것 말고는 할 일이 없다.

더 알아보기 — 실무에서는 / 스트리밍(선택)

보관증을 손님이 마음대로 적게 두면 안 됩니다

지금은 클라이언트가 보낸 session_id를 그대로 믿습니다. 학습엔 편하지만, 실제 서비스라면 남의 번호를 넣는 순간 남의 대화를 읽을 수 있어요. 실무에서는 로그인 토큰으로 사용자를 확인한 뒤 서버가 번호를 만듭니다(예: f"{user_id}:{conversation_id}"). 이 프로젝트에선 인증까지 만들지 않고, STEP 9 README의 한계 목록에 한 줄 남깁니다.

같은 방에는 한 번에 하나씩

응답이 오기 전에 같은 session_id로 다음 요청을 보내면 안 됩니다. 서버는 앞 요청을 아직 처리 중이고, 뒤 요청은 쓰다 만 대화 기록을 읽게 되어 실패합니다. 운영에서는 방마다 잠금을 두거나 클라이언트가 응답 전엔 다음 요청을 못 보내게 막습니다. 이 프로젝트에선 구현하지 않고 STEP 9 README의 한계 목록에 적습니다.

스트리밍 — "생각 중…"을 보여 주기 (선택)

Agent는 도구를 여러 번 부르느라 10~20초씩 걸립니다. 그동안 화면이 멈춰 있으면 고장 난 줄 알죠. 그래서 끝날 때까지 기다렸다가 한 번에 주는 대신, 진행 상황을 한 줄씩 흘려보내는 두 번째 창구를 만듭니다. 글자를 한 자씩 흘리는 게 아니라 "🔧 문서 검색 중 → 🔧 계산 중 → 답변"처럼 단계를 흘립니다 — Agent에는 이쪽이 어울려요.

_sse()딕셔너리 하나를 브라우저가 알아듣는 한 줄로 포장
→
_event_stream()Agent를 돌리며 사건이 날 때마다 한 줄씩 내보낸다 (핵심)
→
/chat/stream그 흐름을 HTTP 응답으로 감싼다
S-1

포장기

— 규칙은 "data: " + JSON + 빈 줄
import json
from fastapi.responses import StreamingResponse
from agent import agent                      # ask()가 아니라 agent 객체. 중간을 열어 보려면 이게 필요하다

def _sse(payload: dict) -> str:
    return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n"   # \n\n = "이벤트 하나 끝" 신호

줄바꿈이 두 개인 게 규칙입니다. 하나만 쓰면 브라우저가 다음 줄까지 같은 이벤트로 보고 영원히 기다립니다.

S-2

중계 캐스터

— return 대신 yield: 한 접시 나올 때마다 바로 내보낸다
def _event_stream(message: str, session_id: str):
    cfg = {"configurable": {"thread_id": session_id}}
    final_state = None
    for mode, chunk in agent.stream(
        {"messages": [{"role": "user", "content": message}]}, cfg,
        stream_mode=["updates", "values"],   # updates = 이번 단계에 새로 생긴 것 / values = 지금까지 전체
    ):
        if mode == "values":
            final_state = chunk              # 계속 덮어쓰면 마지막 것이 남는다
            continue
        for update in chunk.values():        # 노드 이름은 버리고 알맹이만
            if not isinstance(update, dict):
                continue
            for m in update.get("messages", []):
                if getattr(m, "tool_calls", None):          # AI가 "도구 부를게"
                    for call in m.tool_calls:
                        yield _sse({"type": "tool_start", "tool": call["name"]})
                elif getattr(m, "type", None) == "tool":    # 도구가 결과를 들고 돌아옴
                    yield _sse({"type": "tool_end", "tool": m.name})

    reply = (final_state or {}).get("structured_response")   # 루프가 끝났다 = Agent가 다 했다
    if reply is None:                                        # 가드레일에 막힌 경우
        messages = (final_state or {}).get("messages", [])
        yield _sse({"type": "answer", "answer": messages[-1].content if messages else "",
                    "sources": [], "blocked": True})
    else:
        yield _sse({"type": "answer", "answer": reply.answer,
                    "sources": reply.sources, "blocked": False})
    yield _sse({"type": "done"})             # 이게 없으면 화면의 로딩 표시가 안 멈춘다

yield가 있으면 이 함수는 "주문서"가 됩니다 — 호출해도 바로 실행되지 않고, 누군가 "다음 줄 주세요" 할 때마다 딱 그만큼만 돕니다. 당기는 쪽은 FastAPI고, 나온 줄은 곧장 사용자 화면으로 갑니다.

S-3

송신탑

— 네 줄. async def로 바꾸지 말 것
@app.post("/chat/stream")
def chat_stream(body: ChatIn):
    return StreamingResponse(_event_stream(body.message, body.session_id),
                             media_type="text/event-stream")   # "이건 SSE다"라는 이름표

agent.stream()은 중간중간 멈춰 기다리는 동기 코드라, 평범한 def로 두면 FastAPI가 별도 스레드에서 돌려 줍니다. async def로 바꾸면 그 기다림이 서버 전체를 붙잡아 다른 사용자까지 멈춥니다. 

curl -N -X POST http://localhost:8001/chat/stream -H "Content-Type: application/json" \
  -d '{"message":"카드 연회비 조항 찾아보고 15000원의 5년치를 계산해줘","session_id":"u3"}'
# -N = 버퍼링하지 말고 오는 대로 보여 달라. 한 줄씩 시간차를 두고 나오면 성공:
