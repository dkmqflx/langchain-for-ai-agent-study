03. Memory 기초 — Short-term Memory

실습 노트북: 03.ipynb  ·  원문: docs/02.agent-basic.md 2장 Memory  ·  난이도: 🟢 입문  ·  선행: 02. Tool 심화

이 자료는 실습 노트북(03.ipynb)을 열기 전에 먼저 읽는 강의 교재입니다. 앞 장에서 만든 Agent는 대화가 한 번 끝나면 방금 나눈 이야기를 모조리 잊어버립니다. 이 장에서는 Agent에게 "기억용 수첩"을 하나 쥐여줘서, 이전 대화를 이어갈 수 있게 만드는 Short-term Memory를 배웁니다. 핵심 도구는 딱 두 가지 — InMemorySaver와 thread_id입니다.

🔍 비유 — 매번 처음 보는 사이인 상담사 LLM은 원래 대화가 끝나는 순간 방금 무슨 얘기를 했는지 통째로 잊습니다. 아무리 정겹게 대화해도, 다음에 말을 걸면 당신을 오늘 처음 만난 사람처럼 대하죠. 이 성질을 어려운 말로 "stateless(상태가 없다)"라고 합니다. 그래서 "제가 뭐라고 했죠?"라고 물으면 "저는 이전 대화를 기억할 수 없어요"라는 답이 돌아옵니다. 이 장의 목표는 이 기억상실을 고쳐주는 것입니다.
이 장에서 배우는 것 "기억"이라는 마법 같은 기능이 따로 있는 게 아닙니다. Agent가 대화를 나눌 때마다 그 내용을 어딘가에 저장(Checkpoint)해 두고, 다음 호출 때 같은 대화방 번호(thread_id)로 찾아와서 이전 기록을 다시 읽는 방식입니다. 그 저장소가 InMemorySaver이고, 대화방을 구분하는 번호표가 thread_id입니다.

먼저, 메모리에는 두 종류가 있다

사람의 기억도 "방금 대화 내용을 잠깐 붙들고 있는 단기 기억"과 "이름·취향처럼 오래 담아두는 장기 기억"으로 나뉩니다. LangChain의 메모리도 똑같이 두 갈래로 나뉩니다. 이 장에서 다루는 것은 그중 Short-term(단기) 메모리입니다.

🔍 비유 — 통화 중 메모지 vs. 주소록 전화 통화 중에 상대가 부른 번호를 메모지에 잠깐 적어두는 것이 Short-term memory입니다. 통화(세션)가 이어지는 동안만 유효하죠. 반면 자주 연락하는 사람을 주소록에 영구 저장하는 것이 Long-term memory입니다. 이 장은 메모지(Checkpointer) 이야기이고, 주소록(Store)은 나중 장의 몫입니다.
메모리 종류저장 방식용도
Short-term memoryCheckpointer (InMemorySaver 등)대화 중 문맥 유지
Long-term memoryStore사용자 선호도·과거 정보 영구 저장
💡 실생활 예시 ChatGPT 왼쪽 사이드바에 남는 대화 기록이 Short-term memory의 예시이고, "나에 대해 알아두세요" 설정처럼 세션이 바뀌어도 유지되는 정보가 Long-term memory의 예시입니다.

0. 환경 준비

앞 장들과 똑같이 모델 하나와 Agent 재료를 준비합니다. 이번 장의 주인공은 모델이 아니라, Agent에게 붙여줄 기억 저장소입니다.

📥 코드
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langchain.agents import create_agent

# .env 파일에서 환경 변수 로드
load_dotenv()

# 모델 선언
model = init_chat_model("gpt-4o-mini")

1. InMemorySaver로 Agent에게 기억력 부여

InMemorySaver는 대화 상태(스레드)를 프로그램이 켜져 있는 동안 메모리 안에 저장하는 가장 기본적인 Checkpointer입니다. create_agent를 만들 때 checkpointer=InMemorySaver()를 넘겨주기만 하면, 그 순간부터 Agent는 대화를 기억할 수 있게 됩니다.

🔍 비유 — 수첩과 펜을 손에 쥐여주기 기억을 못 하던 상담사에게 수첩과 펜을 하나 쥐여줬다고 상상해보세요. 이제 그는 손님이 한 말을 그때그때 수첩에 적어두고, 다음에 그 손님이 오면 수첩을 펼쳐 읽습니다. InMemorySaver()가 바로 이 수첩이고, checkpointer=로 넘기는 행위가 상담사(Agent)에게 그 수첩을 쥐여주는 것입니다.
📥 코드
from langgraph.checkpoint.memory import InMemorySaver

# 메모리 종류
# short term memory: Checkpointer를 통해 대화 스레드(세션) 저장
# long term memory: Store를 통해 장기 메모리 저장

# 주의할 점은 invoke할 때 thread_id = 1를 명시적으로 지정해야 한다는 점입니다.

agent = create_agent(
    model=model,
    tools=[],
    checkpointer=InMemorySaver()
)
⚠️ 반드시 함께 넘겨야 하는 짝 — thread_id Checkpointer를 붙였다고 끝이 아닙니다. invoke()를 호출할 때 {"configurable": {"thread_id": "..."}}를 두 번째 인자로 반드시 함께 넘겨야 합니다. thread_id가 없으면 수첩은 있는데 "어느 페이지(어느 손님)의 기록인지"를 구분할 수 없어서 기억이 동작하지 않습니다.

2. thread_id로 대화방을 구분한다

thread_id는 한마디로 대화방 번호입니다. 같은 번호로 계속 말을 걸면 이전 대화가 이어지고(맥락 기억), 다른 번호로 말을 걸면 아무것도 모르는 새 대화가 시작됩니다.

🔍 비유 — 카카오톡 채팅방 thread_id는 메신저의 채팅방과 똑같습니다. "엄마와의 대화방"에 들어가면 어제 나눈 얘기가 그대로 이어져 있고, "친구와의 대화방"으로 옮기면 완전히 다른 맥락이 펼쳐지죠. 번호가 같으면 같은 방, 번호가 다르면 다른 방입니다.

먼저 1번 방에서 나를 소개해봅니다. Agent가 이 말을 수첩(1번 페이지)에 적어둘 것입니다.

📥 코드
result = agent.invoke({"messages": [
  {"role": "user", "content": "안녕하세요, 나는 자유인입니다"}]},
  {"configurable": {"thread_id": 1}})

print(result['messages'][-1].content)
▶ 이렇게 나와요
안녕하세요! 자유인님. 어떻게 도와드릴까요?

이제 같은 1번 방에서 "제가 뭐라고 했죠?"라고 물어봅니다. 수첩(1번 페이지)에 앞 대화가 적혀 있으니, Agent는 그것을 다시 읽고 내가 방금 한 말을 그대로 기억합니다.

Human
안녕하세요, 나는 자유인입니다 ← 1번 방에 저장됨
AI
안녕하세요! 자유인님. 어떻게 도와드릴까요?
Human
제가 뭐라고 했죠? ← 같은 1번 방에서 이어 물음
📥 코드
result = agent.invoke({"messages": [
  {"role": "user", "content": "제가 뭐라고 했죠 ?"}]},
  {"configurable": {"thread_id": 1}}) # thread_id가 다르면, 새로운 대화로 인식합니다.


print(result['messages'][-1].content)
▶ 이렇게 나와요
당신은 "안녕하세요, 나는 자유인입니다"라고 말씀하셨습니다. 자유로운 삶에 대해 이야기하고 싶으신가요? 아니면 다른 주제가 있으신가요?
💡 방금 무슨 일이 일어났나 두 번째 호출에서 우리는 "제가 뭐라고 했죠?" 딱 한 문장만 보냈습니다. 그런데도 Agent가 "자유인입니다"를 기억한 이유는, Checkpointer가 1번 방에 쌓여 있던 이전 메시지들을 자동으로 앞에 붙여서 모델에게 전달했기 때문입니다. 즉, 내가 매번 손으로 대화 기록을 다시 보내지 않아도 수첩이 알아서 채워주는 셈입니다.

3. thread_id를 바꾸면 완전히 새로운 대화

이번엔 방 번호를 2번으로 바꿔봅니다. 2번 방은 아직 아무 기록도 없는 빈 페이지입니다. 그래서 똑같이 "제가 뭐라고 했죠?"라고 물어도, "자유인입니다"라고 했던 1번 방의 기억은 전혀 알지 못합니다.

🔍 비유 — 옆방으로 옮겨가면 1번 상담실에서 나눈 이야기를 들고 2번 상담실로 옮겨가면, 그곳 상담사는 앞방에서 무슨 대화가 오갔는지 알 길이 없습니다. 방(수첩 페이지)이 다르니까요. thread_id를 바꾼다는 건 이렇게 기록이 전혀 다른 새 방으로 들어가는 것과 같습니다.
📥 코드
result = agent.invoke({"messages": [
  {"role": "user", "content": "제가 뭐라고 했죠 ?"}]},
  {"configurable": {"thread_id": 2}}) # thread_id가 다르면, 새로운 대화로 인식합니다.


print(result['messages'][-1].content)
▶ 이렇게 나와요
죄송하지만, 저는 이전 대화 내용을 기억할 수 없습니다. 제가 도와드릴 수 있는 것이 있다면 말씀해 주세요!
⚠️ 헷갈리기 쉬운 지점 "기억을 못 하네? Checkpointer가 고장 났나?"라고 오해하기 쉽습니다. 하지만 이건 정상 동작입니다. Checkpointer는 제대로 작동하고 있고, 단지 2번 방에는 저장된 기록이 없을 뿐입니다. 기억을 이어가고 싶다면 방 번호를 바꾸지 말아야 합니다.

4. 1번 방의 대화 히스토리 전체 조회

다시 1번 방으로 돌아와 봅니다. 그동안 오간 대화가 차곡차곡 누적되어 있어서, response["messages"]를 순회하면 대화 흐름 전체(Human → AI → Human → AI …)를 처음부터 끝까지 꺼내볼 수 있습니다. 각 메시지의 .type은 그 발화가 누구 것인지(human/ai) 알려주고, .content는 실제 내용을 담고 있습니다.

🔍 비유 — 수첩을 처음부터 넘겨 읽기 "지금까지 무슨 얘기 나눴죠?"라고 물으면서, 동시에 우리가 수첩(1번 페이지)을 첫 장부터 끝까지 직접 펼쳐 읽는 장면입니다. 방금 던진 새 질문까지 포함해 그 자리에서 나눈 모든 발화가 순서대로 적혀 있는 걸 눈으로 확인할 수 있습니다.
📥 코드
# 1번 방의 대화 내역을 다시 불러옵니다.
response = agent.invoke(
    {"messages": [{"role": "user", "content": "지금까지 무슨 얘기 나눴죠?"}]},
    {"configurable": {"thread_id": "1"}},
)

# 세션에 누적된 전체 메시지 히스토리를 하나씩 뜯어봅니다.
for i, msg in enumerate(response["messages"], start=1):
    print(f"--- Message {i} ({msg.type}) ---")
    print(msg.content)
    print()

--- Message 2 (ai) ---

--- Message 3 (human) ---

--- Message 4 (ai) ---

--- Message 5 (human) ---

--- Message 6 (ai) ---

📘 보충 — 왜 숫자 1과 문자열 "1"이 같은 방을 가리킬까?

앞에서는 thread_id: 1(숫자)로 저장했는데, 여기서는 thread_id: "1"(문자열)로 조회했습니다. 그런데도 같은 1번 방의 기록이 그대로 이어졌습니다. LangGraph가 thread_id를 내부적으로 문자열로 취급하기 때문에 1과 "1"이 사실상 같은 키로 다뤄지는 것입니다.

다만 실전에서는 처음부터 문자열("1", "user-42" 등)로 통일해 쓰는 것을 권합니다. 표기를 섞으면 나중에 "왜 기억이 안 이어지지?" 하는 혼란의 씨앗이 될 수 있습니다.

💡 메시지가 쌓이는 규칙 매 invoke마다 우리는 새 질문 한 개만 보내지만, 방에는 그 질문뿐 아니라 모델의 답변(AI 메시지)까지 함께 쌓입니다. 그래서 대화를 거듭할수록 히스토리는 Human → AI → Human → AI … 순으로 눈덩이처럼 길어집니다. (대화가 아주 길어지면 오래된 메시지를 요약·정리하는 전략이 필요해지는데, 그건 다음 단계의 이야기입니다.)

📚 한 장 정리

오늘의 핵심 Agent의 기억은 마법이 아니다. Checkpointer(수첩)에 대화를 저장하고, thread_id(방 번호)로 그 기록을 찾아 다시 읽는 것이 곧 Short-term Memory다.
  • LLM은 stateless — 손대지 않으면 대화를 스스로 기억하지 못한다(기억상실 상담사).
  • InMemorySaver = 기억용 수첩 — create_agent(..., checkpointer=InMemorySaver())로 Agent에게 쥐여준다.
  • thread_id = 대화방 번호 — invoke의 두 번째 인자 {"configurable": {"thread_id": ...}}로 꼭 지정한다.
  • 같은 번호 → 기억 이어짐, 다른 번호 → 빈 방에서 새 대화.
  • 히스토리는 자동 누적 — response["messages"]를 순회하면 Human/AI 발화 전체를 .type·.content로 꺼내볼 수 있다.
➡️ 다음 이야기 기억은 갖췄으니, 이번엔 Agent가 도구(tool)를 실제로 호출하는 순간을 눈으로 들여다볼 차례입니다. 다음 노트북에서는 Tool Emulator로 도구 호출 과정을 시뮬레이션해 봅니다.
