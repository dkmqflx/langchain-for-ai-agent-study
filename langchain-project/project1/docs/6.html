6

Langfuse로 관측성 붙이기

서비스화 층(얇음) ⏱ 1~2시간
🎯 목표

모든 질의의 검색·생성·토큰·비용·지연을 Langfuse 대시보드에서 눈으로 본다.

🧠 개념

RAG가 틀린 답을 하면 "검색이 잘못됐나, 생성이 잘못됐나"를 알아야 고칩니다. 관측성(Observability)은 그 판단 근거입니다. Langfuse는 LangChain 콜백 한 줄로 실행을 trace(추적 트리)로 남깁니다. 카카오가 공고에 이름을 명시한 도구예요.

🛠 할 일

코드 변경은 몇 줄뿐입니다. 네 조각으로 나눠 보고, 맨 아래 전체 코드로 answer()를 교체하세요.

🧭 네 조각 한눈에

① Langfuse 키 발급해 .env 채우기  →  ② 콜백 핸들러 하나 만들기  →  ③ 기록하고 싶은 호출에 config 붙이기  →  ④ 검색·생성을 '요청 하나'로 묶기

① 키 발급 — STEP 0에서 비워 둔 칸 채우기

cloud.langfuse.com에서 무료 프로젝트를 만들고 키 2개를 받아 STEP 0에서 빈칸으로 남겨 둔 자리에 채웁니다.

.env
LANGFUSE_PUBLIC_KEY=pk-lf-...                  # 공개 키 (pk-lf- 로 시작)
LANGFUSE_SECRET_KEY=sk-lf-...                  # 비밀 키 (sk-lf- 로 시작) — 절대 깃에 올리지 말 것
LANGFUSE_BASE_URL=https://cloud.langfuse.com   # 로그를 보낼 서버 주소
⚠️ 주소는 '가입한 리전'의 주소를 그대로 쓴다

Langfuse Cloud는 리전이 나뉘어 있습니다 — EU는 https://cloud.langfuse.com, US는 https://us.cloud.langfuse.com, 일본은 https://jp.cloud.langfuse.com. 키를 발급받은 리전과 주소가 다르면 인증이 실패합니다(직접 설치해 쓴다면 그 서버 주소). 변수 이름도 버전을 탑니다: v4는 LANGFUSE_BASE_URL이고, 예전 이름인 LANGFUSE_HOST는 아직 동작하지만 deprecated입니다.

키가 제대로 들어갔는지는 대시보드를 보기 전에 한 줄로 확인할 수 있습니다 — True가 나오면 통과입니다. 

uv run python -c "from dotenv import load_dotenv; load_dotenv(); from langfuse import get_client; print(get_client().auth_check())"

② 콜백 핸들러 만들기

콜백(callback)은 "무슨 일이 생길 때마다 나한테도 알려줘"라고 등록해 두는 참관인입니다. 랭체인이 검색을 시작할 때, LLM이 답을 마칠 때마다 이 참관인이 호출되고, 핸들러는 그 내용을 Langfuse 서버로 보냅니다.

rag.py (맨 위에 추가)
from langfuse.langchain import CallbackHandler   # langfuse v3~v4 경로 (v2라면 langfuse.callback)

# 랭체인 실행 중 일어나는 일(검색 시작·LLM 응답 완료 등)을 넘겨받아 Langfuse 서버로 보내는 '참관인'.
# 키를 인자로 넘기지 않는 점에 주목 — .env에 정해진 이름(LANGFUSE_*)으로 있으면 알아서 찾아 읽는다.
langfuse_handler = CallbackHandler()

CallbackHandler()에 키를 직접 넘기지 않는다는 점을 눈여겨보세요. .env에 정해진 이름으로 넣어 두면 알아서 찾아 읽습니다.

⚠️ import 경로가 langfuse 버전에 민감합니다

설치된 버전을 uv run python -c "import langfuse; print(langfuse.__version__)"로 먼저 확인하세요. v3~v4는 langfuse.langchain, v2는 langfuse.callback입니다.

③ 기록하고 싶은 호출에 config 붙이기

핸들러를 만들어 둔다고 자동으로 기록되지는 않습니다. config를 넘긴 호출만 남아요. 그래서 검색과 생성, 두 군데에 붙입니다.

rag.py (answer 교체)
def answer(question: str, mode: str = "rerank"):
    # 이 config를 넘긴 호출만 Langfuse에 기록된다. 한 번 만들어 두 군데에 재사용한다.
    cfg = {"callbacks": [langfuse_handler]}

    # 검색에 붙인다 → trace에 'retriever' 노드로 남는다 (어떤 청크를 가져왔는지 나중에 확인 가능)
    docs = get_retriever(mode).invoke(question, config=cfg)

    # 여기엔 일부러 안 붙인다 — 빈칸에 값을 끼우는 문자열 조립일 뿐이라 시간도 비용도 안 들고, 기록할 게 없다
    msg = PROMPT.invoke({"question": question, "context": format_context(docs)})

    # 생성에 붙인다 → 'LLM' 노드로 남고 토큰 수·비용·지연까지 함께 기록된다
    resp = llm.invoke(msg, config=cfg)

    ...   # return 부분은 STEP 3과 동일하다 (바뀌는 건 위 세 줄뿐)
🤔 PROMPT.invoke에는 왜 안 붙였을까요?

invoke가 세 번 나오는데 config는 두 개만 붙었습니다. 일부러예요. PROMPT.invoke는 빈칸에 값을 끼우는 문자열 조립일 뿐, 네트워크도 안 타고 시간도 비용도 들지 않습니다. 기록할 게 없는 거죠. 반대로 retriever(벡터DB 조회)와 llm(OpenAI 호출)은 느려질 수도, 돈이 들 수도, 이상한 결과를 낼 수도 있는 지점입니다. 관측은 바깥 세상과 이야기하는 곳에만 붙이면 됩니다.

이렇게 두 군데에 붙이면 검색과 생성이 각각 기록되기 시작합니다. 그런데 여기까지만 하고 대시보드를 열면 기대와 다른 그림이 나옵니다.

④ 검색·생성을 '요청 하나'로 묶기

질문을 한 번 던졌는데 Traces에 줄이 두 개 생깁니다. 

ChatOpenAI                       21.5s  $0.0037
ContextualCompressionRetriever    3.6s  $0

이유는 단순합니다. get_retriever().invoke()와 llm.invoke()는 서로 아무 관계 없는 두 번의 함수 호출이에요. 콜백은 "이 호출이 일어났다"만 알려줄 뿐 호출들 사이의 관계는 알려주지 않습니다. Langfuse 입장에서는 이 검색과 저 생성이 같은 질문에서 나왔다고 볼 근거가 없는 거죠.

그래서 "여기부터 여기까지가 한 요청"이라고 표시해 주는 상자를 하나 씌웁니다. 이 with 블록 안에서 일어난 기록은 전부 이 상자의 자식으로 들어갑니다.

rag.py
from langfuse import get_client   # 콜백과 같은 .env 키를 읽는 클라이언트

langfuse = get_client()

def answer(question: str, mode: str = "rerank"):
    # 검색과 생성을 '요청 하나'로 묶는 바깥 상자
    with langfuse.start_as_current_observation(name="rag-answer", as_type="span"):
        cfg = {"callbacks": [langfuse_handler]}
        docs = get_retriever(mode).invoke(question, config=cfg)
        msg = PROMPT.invoke({"question": question, "context": format_context(docs)})
        resp = llm.invoke(msg, config=cfg)
    return { ... }   # return은 with 밖이어도 된다 (기록은 이미 끝났다)

이제 한 질문이 트레이스 하나로, 문서가 약속한 그 트리 모양으로 그려집니다.

rag-answer                          23.8s  $0.0034
  ├ RETRIEVER  ContextualCompressionRetriever
  └ GENERATION ChatOpenAI    input 2,233 / output 653 토큰
🍽 왜 굳이 묶나 — 영수증 두 장 vs 한 장

식당에서 음료와 음식을 따로 계산하면 영수증이 두 장 나옵니다. 각각 얼마인지는 알 수 있지만 "이 테이블이 총 얼마 썼나"는 두 장을 들고 직접 더해야 알죠. with는 "같은 테이블"이라고 묶어 주는 표시입니다.

위 두 그림에서 비용 칸을 비교해 보세요. 흩어진 쪽은 생성에만 $0.0037이 붙어 있고, 묶은 쪽은 trace 자체에 $0.0034·23.8초가 찍힙니다. 질의 1건당 총비용·총지연은 묶어야만 얻어지는 숫자이고, STEP 8에서 구성별로 "품질은 얼마나 올랐고 비용은 얼마나 더 드나"를 비교할 때 바로 이 숫자가 필요합니다.

여기까지 하면 RAG가 틀린 답을 했을 때 "검색이 엉뚱한 걸 가져왔나, 아니면 문맥은 맞는데 생성이 틀렸나"를 추측이 아니라 기록으로 가를 수 있게 됩니다.

📄 전체 코드 (rag.py에 추가·교체할 부분)
rag.py (수정)
# ═══════════════════════════════════════════════════════════════════
# STEP 6 · 관측성(Langfuse): 모든 질의의 검색·생성·토큰·비용·지연을 대시보드로 추적한다.
# 방법은 간단 — LangChain 호출에 '콜백 핸들러'를 config로 넘기면 실행이 trace(추적 트리)로 남는다.
# 사전 준비: .env의 LANGFUSE_PUBLIC_KEY·SECRET_KEY·BASE_URL을 채워둘 것(STEP 0의 빈칸).
# ═══════════════════════════════════════════════════════════════════
from langfuse.langchain import CallbackHandler   # langfuse v3~v4: 콜백은 langfuse.langchain 에 있음
# (v2를 쓰면: from langfuse.callback import CallbackHandler)
from langfuse import get_client                  # 검색·생성을 요청 하나로 묶을 때 쓰는 클라이언트

# 아래 두 줄은 반드시 load_dotenv() '뒤'에 둔다 — 키를 인자로 안 넘기고 .env에서 알아서 읽기 때문
langfuse_handler = CallbackHandler()             # Langfuse로 로그를 보내는 콜백(키는 .env에서 자동으로 읽음)
langfuse = get_client()                          # 콜백과 같은 연결을 공유하는 클라이언트

def answer(question: str, mode: str = "rerank"):
    # 이 with 안에서 일어난 기록은 모두 이 상자의 자식이 된다 → 대시보드에 trace 1개로 그려진다.
    # 없으면 두 invoke가 남남이라 trace가 2개로 흩어지고, 질의당 총비용·총지연을 볼 수 없다.
    with langfuse.start_as_current_observation(name="rag-answer", as_type="span"):
        cfg = {"callbacks": [langfuse_handler]}   # 이 config를 붙인 호출만 Langfuse에 기록된다
        docs = get_retriever(mode).invoke(question, config=cfg)  # 검색도 config 전달 → 'retriever' 노드로 남음
        msg = PROMPT.invoke({"question": question, "context": format_context(docs)})
        resp = llm.invoke(msg, config=cfg)        # 생성도 config 전달 → 'LLM' 노드 + 토큰·지연 기록
    return {
        "answer": resp.content,
        "citations": [{"source": d.metadata.get("source"), "page": d.metadata.get("page")} for d in docs],
        "contexts": [d.page_content for d in docs],
    }
💡 팁 CallbackHandler import 경로는 langfuse 버전에 민감합니다. 설치된 버전은 uv run python -c "import langfuse; print(langfuse.__version__)"로 확인하고, v3면 langfuse.langchain, v2면 langfuse.callback을 쓰세요.
✅ 검증 게이트 /query를 몇 번 호출한 뒤 Langfuse 대시보드 Traces에서 요청 1건 = 트레이스 1건(rag-answer)으로 보이고, 그 아래 retriever → LLM 트리와 토큰·비용·지연이 찍히면 통과. (줄이 두 개로 흩어져 있다면 ④의 with가 빠진 것)
