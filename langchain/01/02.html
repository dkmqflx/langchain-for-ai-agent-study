02. Memory — 메시지로 대화 맥락 만들기

실습 노트북: 02.ipynb  ·  원문: docs/01.langchain.md 3장 Memory  ·  난이도: 🟢 입문  ·  선행: 01. Model

이 자료는 실습 노트북(02.ipynb)을 열기 전에 먼저 읽는 강의 교재입니다. LLM은 사실 대화를 전혀 기억하지 못합니다. 그런데 ChatGPT는 어떻게 앞 대화를 이어갈까요? 이 장에서는 그 비밀 — "메모리는 사실 메시지 리스트를 다시 보내주는 것" — 을 비유로 풀어봅니다.

🔍 비유 — 기억을 못 하는 상담사 영화 메멘토의 주인공처럼, LLM은 대화가 끝나는 순간 방금 나눈 이야기를 전부 잊습니다. 다음에 말을 걸면 당신을 처음 보는 사람처럼 대합니다. 이걸 어려운 말로 "stateless(상태가 없다)"라고 합니다. 그럼 어떻게 대화를 이어갈까요? 방법은 하나 — 매번 지금까지의 대화 전체를 다시 들려주는 것입니다.
이 장에서 배우는 것 "메모리"라는 특별한 기능이 따로 있는 게 아닙니다. 메시지를 리스트에 차곡차곡 쌓아 매번 함께 보내면, 모델은 그걸 전부 읽고 마치 기억하는 것처럼 답합니다. 그 메시지를 만들고 쌓는 방법을 배웁니다.

먼저, 메시지 3형제 — System · Human · AI

대화는 메시지(message)들의 모음입니다. 그리고 각 메시지에는 역할(role)이 있습니다.

🔍 비유 — 연극 무대 대화를 한 편의 연극이라고 생각해보세요. 감독(System)은 무대 뒤에서 "너는 가치투자자를 연기해"라고 배역과 규칙을 정해줍니다. 관객(Human)은 객석에서 질문을 던지고, 배우(AI)는 감독의 지시를 지키면서 관객에게 대사로 답합니다. 이 세 역할이 번갈아 쌓이면서 하나의 대화(연극)가 됩니다.
메시지 클래스역할 (연극에 비유)딕셔너리의 role
SystemMessage감독의 지시 — 페르소나·규칙을 미리 주입system
HumanMessage관객의 질문 — 사용자의 요청·입력user / human
AIMessage배우의 대사 — 모델의 답변assistant / ai

0. 환경 준비

01장과 똑같이 모델 하나를 준비합니다. 이번 장의 주인공은 모델이 아니라 모델에 건네는 메시지 리스트입니다.

📥 코드
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

# .env 파일에서 환경 변수(OPENAI_API_KEY 등)를 로드
load_dotenv()

# 모델 선언 — 이번 노트북에서는 메시지 리스트를 다양한 방식으로 invoke해 본다.
model = init_chat_model("gpt-4o-mini")

1. SystemMessage + HumanMessage로 대화 구성

가장 기본적인 대화는 감독의 지시(System) + 관객의 질문(Human)을 리스트에 담아 보내는 것입니다. 이렇게 하면 모델은 System에서 정한 페르소나(역할)를 유지한 채로 답합니다.

📥 코드
from langchain.messages import HumanMessage, SystemMessage

# SystemMessage로 페르소나를 지정하고, HumanMessage로 사용자 질문을 전달한다.
messages = [
  SystemMessage(content="You are a value investment investor."),  # 역할 부여: 가치 투자자
  HumanMessage(content="Broadcom price will be increased?")        # 사용자 질문
]

# invoke의 결과는 AIMessage 객체이다.
# response.content 에 답변 텍스트가, response.response_metadata 에 토큰 사용량 등이 담긴다.
response = model.invoke(messages)
print(response)
💡 System은 "말투와 관점"을 바꾼다 같은 질문 "브로드컴 오를까?"라도 System을 가치투자자로 두면 기업 펀더멘털 관점으로, 단타 트레이더로 두면 차트·모멘텀 관점으로 답이 달라집니다. System은 배우에게 주는 배역이니까요.

결과인 AIMessage에서 답변 텍스트는 response.content로, 토큰 사용량 같은 부가 정보는 response.response_metadata로 꺼낼 수 있습니다.

2. 메시지 리스트 = 메모리

여기가 이 장의 핵심입니다. LLM에 진짜 "메모리"는 없습니다. 대신 이전 대화를 메시지 리스트로 함께 보내주면, 모델은 그걸 전부 읽고 마치 기억하는 것처럼 답합니다.

🔍 비유 — 새 직원에게 회의록 통째로 건네기 회의 중간에 새 직원이 투입됐다고 해봅시다. 그는 앞 내용을 하나도 모릅니다(stateless). 하지만 지금까지의 회의록 전체를 손에 쥐여주면, 그는 그걸 쭉 읽고 "아까 파란색을 좋아한다고 하셨죠"라고 마치 처음부터 있었던 것처럼 답할 수 있습니다. LLM에게 매번 보내는 messages 리스트가 바로 이 회의록입니다. 기억하는 게 아니라, 매번 전체를 다시 읽는 거예요.

아래 예시는 4개의 발화를 하나의 리스트에 모두 담아 한 번에 보냅니다.

System
가치투자자 역할을 해줘 ← 감독 지시
Human
브로드컴 가격이 오를까? ← 첫 질문
Human
내가 좋아하는 색은 파란색이야
Human
내가 어떤 색을 좋아한다고 했지?
Human
내가 처음에 한 질문이 뭐였지? ← 앞을 참조해야 답 가능
📥 코드
# 여러 개의 HumanMessage를 누적해 보낸다.
# 모델은 리스트 전체를 "이전 대화"로 보고 마지막 질문에 답한다.
messages = [
  SystemMessage(content="You are a value investment investor."),
  HumanMessage(content="Broadcom price will be increased?"),

  HumanMessage(content="My favorite color is blue."),
  HumanMessage(content="What color did I say is my favorite?"),
  HumanMessage(content="Remind me what my first question was.")
]

# 마지막 질문은 "내가 처음에 한 질문이 뭐였지?" → 모델이 messages[1]을 참조해 답변한다.
response = model.invoke(messages)
print(response)
▶ 이렇게 나와요 (예상 출력)
Your favorite color is blue, and your first question was whether Broadcom's
price will increase.
(모델이 리스트 앞쪽 메시지를 참조해 "파란색" · "브로드컴 질문"을 정확히 회상)
💡 그래서 메모리란… 결국 "메시지를 어떻게 쌓고(누적) 관리할 것인가"의 문제입니다. 대화가 길어질수록 이 리스트는 눈덩이처럼 커지고, 그만큼 매번 더 많은 내용을 다시 보내게 됩니다. (그래서 실전에서는 오래된 메시지를 요약하거나 잘라내는 전략이 필요해집니다.)

3. 딕셔너리 포맷 (OpenAI 스타일)

LangChain의 메시지 클래스(SystemMessage 등) 대신, OpenAI API와 똑같은 딕셔너리 형식으로도 메시지를 전달할 수 있습니다. role과 content 두 칸을 가진 딕셔너리를 쓰는 거죠.

🔍 비유 — 같은 요리, 다른 그릇 똑같은 김치찌개를 도자기 그릇에 담든 양은냄비에 담든, 안의 음식은 같습니다. 메시지 클래스 방식과 딕셔너리 방식도 마찬가지예요 — 담는 그릇만 다를 뿐, LangChain 내부에서 같은 메시지 객체로 변환되어 결과가 같습니다. 덕분에 기존 OpenAI 코드를 LangChain으로 옮길 때 거의 손대지 않고 가져올 수 있습니다.

Role 매핑

LangChain 클래스딕셔너리 role
SystemMessage"system"
HumanMessage"user" 또는 "human"
AIMessage"assistant" 또는 "ai"
📥 코드
# 메시지를 딕셔너리(role + content) 형태로 정의 — OpenAI API와 동일한 포맷
# 위 셀의 SystemMessage / HumanMessage 예시와 동일한 의미를 갖는다.
messages_data = [
  {"role": "system", "content": "You are a value investment investor."},
  {"role": "human",  "content": "Broadcom price will be increased?"},
  {"role": "human",  "content": "My favorite color is blue."},
  {"role": "human",  "content": "What color did I say is my favorite?"},
  {"role": "human",  "content": "Remind me what my first question was."}
]

# 결과는 위 셀과 동일하게 첫 질문(Broadcom 관련)을 회상하는 답변이 나온다.
response = model.invoke(messages_data)
print(response)
💡 어느 표기를 써도 결과는 같다 클래스든 딕셔너리든 LangChain이 내부에서 동일하게 변환하므로 답은 같아야 합니다. 팀 컨벤션·기존 코드에 맞춰 편한 쪽을 고르면 됩니다.

📚 한 장 정리

오늘의 핵심 LLM의 메모리는 마법이 아니다. "지금까지의 대화(메시지 리스트)를 매번 다시 보내는 것"이 곧 메모리다.
  • LLM은 stateless — 대화를 스스로 기억하지 못한다(기억상실 상담사).
  • 메시지 3형제 — 감독(System) · 관객(Human) · 배우(AI).
  • 메모리 = 메시지 리스트 누적 — 이전 대화를 회의록처럼 통째로 함께 보내면 기억하는 것처럼 답한다.
  • 두 가지 표기 — 클래스 방식과 딕셔너리 방식은 같은 요리, 다른 그릇. 서로 호환되고 결과가 같다.
  • 진짜 멀티턴이 되려면 — 모델의 답변(AIMessage)도 다시 리스트에 쌓아 다음 invoke에 함께 보내야 한다.
➡️ 다음 이야기 대화가 길어질수록 이 "메시지 쌓기"를 손으로 관리하기는 번거롭습니다. 다음 노트북부터는 LangGraph로 이 누적 과정을 자동화해 본격적인 Agent를 만들어봅니다.
