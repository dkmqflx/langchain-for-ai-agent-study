LangGraph 스터디 — 전체 목차

강의 자료 15편  ·  실습 노트북: 각 강의 폴더의 *.ipynb  ·  난이도: 🟢 입문 ~ 🟡 중급

LangGraph로 Agent를 직접 조립해 보는 스터디의 강의 자료 모음입니다. State·Node·Edge라는 부품 세 개에서 출발해서, 그 부품을 어떤 모양으로 이어 붙이느냐에 따라 달라지는 아키텍처 패턴까지 순서대로 다룹니다. 위에서부터 차례대로 읽으면 한 줄기로 이어집니다.

📖 읽는 방법

각 문서는 ①개념 → ②비유 → ③기획(그래프·State 설계) → ④코드 구현 → ⑤실행 결과 → ⑥함정 정리 순서로 되어 있습니다. 코드보다 기획 파트를 먼저 이해하는 것이 훨씬 남는 게 많습니다.

문서 하단의 이전 / 다음 버튼으로 계속 이어서 읽을 수 있고, 가운데 목차 버튼을 누르면 언제든 이 페이지로 돌아옵니다.

2강 · LangGraph 기초 — 부품 익히기

LangGraph의 문법 전부가 사실상 이 두 문서에 들어 있습니다. 뒤의 3강은 여기서 배운 것을 어떻게 배치하느냐의 이야기일 뿐입니다.

2-1
LangGraph 기초 — State · Node · Edge로 Agent 만들기02.LangGraph 기초

그래프의 부품 세 개를 익힙니다. State는 모두가 함께 보는 공책, Node는 일하는 사람, Edge는 사람과 사람 사이의 화살표.

2-2
Agent 구축 실전 — 기획부터 LLM·Tool 결합까지02.LangGraph 기초

3강 · LangGraph 응용 — 아키텍처 패턴

같은 부품으로 모양을 다르게 만드는 다섯 가지 패턴입니다. 앞의 세 개가 기초 패턴, 뒤의 두 개가 그것들을 조합한 응용 패턴입니다.

3-1
기초 패턴 — Prompt Chaining · Parallelization1-1.ipynb

일자로 줄 세우기와 부챗살로 펼치기. 그리고 펼친 결과를 한 칸에 모을 때 필요한 리듀서(reducer)까지.

3-2
기초 패턴 — Routing1-2.ipynb

여러 전문가를 만들어 두고 그중 하나에게만 토스합니다. 핵심은 라우터의 답을 미리 약속된 값으로 못 박는 것(with_structured_output).

3-3
응용 패턴 — Evaluator-Optimizer2-1.ipynb

만들고, 채점하고, 불합격이면 피드백을 들려 되돌려 보냅니다. 그래프에 처음으로 "뒤로 가는 화살표"가 등장하는 장.

3-4
응용 패턴 — Orchestrator-Worker2-2.ipynb

지휘자가 일을 몇 조각으로 쪼갤지 실행 중에 정하고 그만큼 워커를 만들어 뿌립니다. 도면 자체를 실행 중에 그리는 구조.

4강 · Memory — 그래프에 기억을 붙이기

3강까지의 그래프는 한 번 돌고 나면 방금 한 일을 잊습니다. 여기서부터는 State를 저장해 두는 법을 배웁니다. 대화 한 판을 기억하는 것에서 시작해서, 과거로 되돌아가고, 대화창을 닫아도 남는 기억까지 갑니다.

4-1
Short-term Memory — Checkpointer와 State History1.ipynb

한 단계 끝날 때마다 State를 사진 찍어 두는 장치가 checkpointer입니다. 같은 thread_id로 부르면 대화가 이어집니다.

4-2
Time Travel & Interrupt — 과거로 돌아가 사건을 바꾸기2.ipynb

쌓아 둔 사진 중 하나를 골라 그 시점부터 다시 돌립니다. 게임의 세이브 파일 불러오기와 같은 이야기.

4-3
Store (Long-term Memory) — 스레드를 넘어 사람을 기억하기3.ipynb

checkpointer가 대화 한 판짜리 기억이라면, Store는 대화창을 닫아도 남는 기억입니다. 기준이 스레드가 아니라 사람.

5강 · Multi Agent — 사람을 끼워 넣고, 그래프를 쪼개기

혼자 다 하는 Agent에서 여럿이 나눠 하는 구조로 넘어갑니다. 먼저 중간에 사람에게 물어보는 법을 익히고, 그다음 노드가 다음 목적지를 직접 정하는 법과 그래프를 통째로 노드에 접어 넣는 법을 배웁니다.

5-1
Dynamic Interrupt — 일하다 말고 사람에게 물어보는 에이전트1.ipynb

interrupt()로 그래프를 멈춰 세우고 사람의 답을 기다렸다가, Command(resume=...)로 멈춘 그 자리에서 다시 출발합니다.

5-2
Validating Human Input — 사람의 답에 검문대 세우기1.ipynb

사람이 엉뚱한 답을 줄 수도 있습니다. 통과 못 하면 같은 자리에서 다시 묻는 되묻기 고리를 답니다.

5-3
Command with Goto — 엣지를 그리지 않고 노드로 순간이동하기2.ipynb

노드가 "공책에 뭘 쓸지"와 "다음에 누구한테 갈지"를 한 번에 돌려줍니다. 화살표를 미리 그려 두지 않아도 되는 방식.

5-4
Subgraph — 그래프를 통째로 노드에 접어 넣기3.ipynb

노드 한 칸을 확대하면 그 안에 또 그래프가 들어 있습니다. 공책을 같이 쓰는 방식과 따로 쓰고 브릿지로 옮기는 방식 둘 다.

5-5
Multi Agent — 감독관이 지휘하거나, 서로에게 넘기거나4.ipynb

배운 문법을 전부 조합한 진짜 멀티 에이전트. 감독관이 지시하는 Supervisor와 동료끼리 넘기는 Handoff 두 조직도를 다 만듭니다.

한눈에 보는 아키텍처 패턴 5종

3강에서 다루는 다섯 패턴을 고르는 기준만 먼저 정리해 둡니다. 막힐 때 이 표로 돌아오세요.

패턴한 줄 요약모양이럴 때 쓴다
Prompt Chaining 차례차례일자 앞 결과가 있어야 뒤를 할 수 있을 때
Parallelization 동시에부챗살 → 깔때기 서로 독립적인 일을 여럿 돌려 모을 때
Routing 골라서갈림길 입력 종류가 다양해 담당을 나눠야 할 때
Evaluator-Optimizer 될 때까지고리 (loop) 속도보다 품질이 우선일 때
Orchestrator-Worker 쪼개서실행 중에 결정 일을 몇 조각으로 나눌지 미리 알 수 없을 때
🔍 비유 — 패턴은 결국 "조직도"입니다

같은 직원들로도 일렬 결재 라인을 만들 수도 있고, 전 부서 회람을 돌릴 수도 있고, 접수 창구가 담당 부서로 넘기게 할 수도 있습니다.

LangGraph에서 배우는 문법은 몇 개 안 됩니다. 진짜 배우는 건 그 몇 개로 조직도를 어떻게 그릴 것인가죠. 3강 문서들이 전부 이 이야기입니다.
