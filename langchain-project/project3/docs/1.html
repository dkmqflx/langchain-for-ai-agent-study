골든셋 v1 — 시험지와 스키마

🟢 뼈대 ⏱ 2~3시간 (케이스 쓰는 시간 포함)
🎯 목표

시험지 두 벌을 만듭니다 — RAG용(rag_v1.json, 정답이 있는 질문 15개)과 Agent용(agent_v1.json, 기대 행동이 있는 질문 15~20개). 그리고 시험지의 모양을 코드로 못 박아, 칸이 빠진 케이스는 읽는 순간 거절되게 합니다.

🧠 개념 — 딱 하나만

시험지는 고정돼야 점수를 비교할 수 있다 — 그래서 버전을 붙인다

P2 STEP 8에서 "같은 코스에서 스톱워치로 재야 비교가 된다"고 했죠. P3에서는 그 코스가 파일이 되고, 파일에 버전이 붙습니다. 지난주 v1으로 잰 0.72와 오늘 v2로 잰 0.80은 비교할 수 없어요 — 시험지가 쉬워진 건지 시스템이 나아진 건지 모르니까요. 케이스를 하나라도 고치면 버전을 올리고, 비교는 같은 버전끼리만 합니다(STEP 6의 compare.py가 이걸 강제합니다).

시험 대상이 둘이니 케이스도 두 종류입니다. RAG 케이스는 정답 문장이 있어야 하고(RAGAS가 "빠진 게 없나"를 잽니다), Agent 케이스는 정답 대신 기대 행동이 있어야 합니다(어떤 도구를 써야 하나, 막혀야 하나).

schemas.py — 케이스 두 종류

— 칸 이름이 곧 "무엇을 기대하는가"
schemas.py
from typing import Literal
from pydantic import BaseModel, TypeAdapter, model_validator


class RagCase(BaseModel):
    """P1(RAG)용 케이스. 정답 문장이 있어야 RAGAS가 '빠진 게 없나'를 잴 수 있다."""
    id: str
    question: str
    ground_truth: str                         # 사람이 쓴 정답. RAGAS의 reference가 된다
    expect_source: str | None = None          # 근거로 나와야 할 문서(파일명 일부). 없으면 근거 적중은 재지 않는다
    tags: list[str] = []                      # "card", "loan" 처럼 묶어 보기 위한 꼬리표


class AgentCase(BaseModel):
    """P2(Agent)용 케이스. 정답 문장 대신 '어떤 행동을 해야 하나'를 적는다."""
    id: str
    question: str
    expect_tool: str | None = None            # 써야 할 도구. None이면 '아무 도구도 쓰지 말아야 한다'
    expect_sources: bool = False              # 근거(sources)를 채워야 하나
    expect_blocked: bool = False              # 가드레일에 막혀야 하나
    rubric: str                               # 답변에 '무엇이 들어 있어야 하는가'. 모범답안이 아니다
    tags: list[str] = []

rubric에 기본값이 없다는 점을 보세요. Agent 케이스에서 이 칸이 빠지면 STEP 5의 채점자가 기준 없이 점수를 매기게 되니, 아예 읽히지 않게 막습니다. 반대로 tags는 없어도 되니 []를 기본값으로 둡니다.

schemas.py — 데이터셋 = 케이스 묶음 + 이름표

— version 칸과 id 중복 검사
class _DatasetBase(BaseModel):
    name: str                                 # 파일 이름과 같게. "rag_v1"
    version: str                              # "v1". 케이스를 고치면 v2로 — 비교할 때 '같은 시험지'였는지 확인용
    description: str = ""

    @model_validator(mode="after")
    def ids_are_unique(self):
        ids = [c.id for c in self.cases]
        dup = {i for i in ids if ids.count(i) > 1}
        if dup:
            raise ValueError(f"id가 겹칩니다: {sorted(dup)}")
        return self


class RagDataset(_DatasetBase):
    target: Literal["rag"]
    cases: list[RagCase]


class AgentDataset(_DatasetBase):
    target: Literal["agent"]
    cases: list[AgentCase]


# target 칸을 보고 둘 중 어느 모양으로 읽을지 pydantic이 고른다
Dataset = RagDataset | AgentDataset


def load_dataset(name: str) -> Dataset:
    """datasets/<name>.json을 읽고 검증한다. 모양이 틀리면 여기서 바로 예외가 난다."""
    raw = json.loads((DATASET_DIR / f"{name}.json").read_text(encoding="utf-8"))
    return TypeAdapter(Dataset).validate_python(raw)

id가 겹치면 STEP 6에서 두 실행의 케이스를 짝지을 수 없고, STEP 7에서 Langfuse의 item과도 짝지을 수 없습니다. id는 이 프로젝트 전체를 관통하는 열쇠라서 여기서 한 번 잠급니다.

import json
from pathlib import Path

rows = json.loads(Path("../project1/eval_data.json").read_text(encoding="utf-8"))
cases = [{"id": f"rag-{i:02d}", "question": r["question"], "ground_truth": r["ground_truth"],
          "expect_source": None, "tags": []}                  # expect_source·tags는 손으로 채운다
         for i, r in enumerate(rows, 1)]
out = {"name": "rag_v1", "version": "v1", "target": "rag",
       "description": "P1 골든셋 15문항 + 기대 문서·tags", "cases": cases}
Path("datasets/rag_v1.json").write_text(json.dumps(out, ensure_ascii=False, indent=2), encoding="utf-8")
print(f"datasets/rag_v1.json ← {len(cases)}개")

종류개수왜 필요한가
사내 문서 질문 (doc-)6~8주력 기능. 답이 문서에 있으니 기준을 정확히 쓸 수 있다
계산 · 날짜 (calc- · date-)3~4어떤 도구를 써야 하는지 명확하다
웹 검색 (web-)2사내 문서와 헷갈리기 쉬운 지점
도구가 필요 없는 질문 (none-)2~3이게 없으면 "다 부르는 Agent"가 만점을 받는다
차단돼야 할 질문 (block-)2~3프롬프트를 고치다 가드레일이 뚫리지 않았는지

🎓 한 줄 정리

시험지는 파일이고, 파일에는 버전이 있고, 모양은 읽는 순간 검사된다. 점수의 신뢰는 시험지의 고정에서 시작한다.

더 알아보기 — 버전을 언제 올리나 / rubric은 어떻게 쓰나 / tags의 쓸모

버전을 올리는 규칙

케이스를 추가·삭제·수정하면 version을 올리고 파일 이름도 rag_v2.json으로 새로 만듭니다. 옛 파일은 지우지 않아요 — 지난 실행(runs/)이 그 시험지를 가리키고 있으니까요. 오타 수정처럼 점수에 영향이 없는 변경도 버전을 올리는 편이 안전합니다. "영향이 없다"는 판단 자체가 틀릴 수 있어서요.

rubric은 정답이 아니라 체크리스트

"분실 신고 시점을 기준으로 책임 범위가 달라진다는 점을 근거와 함께" — 이렇게 들어 있어야 할 것을 적습니다. 모범답안을 통째로 적으면 채점자가 "문장이 다르다"는 이유로 감점하고, 너무 짧게 적으면 아무 답이나 통과합니다. "~를 언급해야 한다", "~라고 하면 감점"의 두 문장 형식이 가장 안정적입니다.

tags로 잘라 보기

전체 평균이 0.02 떨어졌다는 건 정보가 적습니다. tags가 있으면 STEP 6에서 "card 케이스만 떨어졌다"처럼 어디가 나빠졌는지 잘라 볼 수 있어요. 지금은 채우기만 하고, 쓰는 코드는 STEP 6의 더 알아보기에 있습니다.
