1-2. LangGraph란 무엇인가

랭그래프는 공식 문서에서 스스로를 이렇게 소개합니다.

여기서 저수준(low-level)이라는 말이 핵심입니다. 사용자, 즉 개발자가 개입할 수 있는 디테일한 수준이 아주 깊다는 뜻입니다. 그만큼 에이전트를 개발할 때 섬세하게 컨트롤할 수 있다는 의미이기도 합니다. 그래서 이 강의를 듣고 나면, 지난 LangChain에서 구현한 AI 에이전트보다 더 정교하고 복잡한 비즈니스 로직을 완벽하게 소화하는 에이전트를 설계할 수 있게 됩니다.

랭체인 vs 랭그래프 — 블랙박스 vs 투명한 설계도

기존의 랭체인 에이전트가 내부 로직이 꽁꽁 숨겨진 블랙박스 형태였다면, 랭그래프는 에이전트가 어떤 고민을 하고 어떤 순서로 움직일지 개발자가 한 땀 한 땀 가이드할 수 있는 투명한 설계도를 제공합니다. 덕분에 우리는 단순히 "알아서 해줘"라고 맡기는 게 아니라, 복잡한 비즈니스 로직에 맞춰서 에이전트의 행동을 완벽하게 통제하고 예측할 수 있게 됩니다.

그렇다면 여기서 말하는 오케스트레이션 프레임워크란 무엇일까요?

🔍 비유 — 오케스트레이션 프레임워크 = 지휘자

쉽게 말하면, 에이전트라는 개별 연주자들이 제멋대로 연주하지 않도록 지휘봉을 휘두르는 지휘자가 바로 오케스트레이션 프레임워크입니다. 단순히 질문에 답하고 끝내는 일회성 구조가 아닙니다.

랭그래프는 State라는 공유 메모리를 기반으로 지금 단계에서 검색이 필요한지, 코드를 실행해야 할지, 아니면 결과가 부족해 다시 처음으로 돌아가야 할지를 매 순간 판단합니다.

동적 팀 구성과 다이나믹 인터럽트

즉 지휘자 역할을 해주는 메인 에이전트가 지휘봉을 통해 각기 다른 전문성을 가진 에이전트들을 하나로 묶고, 이들이 서로 협력하며 최적의 결과물을 만들어 낼 수 있도록 설계할 수 있는 프레임워크가 바로 랭그래프입니다. 뿐만 아니라 랭그래프를 이용하면 언어 모델의 강력한 추론 능력을 이용해 지휘자 에이전트가 사용자 요청의 성격 혹은 양에 따라 동적으로 에이전트 팀을 꾸리고 업무를 분배한 뒤, 결과를 하나로 취합해 반환하는 아주 다이나믹한 구조로 에이전트 시스템을 구축할 수 있습니다.

💡 정리 — 이번 강의를 통해 배우게 되는 것

여러분은 이번 랭그래프 강의를 통해서 로우 레벨의 에이전트 시스템을 구축하게 됩니다. 그 말인즉 오케스트레이션 기반 멀티 에이전트 시스템을 구축할 수 있고, 지휘자 에이전트의 동적인 결정에 따라 팀이 구성되고 업무가 분배되는 다이나믹 워커, 그리고 과거로 돌아가 이를 되돌리는 타임 트래블 및 포크를 일으키는 방법을 배우게 됩니다.

또한 에이전트가 업무 중에 막히는 부분이 있으면 실행을 멈추고 사람의 승인이나 수정을 입력받아 동적으로 반영하는 다이나믹 인터럽트도 배웁니다. 이를 통해 보다 안전한 에이전트 시스템을 구축할 수 있게 됩니다.

1-3. 이 강의에서 만들 것들 — 아키텍처 예시 미리보기

말로만 들으면 막연하니, 실제로 이 강의를 따라가면 어떤 결과물이 나오는지 예시를 먼저 보고 갑니다.

패턴구조특징
순차 개선 __start__ → generate_joke → improve_joke → polish_joke → __end__ 하나의 결과물을 여러 노드가 순서대로 다듬는 가장 단순한 체인
동적 서브에이전트 호출 User request → Main Agent → (Subagent A/B/C) → Response 메인 에이전트가 상황에 따라 필요한 서브에이전트만 골라 부르는 구조
병렬 실행 후 취합 __start__ → write_joke / write_poem / write_story (동시) → aggregator → __end__ 여러 작업을 동시에 실행하고 결과를 하나로 합침
감독자(Supervisor) 패턴 __start__ → researcher → supervisor → __end__ 감독자 에이전트가 하위 에이전트들에게 작업을 지시하고 취합
라우터(Router) 패턴 __start__ → router_node → billing/general/shipping/technical_expert → __end__ 조건부 엣지로 알맞은 전문가에게 갈림길을 라우팅
핸드오프 네트워크 Receptionist ↔ Tech Support ↔ Billing Team + ToolNode 에이전트끼리 서로 업무를 인계(handoff)하며 협업
⚠️ 지금은 다 이해할 필요 없습니다

위 구조들은 전부 앞으로 2강~5강에 걸쳐 하나씩 직접 만들어볼 것들입니다. 지금은 "아, LangGraph 하나로 이런 것도 만들 수 있구나" 정도로만 눈에 담아두면 충분합니다.

Orchestrator · Worker · Synthesizer 패턴

여러 아키텍처 중에서도 특히 자주 쓰이는 패턴 하나를 짚고 넘어갑니다.

🔍 비유 — 프로젝트 매니저와 팀원

Orchestrator는 프로젝트를 쪼개 팀원들에게 나눠주는 PM입니다. Worker는 각자 맡은 부분을 처리하는 팀원이고요. Synthesizer는 팀원들이 가져온 결과물을 하나의 보고서로 합치는 담당자입니다.

앞서 본 "동적 서브에이전트 호출" 패턴을 조금 더 구체적으로 실행 가능한 형태로 그린 것이 바로 이 Orchestrator-Worker-Synthesizer 패턴이며, 3강에서 직접 만들어 봅니다.

1-4. 컨텐츠 핵심 포인트 & 왜 GPT-5 + Gemini 3인가

항목설명
Multi Agent / Orchestration여러 에이전트를 지휘자가 조율하는 구조
Dynamic Worker상황에 따라 동적으로 꾸려지는 작업자 팀
Time Travel / Fork과거 상태로 되돌아가거나, 그 지점에서 다른 분기를 시도
Dynamic Interrupt실행 중 사람의 승인·수정을 받아 반영하는 안전장치

왜 GPT-5뿐 아니라 Gemini 3인가

이번 강의에서는 가장 최신 모델인 GPT-5뿐만 아니라 Gemini 3를 기반으로도 에이전트를 구축해 봅니다. 그 이유는 LangChain 공식 사이트에서 공개한 State of AI 2024와 2025를 비교했을 때, 구글 Gemini 모델을 사용하는 개발자가 크게 늘었기 때문입니다.

⚠️ 두 차트를 그대로 비교할 때 주의할 점

왼쪽은 단일 선택 비중, 오른쪽은 중복 선택이 가능한 설문이라 질문 방식 자체가 다릅니다. 두 수치를 1:1로 비교하긴 어렵지만, 방향성은 뚜렷합니다 — 1년 사이 Gemini를 쓰는 개발자가 눈에 띄게 늘었다는 것입니다.

그래서 이 강의에서는 Gemini와 GPT 모델을 모두 호출해 보면서 결과를 비교해 보는 시간도 가져볼 겁니다.

1-5. 실습 준비 — Gemini API 키 발급받기

자, 그렇다면 이제 본격적인 강의에 앞서 API 키를 발급받으러 가 보겠습니다. 우리가 발급받을 API 키는 Gemini입니다.

  1. 구글 검색창에 "구글 AI 스튜디오"라고 검색한 뒤 aistudio.google.com으로 이동합니다.
  2. 화면 우측 상단의 Get started 버튼을 클릭하고, 이용 약관에 동의한 뒤 계속을 클릭합니다.
  3. 좌측 메뉴에서 대시보드를 클릭합니다.
  4. 우측 상단의 API 키 만들기 버튼을 클릭합니다.
  5. 프로젝트 선택 탭에 만들어진 프로젝트가 없다면 프로젝트 만들기를 클릭하고, 이름을 Gemini 프로젝트 그대로 두거나 랭그래프 프로젝트 정도로 설정한 뒤 프로젝트 만들기를 클릭합니다.
  6. 만든 프로젝트를 선택한 뒤, 우측 하단의 키 만들기 버튼을 클릭하면 API 키가 생성됩니다.
  7. 생성된 키를 클릭하면 확인할 수 있고, 복사 버튼을 눌러 API 키를 사용하면 됩니다.
🚫 API 키는 비밀번호와 같습니다

발급받은 API 키를 코드에 그대로 적어 노트북을 공유하지 마세요. 실습이 끝난 뒤에는 노트북에서 키 값을 지우거나, Colab의 보안 비밀(Secrets) 기능을 사용하는 것을 권장합니다.

💡 실습 파일 안내

실습은 강의 영상 고정 댓글에 준비된 Colab 파일로 진행합니다. 링크로 들어가 "1강 Gemini" 파일을 연 뒤, 좌측 상단의 파일 → 드라이브에 사본 저장을 클릭해 본인의 개인 드라이브로 사본을 만들어 두면 이후 실습을 자유롭게 수정하며 진행할 수 있습니다.

1-6. 코드 실습 — 첫 Gemini API 호출

사본을 다 만드셨다면 이제 패키지를 설치해 Gemini에게 요청을 보내 보겠습니다. API 키를 발급받았던 구글 AI 스튜디오로 돌아가 대시보드의 Documentation(문서)을 보면 Gemini API 사용법을 확인할 수 있습니다.

패키지 설치

문서의 빠른 시작(Quickstart)을 클릭하면 패키지 설치 명령어를 확인할 수 있습니다. 이 명령어를 복사해 Colab 사본에 입력합니다.

📥 코드
# 패키지 설치
!pip install -q -U google-genai
💡 Colab에서 느낌표(!)가 붙는 이유

Colab 환경에서 터미널 명령을 입력하려면 앞에 느낌표(!)를 붙여야 합니다. 명령을 입력한 뒤 Shift + Enter를 눌러 google-genai 패키지를 설치합니다.

설치가 끝났다면 OS 환경 변수에 API 키를 등록합니다.

📥 코드
#os 환경변수 GEMINI API KEY 등록
import os

os.environ["GEMINI_API_KEY"] = ""

다시 AI 스튜디오의 대시보드로 들어가 API 키를 클릭해 복사한 뒤, 위 코드의 따옴표("") 사이에 붙여넣고 Shift + Enter로 실행합니다.

API 실행 — 첫 요청 보내기

패키지 설치와 API 키 등록까지 마쳤다면 이제 API를 실행해 볼 차례입니다. 다시 Gemini 문서로 돌아가 아래로 내려가면 요청하는 방법을 보여주는 파이썬 코드를 확인할 수 있습니다. 이 코드를 그대로 복사해 Colab에 붙여넣습니다. 모델은 gemini-3-flash-preview로 설정되어 있고, contents에 인공지능 모델에게 하고 싶은 질문을 채워 넣으면 됩니다. 여기서는 "랭체인과 랭그래프의 관계를 설명해줘"라고 요청해 보겠습니다.

📥 코드
# API 실행
from google import genai

client = genai.Client()

response = client.models.generate_content(
    model="gemini-3-flash-preview",
    contents="랭체인과 랭그래프의 관계를 설명해줘"
)

print(response.text)

Shift + Enter로 실행하면 Gemini 3 모델에게 요청이 가고, 그 응답이 response에 담겨 text 속성으로 꺼내 출력됩니다.

▶ 출력 (예시)
랭체인과 랭그래프의 관계는 ... (Gemini가 생성한 설명이 이어집니다)
⚠️ 실행할 때마다 문구가 달라질 수 있습니다

언어 모델의 답변은 매번 조금씩 다르게 생성될 수 있습니다. 위 출력은 실제 답변의 시작 부분만 옮긴 예시이며, 여러분이 실행하면 표현이 다르게 나올 수 있습니다.

다양한 Gemini 모델

Gemini 3 Flash 모델뿐만 아니라 다양한 모델을 호출해 답변을 받아볼 수 있습니다. 어떤 모델이 있는지는 아래 링크를 통해 확인할 수 있습니다.

모델특징
gemini-3-pro-preview촬영 시점 기준 가장 성능이 좋은 최신 모델
gemini-3-flash-preview이 강의의 기본 실습 모델 — 빠르고 비용 부담이 적음
gemini-2.5-flash이전 세대의 경량 모델
gemini-2.5-flash-lite2.5-flash보다 더 가벼운 모델

참고: ai.google.dev/gemini-api/docs/models

만약 현재 시점에서 가장 성능이 좋은 모델을 호출하고 싶다면, model 파라미터만 gemini-3-pro-preview로 바꿔주면 됩니다.

📥 코드
# 가장 성능이 좋은 모델로 바꾸고 싶다면 model 파라미터만 교체
response = client.models.generate_content(
    model="gemini-3-pro-preview",
    contents="랭체인과 랭그래프의 관계를 설명해줘"
)
💡 Pro vs Flash

Pro 계열은 더 똑똑하지만 느리고 비쌉니다. 반면 실습 중에는 짧은 질문을 수십 번 호출하는 경우가 많으므로, 이럴 땐 Flash로도 충분합니다. 앞으로의 실습은 기본적으로 Flash 모델을 기준으로 진행합니다.

📚 한 장 정리

오늘의 핵심 한 문장

LangGraph는 State라는 공유 메모리를 기반으로 에이전트의 사고 흐름을 개발자가 직접 설계할 수 있게 해주는 저수준 오케스트레이션 프레임워크다.

  • LangGraph vs LangChain — 내부가 숨겨진 블랙박스 대신, 개발자가 사고 순서를 직접 통제할 수 있는 투명한 설계도.
  • 오케스트레이션 — 지휘자가 여러 에이전트(연주자)를 조율하는 것. State를 보고 매 순간 검색·실행·재시도 여부를 판단한다.
  • 동적 팀 구성 — 지휘자 에이전트가 요청의 성격·양에 따라 서브에이전트 팀을 동적으로 꾸리고 업무를 분배한 뒤 결과를 취합하는 Orchestrator-Worker-Synthesizer 패턴.
  • 이 강의의 네 축 — Multi Agent/Orchestration, Dynamic Worker, Time Travel/Fork, Dynamic Interrupt. GPT-5와 Gemini 3를 모두 사용해 비교해 본다.
  • 실습 흐름 — Gemini API 키 발급 → google-genai 패키지 설치 → 환경 변수 등록 → client.models.generate_content() 호출.
🔍 마무리하며

단순히 AI에게 질문하고 답을 기다리는 시대는 끝났습니다. 이제는 우리가 에이전트의 사고 과정을 설계하고, 복잡한 비즈니스 로직을 제어하고, 스스로 판단하고 행동하는 지능형 에이전트 팀을 만드는 시대가 되었습니다. 강의의 마지막 페이지를 넘길 때쯤, 여러분은 LangGraph를 활용해 멀티 에이전트 시스템을 구축하는 엔지니어가 되어 있을 겁니다.
